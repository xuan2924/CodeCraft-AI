# 15：倒计时、结束与最终验收

**Type:** implementation
**Status:** needs-info
**Blocked by:** 12 本地草稿与冲突恢复；14 实时日志、停止与断线恢复
**Spec:** [第一阶段规格](../spec.md)

## What to build

完善工程底座的开始计时、主动结束、到期收尾、冻结与最终验收；用户能查看只读结果，但不能误以为 AI 报告已经实现。

## Acceptance criteria

- [ ] 服务器保存开始/截止时间；断线、刷新与重启不重置倒计时，澄清不自动闲置过期。
- [ ] 主动结束先处理草稿和运行任务；到期阻止新作答操作，未保存草稿不自动纳入正式代码。
- [ ] 在途写入、停止、接管与到期按确定顺序收敛，冻结后不能继续写入。
- [ ] 最终版本有效验收可复用，否则运行基础验收；环境持续失败按确认契约收尾，不永久占用活动名额。
- [ ] 结束后代码及结果只读，再练创建新工作区；保留已应用修改，不暗中回滚。
- [ ] 页面明确报告尚未接入，模型准备未接通不伪报正式产品流程完成。
- [ ] 使用可控时钟及执行服务替身，覆盖到期拒绝、在途写入收敛、冻结版本、验收结果复用、环境失败收尾和资源释放责任的核心正常与失败分支。

## Comments

不实现面试对话、挑战、回顾采集或 AI 评价；测试等待和作答时间的界限沿用有效设计。

### 当前验收边界（用户确认）

“最终验收”是产品对冻结代码执行基础验收的功能，必须实现，不是要求开发阶段反复执行全套真实链路。临界竞争用可控时钟、受控回执顺序及持久化状态夹具进行 L1 测试，不实际等待作答期限，不默认强杀进程。真实链路仅按明确安排或具体问题做最小验证，复用已有证据；未执行不自动形成 QA 欠账，不阻塞功能、L1 与整票 code-review 完成后的 Dev Done。本次调整不勾选功能验收项。
