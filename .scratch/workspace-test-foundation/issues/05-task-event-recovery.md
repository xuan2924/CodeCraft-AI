## Comments

### 产品失败路径确认

用户在任务 05 对话中确认：

- 工作区准备失败后允许重试或放弃；放弃释放唯一活动演练名额，残留资源后台清理，清理失败可见。
- 最终验收持续遇到环境故障时采用有限次重试；达到上限后以“已结束，但最终验收结果不可用”收尾，保留冻结代码并释放活动名额。不将环境故障记为代码失败，也不伪报通过。

本次确认不代表正式服务已实现或验证。用户随后同意以最小状态模型检查操作权/写入、任务停止/恢复和事件快照/撤销边界，并以开始实现前提交 `3976a73` 为评审基线。

### 协议与模型

- 协议：[任务、操作权与事件恢复](../../../docs/design/task-event-recovery.md)；已同步接口、工作区、面试与 Web IDE 入口。
- 模型：`backend/prototypes/task-protocol/`；实际运行及真实链路未验证项见 [任务 05 验证记录](../../../docs/validation/task-event-recovery-05.md)。

- 分诊改为 ready-for-agent 只表示本票决策资料已充分；决定票验收以清单/证据为准，正式实现任务仍必须满足各自阻塞项与真实故障验证门槛。

先完成阻塞项再开始正式定稿；可准备资料，但不能猜测身份、文件提交或执行结果契约。

任务 04 已完成文件侧决定与 Linux 故障验证，见 [工作区设计](../../../docs/design/workspace-execution.md#文件一致性与恢复契约任务-04)。Go 持久化版本、冻结与回执；原子发布是唯一文件提交点。任务 05 必须定义 Java 授权检查和该提交点之间可跨重启恢复的排空/栅栏协调：旧写入先提交则接管后生效，接管先完成则旧写入不得再提交。查询 NotFound 不表示迟到 RPC 已被取消；不能仅释放 Java 本地锁便宣布接管成功。页面租约/凭证实现、本任务其他阻塞项与分诊状态不因此自动改变。
