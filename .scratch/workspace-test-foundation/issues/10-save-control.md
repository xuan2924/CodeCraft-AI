# 10：单页面操作权与文件保存

**Type:** implementation
**Status:** needs-info
**Blocked by:** 09 发布首题并创建独立工作区
**Spec:** [第一阶段规格](../spec.md)

## What to build

用户打开文本文件、编辑并显式保存，服务端维护工作区版本；多页面只能由一个操作页面写入，另一个页面可显式接管。

## Acceptance criteria

- [x] 保存真实写入 Go 工作区并返回持久化修订版本；相同内容不推进版本。
- [ ] 基线过期不写入，显示明确冲突；无权限路径、未开始或已只读状态不能保存。
- [x] 使用已验证原子写入/回执机制，响应丢失后核对结果，不盲重放。
- [x] 操作凭证只在页面内存持有；第二页面只读，接管使旧凭证失效，刷新不静默抢占。
- [ ] 接管与在途写入按协议排序；服务端拒绝旧页面写入，不仅前端禁用按钮。
- [x] 区分未保存、保存中、已保存和失败；保存期间新输入保留，未完成草稿功能不伪报已备份。
- [ ] 浏览器覆盖双页面、编辑保存和冲突；REST/gRPC 覆盖跨用户写入、并发及重启版本恢复。

### Java 协调切片

- 控制权转换、待派发写入与独立撤销 fence ticket 落库；数据库事务不跨 RPC。控制权转换与写入准入在同一控制行排序，身份准入沿用用户锁。
- 每个写入最多自动派发一次。派发前崩溃与响应丢失统一走查询；无回执时先关闭覆盖原代次的栅栏，再判定未提交，不重新发送。
- 撤销捕获固定 fence ticket（不是后续重新扫描用户）：已有转换先完成，再关闭、对账；重复旧 ticket 不关闭新登录后重新打开的栅栏。身份撤销完成前不返回成功。
- 一次性操作凭证只保存摘要；200 才能交付凭证，202/丢失响应后显式接管，不从数据库恢复秘密。
- 验证入口：真实 REST/PostgreSQL/Go 的保存、无变化、冲突、双控制凭证、撤销；故障替身测试用于确定性丢回执/迟到调用，不能替代真实链路。
