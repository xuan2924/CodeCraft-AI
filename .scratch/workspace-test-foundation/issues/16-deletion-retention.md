# 16：删除演练与保留清理

**Type:** implementation
**Status:** needs-info
**Blocked by:** 11 文件创建、删除与原子重命名；15 倒计时、结束与最终验收

## What to build

用户删除已结束演练后立即失去访问入口，后台清理持久化工作区和相关记录；清理过程可见、可重试，并完成第一阶段整体验收。

## 开工门槛

数据/日志/证据保留期限、限额和清理策略须先取得用户确认并更新执行设计。此项尚未定，不可自行填写天数；实现依赖完成不自动解除本门槛。

## Acceptance criteria

- [ ] 明确保留与清理配置及证据引用关系；保留的结果不能引用已静默删除的必要证据。
- [ ] 只能删除已结束且归属自己的演练；确认删除后先禁止文件/任务/日志访问及事件订阅。
- [ ] 后台清理代码、结果、日志和记录，显示正在删除/失败/完成，失败可重试且重复请求幂等。
- [ ] 清理与残留执行、未知回执及服务重启协调，无删除后复活的写入或孤儿资源。
- [ ] 浏览器处理被删除工作区的草稿和文件状态，不恢复成可继续写入的演练；具体提示按已确认行为落实。
- [ ] 汇总执行规格的 16 项验收，包含真实浏览器—Java—Go—Docker 链路；缺陷定位回所属任务修复。
- [ ] 分别报告自动化、真实集成及未验证项；真实链路未通过不宣称第一阶段交付。

## Comments

任务 11 的依赖用于整阶段组合验收，不表示删除工作区技术上依赖重命名。每个前置实现任务仍须自行交付测试，不能把首次联调推迟到本任务。
