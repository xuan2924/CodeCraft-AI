# 04：确定文件一致性与版本恢复方案

**Type:** decision
**Status:** ready-for-agent
**Blocked by:** None
**Spec:** [第一阶段规格](../spec.md)

## What to build

确定 Go 持久化工作区的修订版本、整批写入、回执和崩溃对账方案，提供保存、重命名、测试副本与冻结可以依赖的公开边界。无需等待题目最终格式，验证使用受控文本夹具。

## Acceptance criteria

- [x] 定义读版本、基线检查、整批变更、结果查询、稳定副本与冻结的职责和契约。
- [x] 用户保存和批次变更共同推进版本；无变化保存不推进，一批多文件仅推进一次。
- [x] 明确持久化版本/回执所有者及 Java-Go 对账，不使用纯内存计数。
- [x] 对多文件中途失败、进程崩溃、响应丢失和重复请求进行可执行故障验证，无部分应用或盲重放。
- [x] 验证复制与写入协调，不产生混合版本；冻结后不允许新写入。
- [x] 给任务 05 明确操作权检查与写入提交的协调边界，不提前锁定页面租约实现。
- [x] 将选定方案与证据写入工作区设计，未证明的恢复保证明确保留，不宣称 exactly-once。

## Comments

这是从原一致性及恢复任务中拆出的文件侧任务。任务、页面控制权和事件协议属于任务 05。

用户已确认“不可变版本目录 + 原子发布提交记录”的候选方案及独立 Go 故障验证边界。决定票验收在受控 Linux 文本夹具范围内完成，非正式服务交付。

- 选定契约：[工作区设计](../../../docs/design/workspace-execution.md#文件一致性与恢复契约任务-04)。
- 证据与未验证项：[任务 04 验证记录](../../../docs/validation/workspace-consistency-04.md)。
- 可执行探针：`backend/prototypes/workspace-consistency/`，无第三方依赖；全套通过，现有 Node/Docker 回归 8/8 通过。
- 任务 05 必须协调 Java 授权与 Go 提交：查询无回执不表示旧 RPC 已终止；接管成功前须排空/隔离旧提交，不提前选择租约。
- 正式 gRPC/Java 对账、部署持久卷、Windows/junction、断电、配额/回执保留及 race 未验证；这些不能因决定票完成被当作已上线保证。
