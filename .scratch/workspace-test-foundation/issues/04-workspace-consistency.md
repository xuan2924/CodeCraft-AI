# 04：确定文件一致性与版本恢复方案

**Type:** decision
**Status:** ready-for-agent
**Blocked by:** None
**Spec:** [第一阶段规格](../spec.md)

## What to build

确定 Go 持久化工作区的修订版本、整批写入、回执和崩溃对账方案，提供保存、重命名、测试副本与冻结可以依赖的公开边界。无需等待题目最终格式，验证使用受控文本夹具。

## Acceptance criteria

- [ ] 定义读版本、基线检查、整批变更、结果查询、稳定副本与冻结的职责和契约。
- [ ] 用户保存和批次变更共同推进版本；无变化保存不推进，一批多文件仅推进一次。
- [ ] 明确持久化版本/回执所有者及 Java-Go 对账，不使用纯内存计数。
- [ ] 对多文件中途失败、进程崩溃、响应丢失和重复请求进行可执行故障验证，无部分应用或盲重放。
- [ ] 验证复制与写入协调，不产生混合版本；冻结后不允许新写入。
- [ ] 给任务 05 明确操作权检查与写入提交的协调边界，不提前锁定页面租约实现。
- [ ] 将选定方案与证据写入工作区设计，未证明的恢复保证明确保留，不宣称 exactly-once。

## Comments

这是从原一致性及恢复任务中拆出的文件侧任务。任务、页面控制权和事件协议属于任务 05。
