# 第一阶段：账号、工作区编辑与隔离测试闭环

**Status:** ready-for-agent

这里的 ready-for-agent 表示规格已完成范围与测试边界确认，可用于拆解任务；不表示所有实现决策已经解决。下文的实现门槛必须由相关任务先完成，受阻任务不得直接标为可实现。

## Problem Statement

受邀用户需要在浏览器中打开平台提供的 Java/Maven 工程，可靠地保存修改、运行隔离测试并查看结果。当前仓库只有规范、专题设计和一次性 PoC，没有正式 Java/Go 服务、前端工程或可交付的编辑测试闭环。

平台首先需要证明：身份隔离、文件一致性、执行安全和日志恢复在真实服务链路中成立。模型回复、审批 UI 或模拟测试日志不能替代这些能力。

## Solution

交付一条内部可验证的工程底座：

管理员创建账号 → 用户登录 → 选择已发布题目 → 创建独立工作区 → 编辑并显式保存 → 在稳定代码副本上运行隔离测试 → 查看日志与结构化结果。

保留演练归属、版本、单页面操作权、结束与资源清理等必要边界，以便后续接入 Copilot 和完整面试流程。本阶段不宣称完整演练产品已上线，不展示假的 AI 回复、模型连接成功或评测报告。

### 阶段边界

- 本阶段实现手动编辑与测试所需的题目、工作区、身份、任务和最小生命周期。
- 正式产品的模型检查、AI 澄清、挑战及评测尚未接入；完整演练入口不得因此被标记为通过全部准备条件。
- 内部联调使用明确标识的工程底座入口；它不是新产品模式，也不改变完整产品的“准备完成后才能开始实施”规则。
- 底座需要开始、截止、收尾及只读状态，以验证编辑权限和资源回收；不以实现这些状态冒充完整面试 FSM。
- 如具体实现需要偏离有效设计，必须先确认并更新对应设计；规格不能静默豁免安全、版本或权限约束。

## User Stories

### 账号与授权

1. 作为管理员，我希望通过后台创建受邀用户账号，以便控制试用范围，而不是开放自助注册。
2. 作为管理员，我希望重置账号密码并使旧登录失效，以便处理凭证失效；具体临时密码交付及改密流程须先确定。
3. 作为用户，我希望登录后只访问自己的工作区、任务和日志，以便我的内容不被其他用户获取。
4. 作为用户，我希望登录过期或被撤销时看到明确提示，以便重新登录，而不误认为保存或测试成功。
5. 作为管理员，我希望仅查看管理与运维必要信息，以便维护系统而不获得用户代码、对话或凭证明文浏览入口。

### 题目与工作区

6. 作为题目维护者，我希望通过版本化题目包及验证流程发布 Java/Maven 题目，以便用户拿到可复现的初始工程。
7. 作为用户，我希望选择一个已发布题目版本创建独立工作区，以便后续题目更新不会改变本次尝试。
8. 作为用户，我希望最多拥有一场未结束演练，并能返回当前工作区，以免重复点击创建多个活动工作区。
9. 作为用户，我希望准备失败时看到明确原因和可用的重试入口，以免陷入一个永远无法使用的活动演练。
10. 作为用户，我希望看到题目要求、可编辑范围及当前工作区状态，以便知道可以修改什么。
11. 作为用户，我希望创建、修改、删除和重命名允许范围内的文本文件，以便完成真实工程修改。
12. 作为用户，我希望不能误改平台权威测试和执行配置，以便测试结果具有可信含义。

### 保存、草稿与多页面

13. 作为用户，我希望显式保存后收到服务端确认及新工作区版本，以便区分正式代码与编辑器草稿。
14. 作为用户，我希望相同内容保存不产生新的修订版本，以免无效修改导致冲突。
15. 作为用户，我希望浏览器备份本地草稿，并在返回时提供恢复，以便尽量保留未提交的编辑。
16. 作为用户，我希望恢复草稿只改变编辑器内容，以便我决定何时提交到服务端。
17. 作为用户，我希望版本冲突时比较本地和服务端内容，并按需查看基线，以便整理修改而不是静默覆盖。
18. 作为用户，我希望保存期间继续输入的内容不被成功回调清掉，以便不会丢失后续编辑。
19. 作为用户，我希望多个页面中只有一个具有操作权，并可以显式接管，以免多个页面同时写入。
20. 作为用户，我希望接管不停止后台测试、不清除旧页面草稿，以便控制权切换不造成额外损失。
21. 作为用户，我希望退出登录前处理未保存草稿，登录过期时仍保留本地草稿，以便避免无提示丢失。

### 测试与结果

22. 作为用户，我希望运行服务端允许的测试目标，而不是提供任意命令，以便在安全边界内验证代码。
23. 作为用户，我希望启动测试时明确使用已保存版本，有草稿时先选择保存或返回，以免误测旧代码。
24. 作为用户，我希望测试使用稳定副本，期间仍可保存新代码，以便继续工作而不改变正在执行的测试输入。
25. 作为用户，我希望每份测试结果标明版本，以便区分旧版本通过与当前版本尚未验证。
26. 作为用户，我希望看到持续输出的 stdout/stderr 及截断提示，以便诊断失败，同时不会让日志无限占用资源。
27. 作为用户，我希望区分通过、测试失败、执行超时、已停止及环境错误，以免把平台故障误判为代码问题。
28. 作为用户，我希望同一演练最多一个测试任务，重复点击不重复启动或隐式排队，以便避免额外资源消耗。
29. 作为用户，我希望能够停止测试并看到确定的最终状态，以便终止长时间执行，而不把关闭页面当停止。
30. 作为用户，我希望断线重连后重新查询状态和已保留日志，以便恢复观察而不重新运行测试。

### 收尾与运行保障

31. 作为用户，我希望开始后倒计时以服务端为准，离开页面也不停表，以便有一致的作答期限。
32. 作为用户，我希望主动结束或到期后工作区只读，最终状态关联冻结版本，以便后续报告有稳定输入。
33. 作为用户，我希望在尚未接入评测时明确看到报告不可用，而不是伪造反馈或成功状态。
34. 作为用户，我希望删除已结束演练后立即失去访问入口，并看到后台清理状态，以便了解删除是否完成。
35. 作为运维者，我希望每次测试结束、超时、停止或服务重启后都能回收容器和临时资源，以便磁盘和运行容量不会持续泄漏。
36. 作为运维者，我希望资源、路径和网络限制可验证，清理失败可观测，以便在同机可信试用的边界内运行系统。

## Implementation Decisions

### 已确认的技术与职责

- Java 21、Spring Boot 3、Maven、LangChain4j；PostgreSQL、MyBatis、Flyway。第一阶段不因已选模型 SDK 而提前实现模型功能。
- Go + Docker SDK 管理工作区与执行；Java-Go 使用 Protobuf/gRPC；浏览器通过 Java REST/SSE 访问。
- Vue 3、TypeScript、Vite、Naive UI、Tailwind CSS、Router、Pinia、Vue Query、Monaco 和只读 xterm。
- Java 是身份、题目、演练、任务业务状态与授权所有者；Go 不访问业务数据库。
- 首期允许同机、仅可信受邀用户；Docker 不是完整恶意代码隔离。不得为了跑通闭环放宽禁网、凭证隔离和资源限制。

### 身份与控制权

- 服务端数据库会话 + HttpOnly Cookie，不采用 JWT；写操作具备 CSRF 防护，密码安全哈希存储。
- 密码重置撤销旧会话；SSE 连接需要撤销处理及存续期复核，不只在建立时检查身份。
- 演练资源归属独立校验；页面操作凭证不能代替用户身份。
- 页面内存持有操作凭证；接管使旧凭证失效。刷新重新申请，不能静默抢占。与在途写入的先后顺序由服务端保证。

### 文件与数据一致性

- Go 持久化目录保存工作区；浏览器草稿与正式代码分离。
- 成功改变正式文件内容/结构才推进整个工作区版本；批次只推进一次。
- 保存、重命名等操作校验基线；不因文件不同就绕过工作区级冲突检查。
- 初期虽不接入 AI Patch，也必须保证多文件重命名等批次的原子性和未知结果可核对，不能把问题留到 AI 接入时再补。
- 文件工具只允许题目声明路径，禁止跨演练及路径越界；任务 03 已确认全面禁止符号链接（含内部链接及 junction）、硬链接和特殊文件。任务 04 已完成 Linux 受控夹具的链接拒绝与目录交换验证；正式服务、Windows/junction 与部署宿主仍须复验。
- IndexedDB 草稿恢复、双栏冲突比较、退出处理遵循专题设计，不把本地备份状态显示成服务端保存成功。

### 执行、流与恢复

- 从确定工作区版本复制稳定测试输入，专用受限容器执行，结束保存结果后删除临时资源。
- 一场演练同时最多一个测试任务。任务启动与事件订阅分开，重复请求、重连不重新执行。
- 平台执行入口和权威验收测试受保护；命令由服务端模板生成，依赖预装、运行时禁网。
- 日志有界、截断可见，结果版本明确；不要求逐事件或逐 Token 完整重放。
- 浏览器离开后测试继续；服务重启先核对执行状态，无法确认时标中断。未知文件写入先对账，不盲目重放。
- 超时/停止由 Go 落实进程终止和回收，RPC 取消不等于执行已停止。

### 最小生命周期

- 一个用户最多一场未结束演练；固定题目版本，重新练习从初始工程新建，不覆盖历史。
- 内部底座验证准备、开始、连续计时、收尾、只读和删除。完整产品的 AI 准备检查及面试对话仍未接通，不伪造完成。
- 主动结束处理草稿及运行任务；到期禁止新的作答操作，收敛在途写入后冻结，未保存草稿不自动纳入最终版本。
- 最终版本有有效验收结果则复用，否则执行已进入阶段的验收；本阶段只有基础阶段，不运行挑战或生成 AI 报告。
- 不设置澄清闲置自动过期；已结束演练默认保留 30 天，到期整场删除，也可提前手动删除，不追溯缩短已有承诺。结束保留最终代码及必要记录、清理临时资源；删除先撤销访问，再后台清理。

### 保留、容量与删除（任务 16 已确认）

参数集中配置，完整边界以 [工作区与执行](../../docs/design/workspace-execution.md#保留与删除) 为准：

- 每用户最多保留 20 场未删除的已结束演练，满额后先清理再新建；最多一场未结束演练的约束不变，不自动提前删除未到期历史。
- 当前工作区最多 200 个文本文件、单文件 1 MiB、总内容 10 MiB；题目初始工程也须符合，超限整批拒绝。
- 单场实际存储预算 512 MiB，计入历史、临时资源、测试证据、日志及相关持久化记录，提前预留收尾空间。不新增固定全局总预算或磁盘水位策略；磁盘不足仍须安全失败，不能损坏已提交内容或伪报成功。
- 只保留当前/最终代码及测试、冲突、在途操作和恢复所需版本，不提供任意保存历史浏览/恢复。普通测试保留最近 20 次已完成完整记录；最终验收各次尝试单独保留，运行中/未知/恢复引用记录不淘汰。只回收无引用版本，历史淘汰明确提示；首题单次日志仍为 1 MiB 尾部保留。
- 删除受理撤销访问后释放历史数量名额，残留资源继续计量。清理失败按 1/5/30 分钟、之后每小时重试，手动重试不得并行重复执行；持续失败超过 24 小时提示人工处理但可继续重试。未知写入和残留执行先隔离对账，不强删必要证据。
- 权威确认删除后清理当前浏览器对应草稿与编辑器状态；其他设备下次联网确认后处理，自动到期同样适用。网络/登录错误及含义不明的 404 不触发误清，不承诺擦除离线设备。
- 最小删除进度完成后保留 7 天，未完成不隐藏；安全墓碑按旧请求不可再生效的条件回收，不保留正文/凭证。完整业务回执至少保留完成后 7 天、未决操作不按时间清除的规则仍有效。
- 第一阶段不建设备份、恢复脚本或恢复验收；接受本机数据损坏可能不可恢复，不豁免正常持久化、重启对账或防重放。

### 实现门槛：相关任务必须先解决

| 门槛 | 需要得到的可检验结果 | 阻塞范围 |
|---|---|---|
| 工程初始化 | 兼容依赖版本、唯一前端包管理器、生成/测试/构建命令和本地启动方式确认并可运行 | 所有正式服务实现 |
| 身份契约 | 管理员首次建立方式、密码交付/重置细则、Cookie/CSRF 和会话期限确定 | 账号与鉴权闭环 |
| 题目与镜像 | 任务 03 已确定最小格式、固定身份、编辑范围，真实 Docker 本机验证通过；正式发布记录与目标部署宿主复验仍必需 | 工作区准备与真实测试 |
| 写入一致性 | 任务 04 已选定不可变树与原子提交记录，Linux 进程故障测试通过；正式服务与任务 05 授权协调、目标部署持久卷仍须验证 | 保存、重命名、测试副本及冻结 |
| 控制权与任务协议 | REST/gRPC/SSE 契约、幂等作用域、接管及终态排序确定 | 多页面、任务执行、恢复 |
| 生命周期失败路径 | 准备失败如何释放或恢复唯一活动名额；最终验收环境持续失败如何收尾 | 创建、结束和重新练习 |
| 链接与容量 | 链接禁用政策及任务 16 保留/单场限额已确认、首题执行限额已有实测建议；运行时链接防护、跨存储计量、收尾空间预留、引用回收及磁盘不足行为仍待验收；不新增固定全局磁盘预算/水位或备份恢复 | 文件安全、执行和清理验收 |

这些事项不因本规格被标记 ready-for-agent 而自动获批。涉及用户选择时先确认；技术可行性用小规模验证或故障测试证明，不要求用户猜第三方 API。

## Testing Decisions

用户已确认以下三层测试边界。优先通过公开行为验证，不锁定私有方法、内部类或数据库表布局。

### 1. 浏览器端到端

以真实 Java、Go、PostgreSQL 和 Docker 验证：管理员创建账号 → 用户登录 → 选题准备 → 编辑保存 → 执行测试 → 日志及结果。

同时覆盖保存失败/冲突、未保存提示、旧版本结果、接管、断线恢复、结束只读及删除状态。测试环境的时钟或故障控制可以显式注入，不能伪造正常业务成功。

### 2. Java REST/SSE 边界

验证身份/资源归属、CSRF、密码重置与旧连接、页面接管及旧凭证拒绝、重复创建/启动、状态查询、重连不重执行、停止与完成竞争、到期与写入竞争。

Go 故障可使用明确标记的替身，以确定性触发超时、断线、未知回执与恢复；替身验证不代替跨语言真实联调。

### 3. Go gRPC + Docker 边界

验证路径和链接越界、保护文件、工作区修订、无变化保存、整批失败、崩溃恢复、稳定副本、并发保存与测试、容器禁网/权限/资源上限、超时停止、日志截断和残留清扫。

路径、一致性等可用临时文件系统夹具；涉及容器隔离、杀进程与资源回收的能力必须运行真实 Docker 测试。

### 测试先例与完成证据

当前一次性 PoC 主要提供 Agent 审批/恢复证据，没有正式身份、工作区或沙箱测试套件可直接继承。不能把 PoC 的固定游标、文件回执或依赖当生产规范。

完成报告必须分别列出单元/边界测试、真实集成测试和浏览器端到端结果。环境不可用时列为未验证；若真实链路未跑通，不得宣称本阶段闭环交付完成。

## Acceptance Criteria

- [ ] 正式工程可按实际提供的命令初始化数据库、生成跨语言契约并启动前后端和执行服务。
- [ ] 管理员可创建账号；用户可登录；跨用户访问文件、任务、日志均被拒绝。
- [ ] 重置密码使旧登录失效，已连接事件流按授权契约处理。
- [ ] 至少一个固定版本 Java/Maven 题目经过发布验证，参考解通过基础验收，禁网环境依赖完整。
- [ ] 重复创建不产生多场活动演练，准备失败有确定的恢复/退出路径。
- [ ] 用户能执行允许的文本文件操作；正式版本、原子性和权限规则在故障测试中成立。
- [ ] 草稿与服务端保存状态区分；冲突、保存中继续输入、登录过期及恢复不静默丢内容。
- [ ] 第二页面只读；显式接管后旧凭证不能写入，后台测试不因此停止。
- [ ] 测试读取固定副本；运行中保存不影响输入，结果关联启动版本。
- [ ] 重复启动、断线和重连不重复运行测试；已保留日志与最终状态可查询。
- [ ] 测试失败、超时、停止和环境错误语义明确；截断可见，未知结果不伪报通过。
- [ ] 容器权限、禁网、资源限制、进程终止及临时资源回收通过真实环境验证。
- [ ] 主动结束/到期后工作区只读，最终验收对应冻结代码；未接入报告明确不可用。
- [ ] 验证任务 16 的 30 天保留、20 场历史数量、工作区内容与 512 MiB 单场限额、收尾预留和磁盘不足；普通测试最近 20 次完整记录与最终验收独立保留，必要证据不提前静默删除。
- [ ] 手动/到期删除先关闭访问再清理，失败按约定重试并提示人工处理；验证删除后草稿、7 天最小进度及安全墓碑回收，不因删除或 GC 放行旧请求。
- [ ] 至少一次真实浏览器—Java—Go—Docker 正常链路通过，关键错误路径有自动化证据。
- [ ] 不出现模拟 AI 成功、假模型检查或将内部底座入口宣称为完整演练产品的情况。

## Out of Scope

- 真实 Copilot 模型循环、AI Patch 审批、steer、压缩、用量/费用展示与 Skill 执行。
- 用户模型连接配置与三种协议适配；本阶段不把缺失检查当已通过，正式产品门槛仍保留。
- 面试官对话、可选挑战、用户回顾采集、AI 评测和授权反馈工作流。
- 平台 Agent 配置后台；账号管理后台属于本阶段。
- 可视化出题、任意仓库/二进制上传、任意 shell、交互式终端及多语言执行。
- 组织/企业权限、多人协作编辑、自助注册、第三方登录、历史代码分叉和成绩排行。
- Redis、消息队列、预热池、容器复用和独立执行机器/VM 建设。
- 全量历史事件回放、无限日志/快照及用户可用的撤销已应用修改功能。
- 第一阶段备份与恢复功能、备份脚本和恢复验收；固定全局业务数据总预算及磁盘水位策略。不豁免单场限额、磁盘不足安全处理、已有执行资源约束或正常重启恢复。
