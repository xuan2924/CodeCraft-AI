# 07: 定向回收过期开发与验证资源

**What to build:** 开发者能够识别并回收本项目已过期的验证工作树、容器、卷和镜像，不误删活跃环境、待恢复证据或其他项目数据；镜像清理逻辑不再承担旧标签兼容。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 盘点本项目资源的归属、活跃引用与保留用途，不能只根据创建时间判定过期。
- [ ] 当前镜像清理只处理受支持的规范标签，未知别名、活跃容器及受保护镜像保守跳过。
- [ ] 定向清理确认过期的本任务工作树、容器、卷、镜像及无用临时产物，不使用全局 prune。
- [ ] 删除工作树前确认没有未提交修改和未合入成果；删除卷前确认没有业务数据、绑定或恢复依赖。
- [ ] 对清理筛选和保护规则保留正常与失败回归，记录实际删除、保留及无法判定的资源，不把清理计划写成执行结果。
- [ ] 完成审查与独立提交；一次性本地资源回收不升级为未经确认的周期任务或 CI 门禁。

## Comments

- 来源：01 总任务及用户新增“过期工作树/容器/卷/镜像及时处理”的要求。
- 已有进展：旧镜像标签兼容分支已修改，部分临时验证产物仅移动到忽略的运行目录，尚不能据此宣称已经回收。当前只有一个 Git 工作树；Docker 中有其他项目与活跃服务，必须按归属筛选，不可批量停止。
- 可独立盘点；实际回收本轮仍在使用的验证资源须等其使用结束。这是资源使用约束，不是必须等待所有实现票完成。
