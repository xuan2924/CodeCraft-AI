# Copilot 编码体验增强

## 授权与交付顺序

用户已确认先完善 Copilot 编码体验，再推进完整面试产品。本规格记录已确认范围，不代表功能已经实现；实施与验证结果另记对应任务。无需再次确认以下产品选择，技术接线由 Agent 按现有架构处理。

本轮不建设多租户、通用插件体系或额外模型地址治理，不以恶意代码威胁扩展工作范围。复用现有 Java 主后端、Go/Docker 执行与 Vue IDE。

## 问题与目标

前两阶段已具备工作区编辑、隔离测试、多轮工具循环、审批、steer、Skill 和持久化恢复。本轮不重建 Agent 框架，而是把受控题目 Copilot 补足为能执行常用开发命令、获得相关项目上下文、清晰反馈执行过程并支持多会话协作的编码助手。

交付目标是用户可以在同一工作区内连续完成“理解项目 → 执行命令/获取资料 → 修改 → 查看结果 → 调整方向 → 撤销或换分支继续”的工作流。Pi 仅作体验参考，不要求复制其全部功能或证明达到同等实战效果。

本文中的“项目”指当前演练关联的工作区，不新增独立项目管理产品、任意仓库导入、多语言执行或 Git 分支管理；New/Fork 是同一工作区内的对话组织能力，不改变一场演练的生命周期。

## 已确认范围

1. **模型适配**：优先 DeepSeek，采用 Chat Completions；不为协议名称迁移至 Responses。完善目标模型的思考、工具调用、流式输出与必要字段往返。保留其他协议入口，但不要求其他供应商正常使用实测，不新增供应商全矩阵验收。
2. **通用执行**：用户和 Copilot 均可在 Docker 内执行 Bash，允许联网及下载依赖；提供运行状态、流式输出、退出码、停止和文件变化同步。AI 命令沿用 ask/auto 体验。普通命令执行结果不冒充平台权威验收。
3. **项目上下文**：加载项目指令，支持文件、选中代码与日志引用，按需获取内容；不默认把整个项目装入每次请求。
4. **工具反馈与输出**：呈现命令、状态、错误及文件 Diff；长输出明确截断且可继续查看。区分回答、思考、工具执行与审批，完善代码块、日志查看与复制。
5. **队列**：steer 在当前任务中介入；follow-up 在当前任务完成后执行，队列可查看和取消。
6. **会话**：同一项目支持 New 与 Fork。New 不继承旧对话；Fork 继承指定位置之前的对话。会话共享项目工作区，创建或切换对话不复制、不回滚文件。
7. **内嵌能力**：内置 btw 旁支讨论、subagent 委派与结果返回、联网搜索及资料读取。不建设通用扩展/插件机制。
8. **修改恢复**：统一保存、AI 修改和 Bash 文件修改的历史；支持预览、撤销与回滚。恢复产生新修订，不删除历史，不回退外部副作用或模型费用；结束后的冻结版本仍只读。
9. **上下文压缩**：保留现有实现，本轮不做压缩保真、质量或长任务专项验证。

## 用户流程

```text
进入现有项目工作区
  → 选择已有会话 / New / 从历史位置 Fork
  → 输入任务，并按需引用文件、选中代码或日志
  → Copilot 加载项目指令与相关内容
  → 读取 / 修改 / Bash / 搜索资料 / 委派 subagent
      → ask 审批或 auto 执行
      → 展示输出、错误、Diff 与可继续读取的证据
  → 运行中 steer 调整方向，或加入 follow-up 等当前任务结束
  → btw 讨论旁支问题，按需把结论带回主线
  → 查看结果，必要时撤销修改或回滚代码
```

手动 Bash、保存、Copilot 与子任务最终操作的是同一份工作区。切换聊天不等于切换代码，关闭页面不等于停止后台任务。

## 行为契约

### 1. DeepSeek 与模型适配

- 本轮主路径为 DeepSeek Chat Completions；Chat 是传输协议，不限制 Agent 使用思考和多轮工具。完善现有适配，不默认迁移 SDK 或引入新的 Agent 执行框架。
- 保持思考模式配置、流式文本、工具参数、调用 ID、结果回填及供应商要求的历史字段一致。思考展示与下一轮请求需要保存的协议字段分开，不能为了简化 UI 丢弃原始字段，也不伪造模型未返回的思考内容。
- 参数/能力不支持、网络失败和工具执行失败应能区分；不能悄悄切换协议、模型或思考模式后显示成功。恢复不自动重发结果未知的收费请求。
- 其他已有协议/配置入口保留，不新增其支持承诺。本轮不要求修复 DeepSeek Responses 思考组合，也不将 Messages 思考实测作为门槛。
- 使用可控模型响应和协议夹具覆盖改动的适配逻辑，不以真实供应商调用成功作为交付条件。这里改变的是本轮验收安排，不自动取消产品运行时已有的模型准备检查。

### 2. Bash 与联网开发

- 手动入口和 Copilot 工具调用均支持命令、项目内工作目录及执行反馈；不再只接受预设测试命令。使用 Docker 内 Bash，不在 Java/Go 宿主执行用户命令。
- 允许联网和下载依赖。安装产物、缓存、运行目录与可恢复的项目源文件应明确区分，不能把下载目录无限复制进代码历史或每次模型上下文。
- 执行前可见命令与工作目录。AI 命令沿用 ask/auto；ask 批准的是该条命令，不是对事后文件 Diff 的预批准。auto 不逐条弹窗；手动命令不重复申请 AI 审批。
- 输出包含执行身份、状态、stdout/stderr、退出码与停止/超时等原因。非零退出不是平台故障；模型应得到可用于修正的结果，而非只有“执行失败”。
- 停止必须作用于实际执行；显示停止完成前先收敛所属命令。失败、超时或停止都可能已经改过文件，必须同步这些变化，不能按命令是否成功决定是否登记修改。
- Bash 与手动保存、AI Patch、回滚之间须协调写入，不静默覆盖新版本或未保存草稿；具体采用串行写入或隔离执行后提交由实现设计确定，不要求长命令期间一直锁死编辑器。
- 命令变化进入修订与 Diff 后，编辑器按正式版本同步；本地草稿仍需保留并显示冲突。不能把命令结束直接等同于文件已同步成功。
- 普通开发命令与权威测试职责分离：前者可联网、可运行用户测试；后者仍用平台权威测试和明确代码版本判断验收，普通命令输出不能直接标记题目通过。
- 无需新增完整交互式 PTY、后台常驻服务托管或全功能终端模拟器；执行 Bash、输出和停止不能仅以展示模拟日志代替。

### 3. 修改历史、撤销与回滚

- 手动保存、AI 修改、Bash 引起的受管理文件变化进入统一历史，标明来源、基线/结果修订、涉及文件和关联任务/会话；内容未变化不生成无意义修订。
- 用户可查看变化并预览恢复 Diff。撤销针对一次已记录修改，回滚针对选定的可用历史代码版本；两者均生成新的当前修订，不擦除原历史。
- 在后续修改存在时，撤销不能默默覆盖后续成果；能安全应用则展示预览，存在冲突则明确拒绝或要求处理，不擅自自动合并。
- 恢复遵循当前正式版本及写入协调规则。运行中的测试仍绑定原快照，恢复后不会自动取得旧测试的“当前版本已通过”状态。
- 代码恢复不恢复对话游标、外部网络副作用、模型费用、依赖缓存或容器进程状态。用户能知道恢复范围，不能把 UI 上的“回滚”宣传成整个运行环境的时间旅行。
- 历史受保留/容量策略约束，不承诺无限版本。尚未确定的历史保留数量与二进制/生成文件策略列入技术落地项；已清理版本不可继续展示为可恢复。

### 4. 项目上下文与资料引用

- 自动发现并加载约定的项目指令文件（例如 `AGENTS.md`），显示生效来源；明确目录作用域、优先级与更新生效点，避免把无关子目录指令全部注入。
- 用户可以选择文件、代码范围与日志片段作为输入，提交前看得见引用对象。引用应保留路径/来源身份及必要版本信息，内容变化后不能把当前文本冒充当时提交的片段。
- 项目指令、任务输入、Skill、工具结果分别组装；New 会话仍获得项目指令与当前工作区信息，但不因此继承其他会话的完整聊天。
- 大文件和长日志按需读取、搜索和分页；缺失、超限、读取失败及截断明确反馈。此处完善的是上下文入口与取回能力，不新增摘要或压缩保真验收。

### 5. follow-up 与运行控制

- UI 明确区分 steer 与 follow-up。steer 修改当前任务下一安全点的方向；follow-up 是当前任务之后的新请求，不提前塞入当前轮模型输入。
- follow-up 按接收顺序登记在所属会话，展示排队状态并可取消；进入执行时成为独立任务。取消排队项与停止已启动任务是不同操作。
- 后端决定派发，刷新、重连或重复提交不能重复启动。待审批属于当前任务尚未完成，不可绕过它运行队列下一项。
- 队列不能跨会话偷偷执行或因切换 UI 转移归属；停止、失败、演练到期、授权失效与队列派发的关系必须明确，不在失去执行资格时继续派发。
- “当前任务后再执行”是显式用户队列，不将原有忙结果全部改成隐式排队。具体失败/停止后的队列暂停策略及上限作为实施契约落实。

### 6. New 与 Fork

- 同一项目提供会话列表、创建、选择与历史查看。New 建立空对话历史；Fork 从用户选择的历史位置建立独立对话分支，并标识来源。
- Fork 的继承边界必须保持工具调用与结果成对；不能复制一个待审批提案变成新的可执行审批，也不能重放历史命令。边界落在未完成工具批次时应明确提示可用位置。
- New/Fork 共享当前工作区与代码历史；不创建 Git 分支、不复制容器、不恢复到 Fork 时的代码。界面明确“对话历史来自过去，文件是当前版本”。
- 会话消息、队列、运行状态与上下文引用有各自身份；不能因原先只有演练级上下文而将不同会话消息混在一起。
- 切换/新建/Fork 不自动停止已有任务，也不默认授权多个会话同时修改工作区。跨会话运行准入与写入协调须给出明确忙/等待提示，不能静默争抢。

### 7. 内嵌 btw、subagent 与联网资料

| 能力 | 用户可见行为 | 与主线关系 |
|---|---|---|
| btw | 针对旁支问题展开讨论，主任务不因打开旁支而被替换；用户可选择将结论带回 | 不自动把全部旁支消息注入主线；带回当前任务走显式 steer 或后续请求 |
| subagent | 可委派任务，查看子任务状态、输出、结果和失败原因 | 子任务有独立任务身份与上下文，结果通过明确交接返回，不冒充主任务已完成 |
| 联网资料 | 可搜索资料并读取网页正文，显示来源链接、内容和失败/截断信息 | 搜索摘要与获取到的正文区分；来源进入工具结果，模型不伪造检索成功 |

- 以上是产品内嵌入口和工具，不依赖用户自行安装 Pi 扩展，不引入通用插件市场、任意扩展脚本或多 Agent 团队管理产品。
- subagent 复用本轮模型、工具、审批与执行能力，不作为绕开 ask/auto、截止或共享文件版本的另一个通道。任务归属、停止传播和结果回收必须接入现有任务机制。
- 是否允许子任务并发写入、具体并发上限、btw 可用工具及上下文投影由技术设计明确；本规格不额外承诺递归多级委派或无限并发。
- 搜索与正文读取提供真实可配置的实现接线，不能只交付测试假工具。搜索供应商/组件选择优先复用成熟方案，缺少配置时如实显示不可用；使用确定性替身验收契约，不要求真实联网服务成功才通过。
- btw/subagent 的模型调用与联网工具如有费用，应沿既有身份/用量归属呈现；不因旁支入口将用户 Key 费用转移给平台 Agent。

### 8. 输出与恢复体验

- 文本、供应商提供的思考内容、工具状态、审批和最终回答在视觉上可区分；代码块可复制，命令、日志和 Diff 可展开查看。
- 流式更新必须关联对应会话、任务与工具。页面重连恢复已保存状态，不重新执行命令，不将不完整预览当最终答案。
- 输出太长时同时反馈“当前展示/模型返回截断”和“底层记录已淘汰或不完整”的区别；继续查看只能读取尚保留的内容，不承诺无限日志。
- 失败应提供下一步可用动作，例如修改命令、重新读取、处理冲突或重试新请求；不以不断弹出同一通用错误代替工具反馈。

## 既有能力复用与技术落地项

以下是实现前需要落实的契约，不重新询问已确认范围，也不把技术设计任务等同于新增产品目标：

| 接线点 | 需要明确的内容 |
|---|---|
| Java / Go / Docker | Bash 执行、联网配置、依赖目录、命令归属、停止与文件变化确认；不绕过原执行回执和对账机制 |
| 修订与历史 | 保存/AI/Bash 共用修订，撤销冲突处理，可恢复文件范围、保留和容量策略；复用现有存储计量，不默认增加全局预算或备份 |
| 会话数据迁移 | 将既有演练中的对话、任务和证据映射到可访问的初始会话；不能让旧历史因引入 session ID 消失 |
| 调度与恢复 | follow-up 幂等派发、失败/停止后的队列行为、跨会话准入、btw/subagent 生命周期与有限并发 |
| 项目指令 | 指令发现与层级、更新时点、引用快照及按需读取接口 |
| 模型和搜索 | DeepSeek Chat 参数与字段映射、搜索/抓取成熟组件与配置；不增加真实供应商通过要求 |
| 前端与事件 | 消息/执行事件携带正确归属，New/Fork/队列/旁支入口、草稿与文件变更协调 |

技术细节可由 Agent 自行选择并在所属任务记录。若确有会改变已确认产品行为的缺项，仅指出该增量，不重问协议选择、联网、评分形式或验证安排。相关实现需读 [风险优先实施](../../docs/agents/risk-first-delivery.md)，以确定性失败注入覆盖必要恢复，不默认安排真实强杀或跨服务故障矩阵。

| 联网资料 | 搜索与正文读取实际接线，来源及错误可见；适配契约用替身验证，不要求真实服务成功 |
| 工程收口 | 受影响类型/编译、Lint 和核心逻辑测试通过；完成变更自审，记录真实通过/失败/未运行，不新增长任务或压缩保真专项 |

## 验收边界

- Agent 负责实现、受影响编译/类型/Lint、核心逻辑确定性自动化测试及自审。
- 不以真实模型调用成功、供应商兼容实测或真实编码任务表现作为本轮通过门槛。未验证组合如实披露，不能标成实测通过。
- 实战效果由用户自行验证；不自动生成待 QA 欠账，不新增收费调用、重型端到端或故障矩阵。
- 不把不做实战验证解释为不实现功能或跳过受影响逻辑测试。
- 本规格更新的是新一轮产品范围，不改写前两阶段历史验收事实。相关领域设计中的禁网、无通用 Shell、无回滚等旧边界，在本轮对应实现时同步更新；联网开发命令与权威验收执行的职责分别明确。

## 实施顺序

1. 核对既有执行、修订、任务和模型接线，先落地 Bash/联网、文件变化同步及统一恢复历史。
2. 完善模型适配、项目上下文、工具反馈与输出体验。
3. 引入 New/Fork、follow-up、btw、subagent 与联网资料工具，明确共享工作区下的写入协调和任务生命周期。
4. 集中完成受影响 L1 与自审，报告实际实现和验证，不添加实战门槛。

具体依赖拆分以代码检查为准，不将上述内部步骤各自变成一轮产品验收。
