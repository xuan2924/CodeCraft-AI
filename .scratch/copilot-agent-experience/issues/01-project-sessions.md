# 01: 同项目 New 会话与历史切换

**What to build:** 用户在现有演练工作区中新建、选择和查看多个 Copilot 会话。会话各自拥有消息与任务状态，共享当前代码；旧演练历史仍可访问。必要的会话身份重构与迁移在本票内先完成，再贯通用户入口。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Spec:** [Copilot 编码体验增强](../spec.md)，行为契约 6、8 及技术落地项。

## Acceptance criteria

- [ ] 提供会话列表、New、选择与历史查看；New 不继承其他会话聊天，创建或切换不复制、不回滚代码。
- [ ] 旧演练中的消息、任务、审批和证据映射到可访问的初始会话；迁移可重复执行而不丢失或重复历史。
- [ ] 模型上下文、事件、任务和页面状态带有正确会话归属；重连和切换不串消息、不重新派发任务。
- [ ] 新建和切换不自动停止已有任务。跨会话运行准入与共享工作区写入协调有明确反馈，不默认允许多个会话静默争抢写入。
- [ ] 保留既有审批、模型选择、Skill、用量、结束只读及删除行为；会话记录纳入既有保留和容量机制，不重新设计压缩算法。
- [ ] 以迁移、服务和组件确定性测试覆盖历史访问、New 隔离、切换中事件归属、重复创建及忙状态；完成受影响类型/编译、Lint 与自审。

### 实施决定：显式对话身份与渐进兼容

- 备选：仅前端分组；以当前选中会话作为服务端全局状态；为任务及上下文保存显式对话身份。选择第三项：前两者会在切换页面或后台任务仍执行时串上下文，不能满足 New 的隔离语义。
- 使用 conversation 标识 Copilot 对话，避免与登录 session_hash 混淆。旧演练的初始对话 ID 固定取演练 ID，新增对话使用独立 UUID；二者仍由所属演练授权，不因 ID 相等混同职责。
- 旧接口未传对话 ID 时明确访问初始对话，不按全局“最近选择”猜测。已有任务、消息引用、上下文摘要和审批身份保持，迁移只补归属，不复制协议消息或重新执行工具。
- 对话元数据沿演练保留、计量与删除；单演练暂设 100 个对话上限（含初始对话），选择显式拒绝而非无限列表或静默截断。创建预留 4 KiB，不增加全局磁盘预算；限额与取舍随本票记录，不将其扩展为额外运营体系。
- 保持每演练最多一个主 Copilot 活动任务；切换/New 不停止任务，新会话若发起请求时槽位被占用则明确提示忙。并行子任务策略在 #11 落实，不提前引入复杂调度。
- 上下文版本头和压缩记录按对话归属接线，保持原压缩算法；只验证会话隔离与恢复接口，不做压缩质量或保真专项。用量累计仍按演练，当前上下文展示须对应所选会话。
- 测试边界：公开会话/任务入口与实际 PostgreSQL 迁移验证归属、幂等和旧数据；可控模型请求验证只收到本会话消息；组件与 API 验证 New、切换、在途响应归属。不使用真实供应商或实战表现作为门槛。
