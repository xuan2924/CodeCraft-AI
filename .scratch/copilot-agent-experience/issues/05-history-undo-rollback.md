# 05: 统一修改历史、撤销与回滚

**What to build:** 用户查看手动保存、AI Patch、Bash 的统一修改历史，预览并撤销一次修改或回滚到可用版本；恢复产生新修订，不擦除原记录或悄悄覆盖后续成果。

**Blocked by:** 03 — 手动联网 Bash 与文件同步。

**Status:** ready-for-agent

**Spec:** [Copilot 编码体验增强](../spec.md)，行为契约 3 及技术落地项。

## Acceptance criteria

- [ ] 三类修改统一显示来源、基线/结果修订、涉及文件和可用的任务/会话关联；可查看 Diff，未变化不生成无意义修订。
- [ ] 明确可恢复文件范围、历史保留与容量策略，复用既有计量/删除机制；不存在或已清理版本不能显示为可恢复，不承诺无限历史。
- [ ] 撤销一次修改与回滚到历史代码版本有明确入口和预览；正式应用以当前基线校验，成功生成新修订，原历史仍保留。
- [ ] 后续修改造成撤销冲突时明确拒绝或要求处理，不静默覆盖或擅自自动合并；在途写入和未知结果未收敛时不能抢先恢复。
- [ ] 编辑器草稿得到保护；恢复不把旧测试通过结果冒充当前版本通过，不回退对话、费用、外部网络副作用、缓存或进程状态。
- [ ] 冻结后只读；重复请求不重复恢复；用确定性测试覆盖三类来源、预览/提交基线变化、冲突、删除/创建恢复、冻结及可控时钟保留逻辑。
- [ ] 完成页面到持久化/工作区的完整接线、受影响类型/编译、Lint、自审及历史策略文档同步。

## 验收与范围边界

不依赖 #04：既有 AI Patch 与 #03 已提供三类修改来源。会话关联适配已存在的身份，不把会话新功能作为本票门槛。不新增 Git 管理、灾难备份、真实供应商、实战或压缩保真验收。
