# 06: 项目指令发现与上下文加载

**What to build:** Copilot 自动获得项目约定的指令，按相关目录范围加载；用户看得到生效来源，新会话获得项目规则而不会继承其他会话聊天。

**Blocked by:** 01 — 同项目 New 会话与历史切换。

**Status:** ready-for-agent

**Spec:** [Copilot 编码体验增强](../spec.md)，行为契约 4。

## Acceptance criteria

- [x] 发现约定的项目指令文件（例如 AGENTS.md），明确目录作用域、层级优先级、更新生效点及内容限额，并将有效指令接入实际请求组装。
- [x] 页面可查看生效来源；根目录规则与相关子目录规则正确区分，不一次性注入所有无关目录指令。
- [x] 项目指令、用户任务、Skill 与工具结果分别组装；New 会话拥有当前项目规则，不泄入其他会话聊天或私有旁支记录。
- [x] 指令缺失、过长、读取失败或版本变化有明确处理；不把文件内容变成审批授权，不自动重写用户任务。
- [x] 用临时项目/文件替身、请求组装和组件测试覆盖目录规则、更新、限额、新会话隔离及来源展示；完成受影响类型/编译、Lint、自审和上下文设计同步。

## 验收与范围边界

本票不依赖 #07 的用户显式引用入口，不建设 AST、向量索引或全仓一次性注入。不重新设计摘要/压缩，不新增其质量或保真验收；无需真实模型或实战表现验证。

## Comments

发布时用户已确认本票范围与依赖；实施结果、技术决定及实际验证统一追加于此。

### 实施决定

- 对比每轮全仓注入、任务开始固定快照、按实际读取路径逐层加载：选择每次模型请求准备时读取根 `AGENTS.md`，并加载当前任务最近最多 32 次 `view_file` 所涉及路径的祖先目录规则。不解析用户自然语言猜目录，不注入无关子树；New 仅从根规则开始，任务内读取文件后下一模型请求获得相关目录规则。
- 仅使用正式已发布工作区的可读文本文件，不读取 Java/Go 宿主项目或私有配置；指令随正常题目发布或既有受管理路径编辑更新，不新增任意文件写权限。规则按根到叶层级排列，子目录仅在自身子树内优先，不能授权审批/工具或覆盖平台规则。
- 每文件最多 8 KiB、累计正文最多 32 KiB、最多 32 个来源；缺失正常标记、超限/读取失败明确记录但不将部分正文冒充完整指令。准备时版本变化拒绝本轮混合快照，下一安全点重新准备；派发比较已观察的正式修订。每次派发保留实际来源/正文快照，页面读原快照而不是用当前文件冒充历史，纳入既有模型调用预留与 turn 行计量/删除。
