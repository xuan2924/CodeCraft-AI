# 09: follow-up 队列

**What to build:** 用户在当前 Copilot 任务运行时排入后续请求，查看并取消队列；当前任务结束后由服务端按顺序启动独立任务，与立即介入的 steer 清楚区分。

**Blocked by:** 01 — 同项目 New 会话与历史切换。

**Status:** ready-for-agent

**Spec:** [Copilot 编码体验增强](../spec.md)，行为契约 5。

## Acceptance criteria

- [x] 输入入口明确选择 steer 或 follow-up；follow-up 持久登记到所属会话，不提前进入当前任务模型输入。
- [x] 队列按接收顺序显示，待派发项可取消；取消排队项和停止已启动任务是不同操作，派发后成为独立任务。
- [x] 当前任务待审批仍未结束，不提前启动下一项；切换会话不转移队列、不偷用其他会话上下文。
- [x] 明确并记录失败/停止后的暂停或继续行为、队列上限及重新启动条件；到期、授权失效或失去运行资格时不继续派发，UI 显示原因。
- [x] 派发由后端幂等控制；重复提交、刷新、重连及派发与取消竞争不能启动重复任务；恢复不盲重发未知收费请求。
- [x] 只对用户显式加入的 follow-up 排队，不把工具忙、手动测试忙等已有结果改成隐式队列。
- [x] 用确定性调度/持久化与组件测试覆盖顺序、取消竞争、待审批、终止资格及恢复；完成受影响类型/编译、Lint、自审与调度文档同步。

## 验收与范围边界

不增加跨项目工作流、任务优先级系统或实战长任务验收；不要求真实模型成功、收费调用或压缩保真验证。

## Comments

发布时用户已确认本票范围与依赖；实施结果、技术决定及实际验证统一追加于此。

### 实施决定

- 对比前端自动发送、把所有忙请求隐式排队、显式持久会话队列：采用第三种，后端将队首与新独立任务原子绑定，再由原 worker 执行。待审批/PAUSED 主任务仍占活动名额，不能提前派发；跨会话忙只等待原会话队列，不转移归属。
- 每会话最多 32 个待执行/暂停项，单项原文 4 KiB，显式费用确认。每项保留原会话、会话授权标识、控制凭证摘要及当前任务锚点，不保存原始 Cookie/操作凭证。
- 前一项/原任务成功后继续；失败、停止、中断或授权/容量失效后暂停队首并阻止后续越过。用户显式确认费用并以当前操作权“重新授权并继续队列”，更新尚未派发项授权；恢复请求幂等，不因重连自动继续。演练结束/到期则取消未派发项，已派发项走原任务停止入口。
- 比较内存 timer 和新通用调度框架，继续复用 CopilotCoordinator 有界池。队首检查/取消/派发在原所有者锁下排序，网络计量在事务外；未知模型/工具仍沿原任务恢复，不重复启动。

### L1 交付与验证

- 已交付 V46 持久化队列/恢复回执、受保护 REST、原子独立任务准入、有界调度器接线、容量与整场保留删除、独立前端输入/顺序记录/取消/恢复/原键核对及 API/Loop/UI 文档。前端每次刷新只读，不隐式重复提交。
