# 09: follow-up 队列

**What to build:** 用户在当前 Copilot 任务运行时排入后续请求，查看并取消队列；当前任务结束后由服务端按顺序启动独立任务，与立即介入的 steer 清楚区分。

**Blocked by:** 01 — 同项目 New 会话与历史切换。

**Status:** ready-for-agent

**Spec:** [Copilot 编码体验增强](../spec.md)，行为契约 5。

## Acceptance criteria

- [ ] 输入入口明确选择 steer 或 follow-up；follow-up 持久登记到所属会话，不提前进入当前任务模型输入。
- [ ] 队列按接收顺序显示，待派发项可取消；取消排队项和停止已启动任务是不同操作，派发后成为独立任务。
- [ ] 当前任务待审批仍未结束，不提前启动下一项；切换会话不转移队列、不偷用其他会话上下文。
- [ ] 明确并记录失败/停止后的暂停或继续行为、队列上限及重新启动条件；到期、授权失效或失去运行资格时不继续派发，UI 显示原因。
- [ ] 派发由后端幂等控制；重复提交、刷新、重连及派发与取消竞争不能启动重复任务；恢复不盲重发未知收费请求。
- [ ] 只对用户显式加入的 follow-up 排队，不把工具忙、手动测试忙等已有结果改成隐式队列。
- [ ] 用确定性调度/持久化与组件测试覆盖顺序、取消竞争、待审批、终止资格及恢复；完成受影响类型/编译、Lint、自审与调度文档同步。

## 验收与范围边界

不增加跨项目工作流、任务优先级系统或实战长任务验收；不要求真实模型成功、收费调用或压缩保真验证。
