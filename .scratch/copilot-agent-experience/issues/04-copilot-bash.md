# 04: Copilot Bash 审批与执行闭环

**What to build:** Copilot 能提出开发命令，经 ask/auto 执行后获得输出、退出原因和文件变化，继续分析与修正；用户可以拒绝或停止，不只看到模拟工具卡片。

**Blocked by:** 03 — 手动联网 Bash 与文件同步。

**Status:** ready-for-agent

**Spec:** [Copilot 编码体验增强](../spec.md)，行为契约 2、8。

## Acceptance criteria

- [ ] Bash 工具贯通模型调用、业务登记、既有执行器、工具回执与页面状态，复用 #03，不另建一套命令执行机制。
- [ ] ask 显示具体命令和工作目录并等待批准，auto 可直接执行；批准针对命令，不宣称提前批准未知文件 Diff，切换模式不偷偷批准旧请求。
- [ ] 拒绝、忙、非零退出、超时、停止及同步未完成均有结构化回执；调用 ID 保持配对，模型可据结果继续，不把失败变成无限重试。
- [ ] 命令所属 Copilot 任务与执行身份持久化关联；父任务停止联动自己的命令，不停止用户独立命令；实际执行和文件变化收敛后才显示父任务已停止。
- [ ] steer、到期及审批竞争遵循有效任务和写入规则；重连/恢复不重复批准或重放已有命令，不复活已终止任务。
- [ ] 页面呈现审批、运行、输出、退出原因和 Diff；用可控模型、执行器及组件测试覆盖 ask/auto、拒绝后继续、停止联动和未知结果；完成受影响类型/编译、Lint、自审及审批/Loop 文档同步。

## 验收与范围边界

现有 Loop 可作为本票基础，#02 不是开工门槛；共享适配发生变化时复查受影响契约即可。不要求真实模型、联网下载或实战成功，不增加压缩保真、收费测试或全套故障矩阵。

## Comments

### 风险与实施决定

- #03 已在 `891311e` / `6ec26d4` 完成。复用 `CommandTaskStore` 的准入、精确执行身份、原授权 gate、容量及恢复协调器；Copilot 只增加命令提案/决定与父工具绑定，不另建 Go 执行或恢复入口。
- `bash(expected_revision, command, directory)` 审批固定原命令、目录和基线；登记时保存 ASK/AUTO 及模式版本。批准不提前批准未知 Diff。原子提交决定、子命令登记和父工具等待；后续恢复只查询绑定的命令，不重新 Start。已有手动回执即使键/载荷相同也不得被父任务认领。
- 父任务新增 `WAITING_COMMAND`；只有原执行已静默、文件同步已得到确定结论且清理收敛，才回填配对工具结果并允许父任务停止或继续。steer 不打断已受理命令的核对；尚未批准的旧命令失效，剩余调用沿既有规则补齐未执行回执。
- 通过现有演练数据贡献接口保护尚未回填父工具结果的命令证据，回填后恢复 #03 的有界普通保留；父子绑定和决定审计纳入既有容量、保留期限与删除顺序。停止只使用持久绑定，不按演练随意停止独立手动命令。
- 复用既有有界 worker 池处理 AUTO，计量/完整回执投影在事务外；忙、拒绝、基线冲突和确定准入失败回填结构化结果，临时计量/协调故障保持待核对，不触发新收费模型轮次。使用可控模型、数据库事务及组件测试验证，不增加外网/收费供应商门槛。
