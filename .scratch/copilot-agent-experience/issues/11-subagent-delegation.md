# 11: 内嵌 subagent 委派与结果交接

**What to build:** 主 Copilot 能委派编码子任务，用户能查看任务目标、运行状态、工具执行和结果；子任务遵循审批及工作区一致性规则，结果明确交回主线。

**Blocked by:** 01 — 同项目 New 会话与历史切换；04 — Copilot Bash 审批与执行闭环。

**Status:** ready-for-agent

**Spec:** [Copilot 编码体验增强](../spec.md)，行为契约 7、8。

## Acceptance criteria

- [ ] 内嵌委派入口/工具贯通父任务、独立子任务身份、上下文构建和实际 Loop；页面显示目标、状态、输出、结果及失败原因，而非静态演示。
- [ ] 子任务复用现有模型与工具能力，包括 Bash；保留所需任务上下文，不共享全部无关聊天，不擅自读取其他旁支私有历史。
- [ ] 复用 ask/auto、修订与执行规则；子任务修改不能绕过审批，父子及跨会话写入必须协调，不以覆盖结果模拟成功合并。
- [ ] 明确有限并发、子任务可用工具、父任务等待/继续方式、停止传播与结果交接；不承诺无限并发或递归多级委派。
- [ ] 父子任务及所属命令停止有明确关联，执行未收敛前不假报已停止；到期或授权失效后不继续派发，恢复不重复执行已完成工具。
- [ ] 子任务成功、失败、停止均产生可追溯交接结果，主线取得结果后可继续；子任务完成不能冒充整个主任务已完成。
- [ ] 子调用用量、费用与记录纳入既有用户归属、保留和容量体系，不转移到平台 Agent 费用。
- [ ] 用可控模型/执行器和服务、组件测试覆盖委派、审批、写入竞争、停止、失败交接、重连及删除引用；完成受影响类型/编译、Lint、自审与父子任务契约同步。

## 验收与范围边界

不建设通用团队框架、插件系统或独立工作区自动合并产品。#02、#09、#10、#12 不是本票开工门槛；复用届时已存在工具，不要求完成其他独立能力才验证委派。无需真实供应商、实战效果、真实强杀或压缩保真验收。
