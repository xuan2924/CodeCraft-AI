# 11: 内嵌 subagent 委派与结果交接

**What to build:** 主 Copilot 能委派编码子任务，用户能查看任务目标、运行状态、工具执行和结果；子任务遵循审批及工作区一致性规则，结果明确交回主线。

**Blocked by:** 01 — 同项目 New 会话与历史切换；04 — Copilot Bash 审批与执行闭环。

**Status:** ready-for-agent

**Spec:** [Copilot 编码体验增强](../spec.md)，行为契约 7、8。

## Acceptance criteria

- [x] 内嵌委派入口/工具贯通父任务、独立子任务身份、上下文构建和实际 Loop；页面显示目标、状态、输出、结果及失败原因，而非静态演示。
- [x] 子任务复用现有模型与工具能力，包括 Bash；保留所需任务上下文，不共享全部无关聊天，不擅自读取其他旁支私有历史。
- [x] 复用 ask/auto、修订与执行规则；子任务修改不能绕过审批，父子及跨会话写入必须协调，不以覆盖结果模拟成功合并。
- [x] 明确有限并发、子任务可用工具、父任务等待/继续方式、停止传播与结果交接；不承诺无限并发或递归多级委派。
- [x] 父子任务及所属命令停止有明确关联，执行未收敛前不假报已停止；到期或授权失效后不继续派发，恢复不重复执行已完成工具。
- [x] 子任务成功、失败、停止均产生可追溯交接结果，主线取得结果后可继续；子任务完成不能冒充整个主任务已完成。
- [x] 子调用用量、费用与记录纳入既有用户归属、保留和容量体系，不转移到平台 Agent 费用。
- [x] 用可控模型/执行器和服务、组件测试覆盖委派、审批、写入竞争、停止、失败交接、重连及删除引用；完成受影响类型/编译、Lint、自审与父子任务契约同步。

## 验收与范围边界

不建设通用团队框架、插件系统或独立工作区自动合并产品。#02、#09、#10、#12 不是本票开工门槛；复用届时已存在工具，不要求完成其他独立能力才验证委派。无需真实供应商、实战效果、真实强杀或压缩保真验收。

### 实施决定

- 对比子进程独立 Agent 框架、让模型模拟委派文本、复用当前持久化 Copilot Loop：采用第三种，委派工具创建真实子任务/独立会话，保留父任务、原工具调用身份及目标；不建立工作区自动合并系统。
- 只允许一层、每场一个活动 CHILD、每父任务最多 8 次且一次在途委派；父任务等待子任务确定结果并释放 worker，不与子任务同时修改工作区。子任务复用现有读取、提案、ASK/AUTO、测试、Bash、资料工具，禁止再次委派；仍共享演练的真实修订/写入协调及额度。
- 工具目标最多 4 KiB、显式选取的支持上下文最多 8 KiB；初始上下文另含父任务最近已保存用户目标最多 4 KiB、来源 ID 和截断标记，不复制无关聊天或其他旁支私有历史；子任务后续运行自身上下文。用户可查看子任务完整状态、工具/提案/命令与待审批项，不把子任务完成表示为主任务完成。
- 子任务确定成功、失败或停止都生成对应原委派工具的可追溯交接回执，父任务获得结果后继续自己的模型循环。父任务停止须传播到子任务及所属命令，子任务未收敛前父任务不能假报已停止；服务恢复不重新创建子任务或重复已完成工具。
- 父任务持久 WAITING_CHILD，待原工具收到子任务真实终态、最新已保存助手文本最多 16 KiB、来源与观察修订后继续；父 steer 等交接后安全点生效。子 PAUSED 不算完成，可停止子任务向父交回；原授权失效不自动改绑新授权。停止/失败不撤销已提交修改。
- 子详情直接复用既有任务面板及其消息、审批、Bash、测试、SSE 和摘要；隐藏主请求/旁支/再次委派入口，只保留一层。代码历史保留子任务 ID，导航到所属主会话。
- 费用与模型配置仍属原用户，子任务/交接保留计量和删除纳入原演练，不转记平台 Agent。复用届时已有任务通道能力但不依赖旁支用户流程或 follow-up 输入。
