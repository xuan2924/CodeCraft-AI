第一阶段达到 Dev Done（功能、L1 与代码审查完成，不含远程 CI 或重型验证）；前置票及 P2-02 的安全点、顺序和未执行结果协议完成。读 [Loop steer](../../../docs/design/copilot-loop.md#steer)。

## Acceptance criteria

- [x] 页面区分已接收与已生效，连续指令按接收顺序持久化；重复请求不重复插入，不静默覆盖。
- [x] 当前模型请求/已开始工具收敛后、下一项工具开始前处理；不修改已发出请求、不提前执行旧批次剩余项。
- [x] 保留已完成结果，使旧待审批提案失效，为未执行项补齐与调用 ID 匹配的明确结果后重新规划。
- [x] steer 仍属于当前任务，不刷新 Skill 快照，不创建第二任务；任务已结束或结束前未生效则明确提示，不自动另起任务。
- [x] 与批准、停止、到期及接管按服务端顺序协调；未知写入/测试不靠 steer 跳过对账或释放执行槽位。
- [x] 可控模型覆盖多指令、审批中、读写/测试进行中、流参数未完成、停止和结束竞争；验证恢复后顺序及协议配对。

## Comments

先验收首条协议的 steer；DeepSeek 思考模式及其他协议的字段兼容由 P2-19/20 在同一控制语义下验证，不静默降级。

### 实施决定

- 沿用原任务 ID、串行批次和资源所有者锁；新指令只进入 steer 审计队列，不改变已发出的请求。每条至多 4 KiB UTF-8，最多 32 条待生效指令，超限明确拒绝而非覆盖。确认请求需 USER、归属、ACTIVE、当前操作权、原父会话仍有效及幂等键；不借 steer 重新授权失效任务。
- 安全点是当前已派发请求/已登记 RUNNING 工具收敛后、下一工具开始前。待审批且未创建写意图的旧提案失效；已绑定 FILE_BATCH 或测试继续核对原结果，不借 steer 取消、释放槽位或跳过未知结果。批准与 steer 按所有者锁顺序决定：先批准的原写入必须收敛，先 steer 的旧提案不能再批准。
- 在安全点为旧批次剩余调用逐 ID 补齐 NOT_EXECUTED/STEER_SUPERSEDED，保留已完成结果；按接收顺序追加原用户指令。只有纳入新模型派发的持久上下文才标记 APPLIED（界面称已纳入请求，不声称供应商已收到）；此前为 RECEIVED。终态前没有派发的指令记录 NOT_APPLIED，不另起任务。
- 单条原文/预编码协议消息及后续正式消息共预留 64 KiB，避免转义后才发现无法保存；序列化在事务外完成，审计/消息归入既有计量与删除。真实外部调用不用于验证 steer 竞态，优先可控模型、真实 PostgreSQL 与组件竞态测试。

### Dev Done 与实际验证

- V33 及 GET/POST steers 接口、原键回执、数字游标、授权版本审计、32 条待处理上限、4 KiB UTF-8 与统一容量/删除已落地；NUL 和孤立代理字符在编码/入库前拒绝，合法 4 KiB 非 BMP 文字保留原文。
- 等待审批即时使旧提案失效；模型生成中、读工具中、提案准备中、未知原写入及等待测试时不越过安全点。原批次已完成结果保留，剩余逐 ID 配对；最终回答与 steer 竞争可唤醒原任务，停止/到期未派发指令明确 NOT_APPLIED。
- 前端接入原任务、只读分页、接收/已纳入请求/未生效状态；未知传输仅原键/原内容核对，账号/演练/任务/凭证变化隔离迟到回执。历史查询、断线观察及任务结束均不自动发起新任务。旧失效提案的文案改为通用失效，避免误称全部为基线冲突。
- 自审需求与规范：所有者锁排序决定与执行登记；RPC/输入编码在事务外；重用原工作区、审批、测试及容量链路，无第二写通道或浏览器凭证持久化。停止立即落终态及恢复清理均结算未生效指令；既有拒绝决定不因 steer 清空。无已知票内功能缺口。
