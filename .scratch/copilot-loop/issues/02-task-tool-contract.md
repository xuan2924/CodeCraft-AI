# P2-02：Copilot 任务与工具执行契约

**Type:** decision
**Status:** needs-triage
**Blocked by:** None
**Spec:** [第二阶段规格](../spec.md)

## What to build

确定正式任务、串行工具批次、提案审批、检查点与控制操作契约，复用第一阶段文件版本、执行槽位、持久化栅栏和回执，不另建绕过授权的工具通道。

## 决策边界

读 [Loop](../../../docs/design/copilot-loop.md)、[审批](../../../docs/design/approval.md)、[接口与事件](../../../docs/design/api-events.md)及 [底座恢复协议](../../../docs/design/task-event-recovery.md)。供应商字段由 P2-01 核验；本票与其协调接口，未核实内容保持门槛，不互相假定已完成。

## Acceptance criteria

- [ ] 确定候选读取/搜索/路径匹配/修改/测试工具的名称、schema、权限、结果和错误结构；限制路径、输出和命令，不把工具文本当授权。
- [ ] 定义单演练一个 Copilot 任务、串行批次/执行位置、调用 ID 配对、逐工具检查点及消息与业务状态的持久化边界。
- [ ] 定义批准/拒绝/模式登记、显式模型切换、停止、steer、结束/到期的排序和 REST/SSE/幂等语义；模型切换按当前请求及工具批次收敛后的下一次请求生效，不使待审批提案失效；未知写入必须复用底座对账，不盲目重放。
- [ ] 明确后台任务授权与页面接管、会话撤销、栅栏变化的关系，既不以旧页面凭证持续越权，也不把断线/接管误当任务停止。
- [ ] 定义 Copilot 测试归属、等待确定结果、父任务停止联动子测试、不停止独立手动测试；共用槽位忙时不排队、不抢占、不高频重试。
- [ ] 定义断线查询与重启恢复、中断收费请求用户重试路径、未完成流/工具参数处理和回执对账；不再生成已有批次。
- [ ] 给出单次超时、有限重试、无进展停止的配置与验收方案；不新增正常任务总 Token/总轮次硬截止。
- [ ] 用可枚举场景或最小模型核对竞争顺序，列出正式跨服务故障验证门槛；同步有效专题，产品待决项先取得确认。

## Comments

工具批次首期按模型返回顺序执行，不并行；auto 只免除逐次修改审批，权限不扩大。此票不将旧固定游标 PoC 直接升级成正式存储方案。

P2-03 讨论已确认演练内可显式切换个人配置中的模型：当前请求及工具批次处理完后，下一次模型请求生效；等待显示“将在下次请求使用”，待审批提案不因切换失效。切换不覆盖停止/steer/到期规则，不额外触发请求。本票需核验选择受理与派发、审批等待、配对完整、重启恢复的排序；跨协议历史字段仍由 P2-01 协调，不视为已有兼容证据。

P2-03 后续确认删除当前个人连接/模型时，当前请求及工具批次按原规则收敛，之后暂停模型调用并提示重选，不自动替选或结束演练；不因删除本身停止测试或使待审批失效。需把配置删除与模型派发、选择切换及恢复排序纳入失败场景，避免缓存已删除配置继续调用。
