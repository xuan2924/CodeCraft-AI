## What to build

建立可重复、显式触发的浏览器—真实 DeepSeek 非思考模式—Java—PostgreSQL—Go—Docker 验收，证明读取、审批修改、测试与模型回复是一条真实业务链路。

## 开工门槛

第一阶段全部验收；P2-09/10 的正式接口及自身验收完成；依赖中的真实配置、费用提示与验证限额已确定。不能用综合票替代前置票首次联调。

## Acceptance criteria

- [ ] 用受邀用户个人配置进入阶段性入口，准备真实工作区和模型检查，显示题目与计时，不展示不存在的面试官或报告。
- [ ] 从页面提交需求，真实模型读取代码、产生提案，用户查看 Diff 并批准；正式版本准确推进，记录调用/提案/回执关联。
- [ ] 在该已保存版本运行真实 Docker 测试，模型收到结构化结果并继续或回复；日志/版本与页面显示一致，不以聊天文字判定测试通过。
- [ ] 至少覆盖拒绝后继续、基线冲突、断线恢复观察和停止所属测试等已实现路径，确定性故障与真实调用分别报告。
- [ ] 联调凭证可读取环境变量 DEEPSEEK，输出与报告只含脱敏配置/模型身份；不保存秘密、不默认启动收费回归。
- [ ] 提供实际运行入口、前置条件和可重复测试方式；缺少真实模型或 Docker 时标未验证，不宣称闭环通过。
- [ ] 缺陷回到所属功能修复并补回归；验证报告区分单元/边界、真实供应商、Docker、浏览器结果。
