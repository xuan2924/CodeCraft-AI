# P2-04：上下文与 AI 数据容量契约

**Type:** decision
**Status:** ready-for-agent
**Blocked by:** None
**Spec:** [第二阶段规格](../spec.md)

## What to build

将上下文压缩与持久化数据保留分开设计，确定从首次模型调用即生效的输出上限、单场计量、存储预留和证据引用契约。

## 决策边界

读 [Loop](../../../docs/design/copilot-loop.md)、[模型接入](../../../docs/design/model-access.md)、[工作区容量](../../../docs/design/workspace-execution.md#保留与删除)及 [第一阶段 #16](../../workspace-test-foundation/issues/16-deletion-retention.md)。与 P2-01/02 协调供应商配对和检查点，不将其未知接口当事实。

## Acceptance criteria

- [ ] 区分对话、模型协议消息、工具结果、提案/Diff、审批、Skill 快照与流事件的所有者、引用、计量及去重，不要求重复存相同内容。
- [ ] 落实全部演练 AI 数据计入既有 512 MiB，个人连接/Skill 原件独立；定义物理复用的引用计量，不漏算保留内容。
- [ ] 定义模型/摘要/工具调用前的空间预留、输出截断和容量不足处理；保护停止、回执对账、结束、最终验收及删除能力，不能执行后才发现无空间记录。
- [ ] 确定窗口估算、输出预留、自动阈值、手动压缩安全点、摘要模板和失败重试参数，保留目标、用户决策、未完成配对及证据引用。
- [ ] 定义最近原文/历史摘要/按需证据的组装与恢复；压缩不删原始记录、不改业务状态，不能用摘要替代审批或测试真相。
- [ ] 将 AI 记录随演练结束后 30 天保留及删除、未决记录保护、快照引用回收落实为契约；不重新引入全局预算/磁盘水位/备份。
- [ ] 列出满额、磁盘不足、并发预留、长输出、摘要失败、超窗口和删除竞态的测试门槛；待决数值先确认再更新专题。

## Comments

512 MiB 是存储预算，不是 Token/轮次预算。原始证据保留不等于全量 SSE/逐 Token 回放；正式计量与故障行为必须实测。
