# P2-09：修改提案、Diff 与审批

**Type:** implementation
**Status:** needs-info
**Blocked by:** P2-08 只读 Copilot 任务
**Spec:** [第二阶段规格](../spec.md)

## What to build

在同一 Loop 中接入修改提案，交付默认逐次审批的整批 Diff、批准/拒绝、原子应用与结果回填。AI 文件创建/修改/删除/重命名复用第一阶段写入通道。

## 开工门槛

第一阶段达到 Dev Done（功能、L1 与代码审查完成，不含远程 CI 或重型验证），P2-08 及其上游提案 schema、检查点、审批排序与授权契约完成。读 [审批](../../../docs/design/approval.md)、[工作区](../../../docs/design/workspace-execution.md)、[Web IDE](../../../docs/design/web-ide.md)。

## Acceptance criteria

- [ ] 提案固定工作区基线和完整变更，展示整批 Diff，默认 ask for approve；等待时保留批次位置及已完成结果，后续工具不执行。
- [ ] 批准重新检查身份、归属、操作权、任务/演练状态、路径、容量、提案和基线；重复批准不重复应用。
- [ ] 多文件整批成功或失败；基线变化使旧提案失效，不自动合并，不让旧批准授权新内容。
- [ ] 拒绝可附理由，回填明确工具结果后继续当前任务，不自动终止整轮，也不允许无进展地反复提交相同被拒方案。
- [ ] 应用与底座修订/回执同源，未知写入先对账；进程重启能恢复待审批及已应用结果，不重新生成或重放副作用。
- [ ] AI 应用不覆盖本地草稿，明确提示协调；整批 Diff、结果及审计持久化并计入容量。
- [ ] 确定性测试覆盖跨用户、旧页面、重复批准、拒绝后继续、基线冲突、批准/停止/到期竞争与写入丢响应；真实模型至少完成一个审批修改流程。
