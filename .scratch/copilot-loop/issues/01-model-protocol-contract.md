# P2-01：模型 SDK 与协议兼容性

**Type:** decision
**Status:** needs-triage
**Blocked by:** None
**Spec:** [第二阶段规格](../spec.md)

## What to build

核实正式 LangChain4j 依赖及三协议能力，先为真实 DeepSeek 非思考闭环提供可用结论，再完成思考模式、四家预设和自定义服务的验证矩阵。沿用应用自管 Loop，不重新选型、不把 PoC 版本当正式锁定。

## 决策边界

读 [模型接入](../../../docs/design/model-access.md)、[Copilot Loop](../../../docs/design/copilot-loop.md)及关联 ADR；使用 API 前核对最新官方说明和实际依赖。可提前核验，不声称第一阶段业务底座已交付。

## Acceptance criteria

- [ ] 清点实际依赖及 SDK 接口，说明正式模块/版本建议和新增依赖理由；区分已核实、待验证与不支持。
- [ ] 为 Chat Completions、Responses、Anthropic Messages 核实流式文本/工具参数、调用 ID、推理字段回传、usage、超时取消和 SDK 隐式重试。
- [ ] 记录 DeepSeek 非思考模式的最小多轮工具闭环方案；思考模式明确必需字段及停止/steer/压缩后的配对限制，不能静默切换模式；按 ADR 0005 核实用户显式变更协议/模型/思考模式时的历史消息兼容边界，不假定任意配置能无损接续。
- [ ] 建立供应商×协议×模式的真实验证清单，不承诺所有组合都支持；确定模型 ID/窗口来源，不复制陈旧示例当现行事实。
- [ ] 仅具体疑问未解决时做最小实验，先说明问题与通过条件，得结论即停止；真实调用显式触发并有费用提示/限制。
- [ ] 可使用环境变量 DEEPSEEK 的联调 Key，但不输出值、不提交秘密、不隐式作为产品回退；凭证缺失或无效明确未验证。
- [ ] 发布可引用的 DeepSeek 子结论及剩余门槛，SDK 缺口或技术路线变更先请用户确认，再同步模型接入设计。研究结果不代替 P2-19/20 的正式业务兼容验收。

## Comments

用户确认三协议属于第二阶段终验目标；先打通 DeepSeek 非思考模式，再验证思考模式。此票交付契约与核验记录，不初始化无业务用途的框架。
