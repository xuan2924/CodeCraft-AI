# P2-07：演练绑定模型与准备检查

**Type:** implementation
**Status:** needs-info
**Blocked by:** P2-06 个人模型连接设置
**Spec:** [第二阶段规格](../spec.md)

## What to build

从用户个人中心保存的多个模型连接中选择模型进入演练，真实检查通过后才可开始计时；演练中的 Copilot 提供显式模型切换入口，不要求通过覆写个人连接换模型。页面明确是第二阶段工程练习入口，不冒充完整面试。

## 开工门槛

第一阶段达到 Dev Done（功能、L1 与代码审查完成，不含远程 CI 或重型验证），P2-06 完成且其上游检查时效、失败释放/恢复及 Key 更新契约已确认。读 [模型接入](../../../docs/design/model-access.md)、[Web IDE](../../../docs/design/web-ide.md)。

## Acceptance criteria

- [ ] 准备工作区/执行环境与基础/工具检查，均真实通过后才允许开始计时，失败原因与重试/退出路径明确。
- [ ] 演练内可显式选择、切换本人连接下的具体模型，支持同连接内换模型及跨连接换模型；同名模型按连接区分，切换不覆写原连接。每请求固定完整配置并保留非秘密身份，运行中可选择新模型，当前请求及工具批次处理完后下一次模型请求生效，待审批不因切换失效，等待时展示“将在下次请求使用”；跨协议历史兼容按前置确认契约处理。
- [ ] Key 保存即替换，不要求先验证；在途请求保持原配置，不自动重放失败请求，无效新配置不回退旧配置或其他连接。
- [ ] 准备开始计时时检查所选配置版本两项结果有效；修改后旧检查失效，迟到旧结果不能覆盖新版本。演练内切换已保存模型不额外测试、不要求有效检查结果；后续业务请求直接使用所选模型，失败明确报错且不自动回退。
- [ ] Key 更新不改变代码、对话、审批或倒计时；Key 失效不阻止手动编辑/测试和结束。
- [ ] 删除当前连接/模型后，当前请求及工具批次按原规则收敛，之后暂停模型调用并提示重选；不自动替选、不结束演练、不因删除使待审批失效，手动编辑/测试及倒计时继续。删除非当前项不影响当前演练。
- [ ] 准备失败不突破一场活动演练限制，也不永久卡住名额；重复操作与配置更新竞争有确定结果。
- [ ] 页面明确无面试官、挑战或 AI 报告，不能将模型准备通过当作完整面试能力上线。
- [ ] 覆盖真实连接、故障替身、准备重试、配置/Key 更新与在途请求/检查的竞争及无效新 Key 不回退的 REST/浏览器测试，秘密不落日志。

## Comments

未接入的第三阶段能力不伪造成功；个人连接保存成功不等于真实检查通过。

P2-03 曾将方案 B 解读为“演练自动跟随个人配置修改”，用户后续澄清要的是“个人中心配置多个 Key，演练中从个人模型配置显式切换模型”。本票已纠正该解读，见 [ADR 0005](../../../docs/adr/0005-live-model-connection-updates.md)。Key 保存无需真实检查的确认保留；用户进一步确认一连接共用地址/协议/Key、其下配置多个模型，演练选择具体模型。用户已进一步确认演练内切换不额外测试、不要求有效检查，开始计时前检查仍保留。切换生效时机后续已确认：当前请求及工具批次完成后下一次请求使用新模型，待审批保留，等待时明确展示。用户随后确认删除当前配置时当前请求和批次收敛后暂停模型调用、提示重选，不结束演练；删除非当前项不影响演练。跨协议兼容及编辑在用连接/模型的生效规则仍待前置决定收敛。
