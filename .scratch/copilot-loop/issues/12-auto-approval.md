# P2-12：自动审批模式

**Type:** implementation
**Status:** needs-info
**Blocked by:** P2-09 修改提案、Diff 与审批
**Spec:** [第二阶段规格](../spec.md)

## What to build

交付用户切换 auto 与 ask for approve。auto 仅免除逐次修改批准，沿用同一提案、授权、原子写入和审计链路，不授予额外权限。

## 开工门槛

第一阶段达到 Dev Done（功能、L1 与代码审查完成，不含远程 CI 或重型验证）；P2-09 及上游模式登记/切换排序契约完成。读 [审批设计](../../../docs/design/approval.md)。

## Acceptance criteria

- [x] 默认 ask for approve，只有用户可切换模式，记录审计；前端收到服务端切换成功后才展示生效。
- [x] 提案使用登记时模式；模型生成中但未登记的提案采用登记时最新值，切到 auto 不批准已登记待审批提案。
- [x] auto 仍校验身份/授权、状态、基线、路径与容量，多文件原子应用；无任意 shell/联网/跨演练/权威文件修改等新增权限。
- [x] 自动应用展示标识、Diff、结果和失败原因；冲突使旧提案失效，不自动合并或静默覆盖本地草稿。
- [x] 模式切换、登记、批准、停止/到期及重复请求有确定顺序；断线时 auto 可继续，停止不撤销已生效修改。
- [x] REST/组件/浏览器测试覆盖默认、切换竞争、旧提案、越权、冲突、重启与审计，不创建第二套写入通道。

## Comments

用户已明确确认 auto 定义与权限表；模型本身无权开启 auto。读/搜索/受控测试在两种模式都不要求逐次批准。

### 实施决定

- 模式属于演练，缺省 ASK / 版本 0；切换使用期望版本与幂等键，每次成功确认记录独立审计（含同值确认），与提案登记共用已有资源所有者锁确定先后。界面在 ACTIVE 阶段持操作权时切换，等待服务端结果，不把本地选择当成生效状态；切换不重新授权暂停/失效任务。
- 提案持久化登记模式及模式版本。AUTO 的自动准入也使用同一 FILE_BATCH 通道，不保存或伪造浏览器 credential；仅以当前有效父任务授权、已登记 AUTO 证据、OPEN gate、生命周期、基线及统一容量准入创建原写入意图。旧 ASK 提案不因后来 AUTO 自动批准，已登记 AUTO 也不随切回 ASK 改写历史授权。
- 登记后释放 worker，自动准入/容量测量由有界 Copilot worker 执行；成功的自动决定、FILE_BATCH 绑定和 WAITING_WRITE 同事务落盘，恢复只核对原身份。确定的准入失败仍保留 Diff 与失败结果，未知数据库/写入结果不改判为失败。模式审计纳入统一计量和演练删除，预算不足仍保留原有停止/结束能力。
- 用真实 Identity 事务代理补授权失效测试时发现 P2-10 的测试恢复曾捕获跨 REQUIRED 代理的拒绝异常，父事务已被标记 rollback-only，导致取消无法落盘（确定性复现 UnexpectedRollbackException）。本票同时修复为既有 `tryAuthorizeMutation` 的非异常失效结果；AUTO 与所属测试均测试真实代理拒绝，而非仅用 mock 抛错冒充事务证据。
- 23 次模式确认测试发现 PostgreSQL `ORDER BY version` 命中了 `version::text` 的输出别名而按字典序排序；显式限定底表数字列，并修复同样影响多次提案展示的既有 sequence 排序，增加 8→12 跨位数分页回归。
