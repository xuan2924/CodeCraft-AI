# P2-12：自动审批模式

**Type:** implementation
**Status:** needs-info
**Blocked by:** P2-09 修改提案、Diff 与审批
**Spec:** [第二阶段规格](../spec.md)

## What to build

交付用户切换 auto 与 ask for approve。auto 仅免除逐次修改批准，沿用同一提案、授权、原子写入和审计链路，不授予额外权限。

## 开工门槛

第一阶段全部验收；P2-09 及上游模式登记/切换排序契约完成。读 [审批设计](../../../docs/design/approval.md)。

## Acceptance criteria

- [ ] 默认 ask for approve，只有用户可切换模式，记录审计；前端收到服务端切换成功后才展示生效。
- [ ] 提案使用登记时模式；模型生成中但未登记的提案采用登记时最新值，切到 auto 不批准已登记待审批提案。
- [ ] auto 仍校验身份/授权、状态、基线、路径与容量，多文件原子应用；无任意 shell/联网/跨演练/权威文件修改等新增权限。
- [ ] 自动应用展示标识、Diff、结果和失败原因；冲突使旧提案失效，不自动合并或静默覆盖本地草稿。
- [ ] 模式切换、登记、批准、停止/到期及重复请求有确定顺序；断线时 auto 可继续，停止不撤销已生效修改。
- [ ] REST/组件/浏览器测试覆盖默认、切换竞争、旧提案、越权、冲突、重启与审计，不创建第二套写入通道。

## Comments

用户已明确确认 auto 定义与权限表；模型本身无权开启 auto。读/搜索/受控测试在两种模式都不要求逐次批准。
