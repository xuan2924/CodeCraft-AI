# P2-15：自动与手动上下文压缩

**Type:** implementation
**Status:** needs-info
**Blocked by:** P2-04 上下文与 AI 数据容量契约；P2-09 修改提案、Diff 与审批；P2-10 Copilot 受控测试工具
**Spec:** [第二阶段规格](../spec.md)

## What to build

交付自动压缩和立即压缩入口，用近期原文、历史摘要和按需证据维持长任务上下文；压缩不删除持久化原始记录。

## 开工门槛

第一阶段全部验收；P2-04 阈值、估算、摘要模板、安全点和失败处理确认，前置消息/工具持久化完成。读 [Loop 压缩](../../../docs/design/copilot-loop.md#上下文压缩)。

## Acceptance criteria

- [ ] 每次请求前估算窗口并预留输出，先控制可重读的冗长结果，再按确认策略压缩；不把估算显示成供应商实测。
- [ ] 手动请求显示安全点等待，在当前请求结束且调用结果配对完整时执行，未完成调用不拆散。
- [ ] 摘要保留任务目标、用户决策、关键修改、审批/工具状态与证据引用；不改变业务真相或依赖摘要恢复未知副作用。
- [ ] 原始对话/协议消息/工具证据仍按演练保留，压缩只改变后续输入；摘要本身计入单场存储和用户模型用量。
- [ ] 压缩失败有限重试，保留旧上下文；仍安全则提示继续，否则暂停可重试，不静默丢信息或结束演练。
- [ ] 并发 steer/停止/结束、服务重启和容量不足不重复发布摘要或破坏调用配对；模型请求前为摘要返回预留空间。
- [ ] 确定性测试覆盖超窗口、长输出、审批状态、失败恢复及手动/自动竞争；真实首条模型验证压缩后的工具继续调用。

## Comments

不以压缩规避 512 MiB 总存储预算；不新增固定任务总 Token/轮次截止。思考字段兼容在 P2-19/20 完成真实验证。
