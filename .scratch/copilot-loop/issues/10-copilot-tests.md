# P2-10：Copilot 受控测试工具

**Type:** implementation
**Status:** needs-info
**Blocked by:** P2-08 只读 Copilot 任务

## What to build

将模型测试请求连接到第一阶段稳定副本与真实 Docker 执行，建立父 Copilot 任务和所属测试的持久关联，并向模型回填确定结果。

## 开工门槛

第一阶段达到 Dev Done（功能、L1 与代码审查完成，不含远程 CI 或重型验证）；P2-08 和其上游任务/工具契约完成，测试归属及停止排序已明确。读 [工作区执行](../../../docs/design/workspace-execution.md)、[Loop](../../../docs/design/copilot-loop.md)。

## Acceptance criteria

- [x] 只接受题目允许目标，不接受任意命令；从确定已保存版本复制稳定输入，结果和日志关联版本，测试不回写源代码。
- [x] 测试工具等待确定结果后回填模型，期间不执行下一工具；用户仍可编辑和保存，不能把新版本显示为已通过旧测试。
- [x] 与手动测试共享单演练执行名额，忙时明确返回结构化结果，不排队、不抢占、不高频自动重试或借用其他版本结果。
- [x] 持久化父子归属；停止 Copilot 联动停止其运行中测试，执行状态收敛后父任务才显示已停止，不停止用户独立测试。
- [x] 断线、Java/Go 重启及结果丢响应先查询原任务，不重启测试；未知执行保持隔离，停止 RPC 返回不等于进程已退出。
- [x] 测试失败是正常结果，不是工具故障；通过/失败/超时/环境错误/中断区分，日志有界且截断可见。
- [x] 自动测试覆盖归属、槽位竞争、停止/自然完成、重复请求及恢复；真实 Docker 验证输入版本、停止进程和资源清理，真实模型能使用回执继续回复。

## Comments

依赖 P2-08 而非 P2-09，可与修改审批并行实施；两者在 P2-11 汇成首条完整链路。这里的测试任务不占第二个 Copilot 任务名额。

### 授权下的实施取舍

- 工具采用 `run_tests(expected_revision, target)`，当前只允许题目已发布的 `base` 目标，严格拒绝额外字段和任意命令。复用 TestTaskStore/Coordinator、稳定副本、原执行槽位和系统停止回执，不另造 Docker 调度或测试重试器。
- AI 测试准入来自已受理父任务与当前有效登录授权，不要求持有旧浏览器页面凭证；仍在用户锁内检查父任务/工具位置、演练状态、当前开放的授权世代、修订、题目可执行性、槽位和容量。普通浏览器测试接口继续要求页面操作凭证。此差异避免把合法后台执行误绑定到浏览器是否在线，同时不允许已撤销会话派发新测试。
- 父子关联、测试准入与 WAITING_TEST 检查点同事务落盘，等待释放 Copilot worker。停止只对关联子测试登记系统停止；原测试协调器负责 RPC/查询，只有明确终态且 quiescent 才回填并结束父任务，RPC 已接受不代表进程已退出。
- 同一任务、同一已生效用户目标、同一保存修订和 target 的已确定测试结果可显式标记 reused 返回，不自动启动第二次相同执行；新的用户目标或新修订允许新测试。相比让不同执行 ID 掩盖重复无进展，此方案防止模型高频重复测试，也不冒充新执行或复用其他版本结果。槽位忙仅返回结构化结果，不挂队列或后台轮询准入。
- 模型回执仅带最多 16 KiB、最多 64 段日志尾部，显式区分底座日志丢弃/不完整与工具投影截断，并保留原测试 ID、修订、状态与证据引用。完整日志仍走原测试页面；结果落入原工具消息前保护对应测试历史，之后沿用底座保留策略。

### 交付与审查结论

- V31 持久化父工具与原测试绑定，扩展活动任务/工具状态及保留计量；测试结果与原工具消息在同一事务确认。完整测试证据在授权事务内只取回原文，事务外解码、裁剪与编码，提交前以轻量版本检查防止过时证据回填。停止先于 dispatch 时不再调用 Start；恢复使用原执行身份与既有查询/隔离机制。
- 页面新增 WAITING_TEST、最近 20 条关联测试及原记录/日志入口，明确原修订与当前草稿/后续保存的区别；只轮询元数据，终态停止轮询，迟到旧账号响应不展示。父任务结果收敛后才解除活动状态，不影响普通保存。
- 真实验证发现既有 Go `StopSystemTask` 只接受 CLOSED/FROZEN，导致 OPEN 工作区的减权限取消一直被拒绝并最终超时。增加先红后绿的 Linux RPC 回归后，修正为已初始化工作区的精确任务取消，仍保留内部鉴权、完整执行身份及迟到 Start 墓碑。相比为取消关闭整个工作区或新增同义 RPC，该修正不撤销无关编辑权限、不引入重复协议，也修复相同底座上的本人恢复停止。
- 持久化夹具改为每次独立随机数据库，退出删除自身数据库，不清理其他测试/开发数据。真实验收复用现有 Linux tracer，新增明确收费的 `--workspace --boundary-only --copilot-tests`；凭证只以环境传入可信测试 JVM，不进入 Go、题目容器或测试环境文件；临时连接 finally 删除，包装密钥仅内存生成。
- 自审覆盖验收、模块依赖、事务/RPC/编解码边界、原身份恢复、停止排序、保留竞态及账号隔离；没有已知票内功能缺口。仍不据此宣称 P2-11 完整读取→修改→测试链路或 P2-14 综合故障验收完成。

### 实际验证

- `CopilotPersistenceIT`：29 个普通 PostgreSQL 场景通过，2 个既有独立收费场景默认跳过；新增测试覆盖丢 Start 响应不重放、整批等待/复用、原测试停止、取消接受不等于 quiescent、证据版本变化、手动槽位不收养/不误停、授权撤销、到期不唤醒模型及回填前保留保护。Go 为确定性替身，不把这些场景写成真实进程重启证据。
- 严格参数、UTF-8/段数裁剪、MVC 归属/no-store、保留贡献及前端 API/等待/原记录入口/跨账号迟到响应均有定向测试。quick 通过：Java 256、Vue 155 项，以及 Node 契约、类型检查、Java/前端 lint、Go quick/vet 与 Linux 编译/vet；热缓存本次约 36 秒（60 秒硬限内）。前端生产构建通过。随后新增的原测试入口回归所在 `WorkspaceTests.test.ts` 12 项及类型检查通过，未无故重复整套 quick。
- Linux RPC 定向回归通过：内部鉴权、OPEN 取消保持编辑世代、原 ID 迟到 Start 被拒绝、其他身份不能借用取消回执及既有冻结最终验收行为。
- 最终真实 tracer 整体通过，日志 `.runtime/cc-tracer-47376-31f06876/`：真实 DeepSeek 非思考检查 3 次、测试工具后续答 2 次、第二次测试派发 1 次，共 **6 次真实调用**。真实 Docker 使用修订 1 的稳定输入，期间保存为修订 2；日志只含旧输入标记，FAILED 及 Surefire 证据回填后模型明确续答 FAILED。第二测试在 RUNNING 后停止父任务，最终测试 STOPPED、quiescent、容器/副本清理成功，源代码未被测试改写；独立检查没有遗留执行容器，测试库/卷已清理。
