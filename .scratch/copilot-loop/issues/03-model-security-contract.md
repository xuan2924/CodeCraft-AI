# P2-03：模型连接安全与准备规则

**Type:** decision
**Status:** ready-for-agent
**Blocked by:** None
**Spec:** [第二阶段规格](../spec.md)

## What to build

确定个人模型连接的凭证保护、地址安全、测试及演练准备契约，为连接设置与 Key 替换提供可检验方案。

## 决策边界

以 [模型接入](../../../docs/design/model-access.md)和 [架构](../../../docs/design/architecture.md)为准；SDK 具体传输能力与 P2-01 协调，不凭空宣称可控制 DNS/重定向。

## Acceptance criteria

- [ ] 确定凭证加密、部署注入解密密钥、轮换及脱敏边界；数据库、响应、日志、上下文、Go 和测试报告均不得泄漏明文。
- [ ] 明确公网 HTTPS、实际解析目标、每次重定向和 DNS 重绑定防护的实现契约；本地例外只由部署配置开启，不由用户输入绕过。
- [ ] 明确基础检查与无副作用工具闭环的独立结果、费用提示、测试限额、超时/错误分类，不以 HTTP 200 作为工具兼容证明。
- [ ] 确定检查有效期、配置/Key 改变后的失效规则、准备失败重试或退出路径，复用一场活动演练限制，不让名额永久卡死。
- [ ] 定义演练固定连接身份、Key 验证成功后仅作用后续请求、失败保留旧值、在途请求与更新竞争、不自动重发收费请求。
- [ ] 明确缺失配置不回退平台或测试环境凭证，删除演练不删除个人连接；个人配置的管理边界不授权管理员浏览用户私有内容。
- [ ] 列出恶意 URL、重定向、解析变化、凭证失败与错误脱敏的测试方案；需用户选择的时效/限制先确认后更新设计。

## Comments

安全、测试有效期和准备失败处理是开工门槛，不因用户提供 DeepSeek 联调 Key 而省略。
