# 02: 图片验证码与受邀登录

Status: ready-for-agent
Blocked by: 01
Spec: [统一规格](../spec.md)

## 目标

按双栏参考布局重构受邀账号密码登录，接入真正的服务端图片验证码；不增加邮箱验证码或找回密码。

## 验收要求

- [x] 复用现有账号密码与 Cookie 身份协议，图片验证码为登录前置校验，不把客户端布尔值当验证结果。
- [x] 服务端生成挑战、有效期、一次性消费、刷新失效与失败限制按确认规则落地，答案不下发至可读取字段/日志。
- [x] 限流与并发重放覆盖服务端边界，不泄露账号存在性；验证码错误不得绕过原密码尝试限制。
- [x] 登录显示提交中、错误、过期及刷新状态，防重复操作；验证码迟到响应不覆盖新挑战。
- [x] 仅做图片验证码，不做语音验证码；验证码刷新与输入可键盘操作，alt 文本不泄露答案。
- [x] 正常、错误、过期、重复消费、刷新、限流及会话隔离有可控测试；完成受影响 L1 与最小布局/键盘检查。

## Comments

当前未授权编码。00 已确认图片验证码规则；用户后续明确不做语音验证码，仅保留图片验证码，不是邮箱登录。信息阻塞解除。

### 实施决定与交付

用户已授权全目录编码，覆盖上面的历史限制。本票 L1 完成；后续票继续执行。

- 复用统一数据库限流与 CSRF 上下文，以 HMAC 绑定验证码；V49 增加有界持久化表。POST 发放每分钟上下文/来源各五次，两个渲染槽；挑战两分钟有效，刷新原子替换，DELETE RETURNING 独立事务消费，失败不会回滚使挑战复活。所有密码登录先扣原有额度再校验验证码。
- 已声明依赖没有验证码图片生成能力，采用成熟 EasyCaptcha 1.6.2（官方仓库 ele-admin/EasyCaptcha；SecureRandom、PNG/内置字体），不自研图像干扰算法。生产没有固定答案/关闭验证码开关，摘要不使用低熵明文 SHA；响应只有图片、随机 id、到期时间。
- 登录采用双栏暗色布局，CaptchaField 封装临时挑战/答案、刷新、防重、过期与卸载取消；真实服务烟测发现改密期间挂载导致挑战未加载，增加先失败测试再修复 disabled→enabled 接线。迟到响应不会写回卸载组件。
- 更新 HTTP 契约、既有身份测试和测试专属夹具。浏览器自动化只在一次性 tracer 数据库里经认证控制面设置指定挑战摘要，仍走生产验证码消费/登录；PNG 渲染单测单独验证真实生成器，不把夹具答案当生产能力。
