# 首期信任共享系统时钟，不建设专门的时钟异常保护

用户在了解同域部署、时钟跳变和单调计时的取舍后确认：保留 ADR 0002 的 Java/Go 同一 Linux VM/宿主时钟域，首期信任该系统 UTC 时间，不新增时钟异常检测、异常准入锁定或人工恢复机制，也不为此引入单调计时授权/倒计时改造。用户认为此风险出现概率低、专项防护价值不足，接受系统时间调整可能造成的截止判断偏差；目前实测发现的是 Windows/VM 双端时间偏差，没有证据表明同域 Linux 测试曾因时间跳变失败。

此决定替代原“监控时钟跳变，回退或无法确认时关闭写入准入”的首期要求及 ADR 0002 中对应的待实施项，不再以该专项保护阻塞 #10–#16 验收。

## 边界与代价

- 用户以约 1 分钟偏差说明可接受风险，不将其写成系统保证的最大偏差，也不新增 1 分钟授权宽限。系统时间可能出现更大调整；本方案不保证调整后的真实剩余时长准确。
- 保留固定、持久化的截止时间及 `now >= notAfter` 拒绝规则；不因重启、重试或后续续期重写已有请求的截止时间。运行和重启恢复均以共享系统时间为依据，接受回拨可能延后、前跳可能提前截止的剩余风险。
- 同一时钟域避免依赖 Windows/Linux 两套时钟一致，但不保证整个请求期间系统时间不变，也不保证跨时刻检查永不出现分歧。
- 不关闭或修改 Windows/WSL/Linux 自动校时；不删除已有 RPC 超时、单调耗时计算、资源限额、栅栏或故障恢复机制。正常时间前提下的过期拒绝、临界竞争与重启恢复仍须测试。
- 这是一项明确的风险接受，不是时钟异常已修复或专项防护已通过验证。跨宿主部署、扩大试用范围或出现实际时钟跳变故障时重新评估。

有效协议见 [任务与恢复](../design/task-event-recovery.md)，实施证据见 [#10–#12 验证](../validation/workspace-write-browser-10-12.md)。
