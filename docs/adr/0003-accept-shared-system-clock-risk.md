# ADR-0003：首期信任共享系统时钟，不建设专项时钟跳变保护

## 背景

即便 Java 与 Go 处于同一 Linux 时钟域（[ADR-0002](0002-java-go-shared-linux-clock.md)），宿主机 NTP 校时仍可能造成系统墙钟小幅前跳或回拨。早期方案曾要求建设“系统时钟异常检测 + 准入锁定 + 单调时钟授权改造”。

## 备选方案

- **建设单调时钟授权与跳变锁定机制**：所有持久化截止时间需配合启动单调偏移与跨重启校正状态，实现复杂度高且收益极低。
- **首期信任同域系统 UTC 时钟**：保留固定持久化 `deadlineAt` 与 `now >= notAfter` 拒绝逻辑，接受极低概率的校时偏差风险。

## 决策与代价

选择 **信任同域系统时间，不建设专项时钟跳变保护**（单次执行耗时统计仍使用单调计时）。

- **收益**：大幅简化跨重启的截止时间与暂停剩余时长持久化逻辑。
- **代价**：若系统发生大幅校时，演练截止时刻或授权到期可能出现对应偏移；未来若扩展为跨宿主多节点集群部署，需要重新评估时钟协议。
