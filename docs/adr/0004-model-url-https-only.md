# 首期模型地址仅校验 HTTPS，不限制内网目标

在 P2-03 讨论中，用户希望按其提供的 Base URL 和凭证直接调用，由用户处理配置错误，不为地址目标检查引入额外复杂度。在明确区分“只校验 HTTPS”（A）与“只允许公网 HTTPS”（B）后，用户选择 A，替代此前公网目标限制。有效契约见 [模型接入](../design/model-access.md#自定义地址安全)。

## 取舍与边界

- 校验合法 HTTPS URL，不做内网 IP、DNS 解析结果、实际连接目标检查或 DNS 重绑定防护；不新增 HTTP 本地例外，不关闭正常 TLS 证书校验。
- HTTPS 只提供传输保护，不构成网络隔离。Java 仍可能被引导请求其可达的内部 HTTP 服务，因此保留 SSRF 风险；不能宣称本方案阻止访问内网，也不能将此风险完全归为用户配置错误。
- 此决定不取消凭证加密、脱敏、用户隔离、检查限额及失败不隐式回退等规则。本决定当时未决定重定向/凭证转发；后续 P2-03 已落实 Redirect.NEVER，任何 3xx 明确失败、不自动携凭证跟随，见模型接入设计。这个补充不恢复公网目标限制，也不消除 SSRF 剩余风险。
- 本决定基于首期可信受邀用户范围；扩大使用范围前须重新评审。之后恢复公网目标限制可能使已可用的内网 HTTPS 连接不再可用，需显式迁移与告知，不能静默收紧。
