# Java 统一单场预算，Go 提供有序实际占用快照

单场 512 MiB 同时覆盖 Java 业务记录与 Go 文件/执行证据，不能分别各发一份额度，也不能在数据库事务中等待沙箱 RPC。选择 Java 持久化空间预留作为统一准入账本，结合 Go 持久化计量世代及递增快照序号：普通消费先预留，再与业务意图同事务绑定；未知副作用保留预留，确定收敛并取得后置占用快照后才结算。乱序快照不得降低已知账本，计量身份丢失不能被当成零占用。

不采用跨服务数据库事务、文件系统全局水位或两套独立硬配额；它们分别扩大故障耦合、改变产品政策或无法保证合计预算。采用 PostgreSQL 事务/行锁、MyBatis 与 Go 已有持久化/原子发布能力，不另造分布式事务框架。保留不承载正文的工作区/执行归属用于计量与防重放；普通额度与停止、对账、最终验收、删除所需的预留分开，预留不代表预写磁盘。

计量对象为可归属的持久化内容：Go 普通文件实际长度（包括副本、暂存、日志、证据及防重放元数据），以及 PostgreSQL 可归属业务行的存储长度。数据库/文件系统的共享页、WAL、索引页和 Docker 内存文件系统属于运行基础设施，不伪装为可逐场精确分摊的业务字节；磁盘满仍须失败安全，额度不是磁盘空间保证。实现、额度推导与验证记录留在第一阶段 #16，后续 AI 消费复用同一本账。

默认收尾保留采用 256 MiB：普通消费最多使用其余 256 MiB，三个最终尝试即使各占满 56 MiB，也仍留下至少 72 MiB 计量暂存/有界救援空间及 16 MiB 余量。不再依赖“192 MiB 足够”所隐含的前两次尝试结算后各小于 32 MiB 假设；取舍是普通消费较早背压，避免为提高普通可用额度提前擦除最终证据或放任无界救援元数据。
