# 个人中心管理多个模型连接，演练内显式切换模型

用户澄清其需求：在个人中心配置多个 Key，例如 Kimi、DeepSeek、OpenAI，演练中的 Coding Agent 支持从这些个人配置中选择、切换模型。此前将用户选择的 B 解读为“编辑个人连接后，演练自动跟随配置变化”有偏差，该解读撤回；本 ADR 保留编号和路径并纠正结论。有效行为见 [模型接入](../design/model-access.md#多连接管理与演练内模型切换p2-03-已澄清)。

## 取舍与边界

- 个人配置管理与演练模型选择分离；切换是选择另一个已保存配置/模型，不是覆写同一条连接来换供应商，也不是平台自动选模或失败回退。
- 用户进一步确认一条连接下可配置多个模型 ID，共用一次填写的地址、协议和 Key；演练选择具体“连接 + 模型配置”。不为每个模型重复保存一份凭证，同 Key 下不同模型的检查结果不能互相代替。
- 已发出的请求保持原配置，切换用于后续请求；不自动重发失败请求，不重置代码、对话、审批或倒计时。历史按实际请求记录非秘密配置身份，不保留旧 Key，不随当前模型选择重标用量。
- 用户明确要求 Key 可直接保存替换，不以检查通过为前提；保存成功不等于连接可用。开始演练前检查的既有约定保持；用户另行确认演练中切换模型不额外测试，也不要求已有有效检查结果，后续业务请求直接使用所选模型，失败由用户修正或切换，不自动回退。
- 用户确认运行中可选择新模型；当前模型请求及其工具批次处理完后，下一次模型请求生效。切换不使待审批提案失效，等待时显示“将在下次请求使用”；不要求等整个 Copilot 任务结束，也不因切换自动另起任务。停止、steer、基线变化和到期规则保持。
- 用户确认可删除连接或单个模型：删除非当前项不影响演练；删除当前所选项时当前请求及工具批次按原规则收敛，之后暂停模型调用、提示重选，不自动替选或结束演练。手动编辑、测试及倒计时继续，删除本身不等于停止 Copilot。
- 此处原先留下的编辑生效与不兼容历史边界已由 [ADR 0008](0008-model-revisions-and-history-boundaries.md) 补齐：当前批次收敛后暂停新调用，等待显式应用修订；旧完整批次按兼容域转换并保留原证据。P2-07/08/15/19/20 已记录实现验证，不再是待决项；仍不能从“支持切换模型”推导个人中心编辑自动作用于当前演练。
- 平台面试官/评测官固定模型与规则版本、任务 Skill 快照不受此决定影响。不再将 Copilot 整场固定单一模型作为既定产品限制。
