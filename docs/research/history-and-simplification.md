### 不采纳的“简化”及原因

- 不按“约 36 行/文件”批量合并 Java 类，也不把 DTO 改成嵌套 record：行数不能证明抽象无价值，且嵌套 DTO 与当前后端规范不符。需要修改规范的方案应另行确认。
- 不把 30 个 RPC 强行拆成多个 Proto Service，也不把 Go `enter` 的鉴权与生命周期锁简单搬到拦截器。当前锁还承担操作串行/存储所有者保护；这不是删除重复函数调用即可等价替换。
- 不把 25 个调度方法直接扩成并行线程池。共享默认调度器确有阻塞风险，但调度发现与 worker 不同，改变并行度属于运行时行为变化，缺乏当前故障证据时不借清理扩大整改。
- 不机械统一所有前端 4xx 为“确定未执行”。结果未知的原命令、鉴权错误及已提交回执需要不同处理；`useCommand` 已统一原键恢复，错误文案清单不等于重试协议。
- 不为减少文件数合并不同领域 API；不为一个 5 行整数解析器再建通用工具框架。
- 不把 `ProblemPublicationReader` 的固定编辑目录改为任意目录策略。当前 Node 发布契约明确只支持两个 Java 源码目录；Jackson 解析后 `toString()` 不受 JSON 原文空格或对象字段顺序影响，原报告将其描述成“空格变化即失败”不成立。数组顺序可更明确，但不构成当前功能缺陷。
- 大型 `CopilotPersistenceIT` 和部分页面仍有进一步拆分空间；本次优先移除仅为测试保留的生产入口，未进行跨千行夹具的机械拆分。不是恢复/审批等功能缺口，也不自动新增 QA 欠账。

## 4. 接手认知成本评估

没有新人实测样本，不把“1.5 天/两周”写成定量事实。成本分三个层次：

1. **跑起来/改页面：中等。** Docker、生成代码、发布题包和平台/个人模型前置容易混淆。过去 README 大量历史验收命令掩盖正常路径，且默认发布无执行配置旧题包；本次统一入口与默认包。
2. **修改局部业务：中高。** 同一个概念的名称、会话/演练作用域、事务代理及夹具选择影响理解。本次删除旧 accept/query 路径、统一控件命名和会话容器、提取计时，减少“新旧两条路哪条正式”的判断。
3. **改跨进程状态机：高且部分必要。** 成本来自未知副作用、撤销、配额及恢复，不应该靠隐藏或删除不变量降低。导航提供栅栏速查与调用链，开发者可以从当前入口跟到提交点，不必考古每张票。

仍保留的复杂部分应按具体改动逐次深化；“文件更少”不是验收指标。本次降低的是重复接口、失效选择、误导文档和无意义命名，不承诺消除领域固有复杂度。

## 6. 流程优化方案——待用户确认，未实施

本次没有修改 AGENTS、分诊标签、CI 门禁或创建 Skill。建议只保留三项，复用已有风险优先与集中收口约定：

1. **票内写 3～5 行“本次会触及的旧契约”。** 新工具/身份/引用变更列出入口、装配、持久读取/清理的实际消费者，选最可能遗漏的一条组合回归；不新建模板大全。针对 Bash 上限、大 Skill、模型删除和本次平台迁移。成本：少量追踪，收益：减少叶子正确但接线错误。
2. **测试跟随真实入口，不在生产保留夹具专用旧路。** 优先复用公开 Service/正式配置构造合法前置；只有确需代理/SQL 证据时使用最小 PG 测试。UI 入口移动同批核对路由夹具及未知意图断言。成本：维护一条代表链；收益：避免旧 start、旧 accept、错误 mapper 的重复修复。
3. **收口只维护一个当前结论，变化链验证一次。** 原票最后集中写实现、实际结果、复用证据和剩余缺口；产品边界改变时只更新受影响的现行摘要，不重写历史。沿用 Acceptance/清单判断完成，不强制新增 done 分诊标签。成本：一次收口检查；收益：减少“又验收一次”和重复考古。

暂不建议：正则检测所有事务 catch、按 `*_id` 自动推断删除责任、要求所有后端错误码都有前端文案、强制多线程调度、扫描所有旧文档“尚未实现”即失败、每票新建 Skill 或默认全套故障矩阵。这些误报和维护成本尚无收益证据。先确认上述最小流程，再决定是否有值得自动化的稳定契约。
