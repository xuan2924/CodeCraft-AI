# 风险优先的实施顺序

适用于跨进程副作用、异步授权和持久化恢复。风险优先决定代码实现顺序，不扩大验收责任；完成边界遵循根 [AGENTS.md 的验收责任](../../AGENTS.md#验收责任)。业务协议仍以 `docs/design/` 为准。

## 1. 区分功能与验证

在现有任务 Comments 或验证记录中维护简短表格，不另建一套规格：

| 功能 / 不变量 | 权威状态与提交点 | 失败或竞态 | L1 单测入口 | 待 QA 验证 |
|---|---|---|---|---|

只分析本次功能涉及的分支：

- 跨进程副作用：重复、迟到、回执丢失及未知结果的确认。
- 异步授权：派发与提交之间的撤销、过期、账号或实例切换。
- 持久化恢复：重启、证据不可读及清理失败后的状态与资源归属。

**完成条件：** 每项功能都有明确的提交点、失败行为及验证责任；待决项先确认，不把整套真实故障演练追加为开发 AC。

## 2. 先实现高风险逻辑

优先实现失败后可能破坏授权、已提交数据或恢复能力的状态转换，再扩展其余功能。用快速自动化单测覆盖核心正常与失败分支；未知结果保持未决，安全确认后才推进状态或释放资源。

缺陷测试先因目标行为失败，再修复代码；编译、环境或夹具错误不作为目标缺陷的红灯。

**完成条件：** 该切片代码及 L1 检查完成。真实跨进程效果尚未验证时标为待 QA，不用单测替身证明真实链路，也不因此扣留 Dev Done。

## 3. 开发收口

- 核对剩余项：功能未实现、已知代码缺陷和 L1 失败由 Agent 继续处理；复杂链路验证交接 QA/CI。
- 执行项目实际配置的类型/编译、Lint 与核心逻辑单测；选择快速测试入口，混合了 E2E 或压测的一键脚本不作为默认收口入口。
- 按独立功能或可验证改动原子提交。用户另行要求的审查按其约定执行。

**完成条件：** 约定功能已实现、已知代码缺陷已修复、L1 通过；报告实际执行结果和待 QA 验证项，不声明 QA 或生产可靠性已获证明。

## 4. 发现缺口时重定界

发现缺失状态、协议或迁移时，先判断它是功能缺口还是验证缺口。功能缺口映射回现有需求并修复；验证缺口记录责任层级。扩展约定范围或改变已确认路线时，先获得用户确认。

**完成条件：** 每个剩余项都有明确归属，不把“尚未完整验证”写成“功能尚未完成”，也不通过增加故障矩阵无限延长开发交付。
