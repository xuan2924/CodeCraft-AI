# 风险优先的实施顺序

适用于跨进程副作用、异步授权和持久化恢复。本文只补充风险分析与实现顺序；范围、验证节奏、审查和完成标准统一遵循根 [AGENTS.md](../../AGENTS.md#实施与验证)，业务协议以 `docs/design/` 为准。

## 1. 开工识别关键风险

对照整票范围，识别可能破坏授权、已提交数据或恢复能力的不变量，核对其权威状态、提交点与核心测试入口。已有设计和测试足够则直接复用；仅把缺口或待决决定记入现有任务。

按本票涉及的风险检查：

- 跨进程副作用：重复、迟到、回执丢失及未知结果如何确认。
- 异步授权：派发到提交之间的撤销、过期、账号或实例切换如何拒绝。
- 持久化恢复：重启和清理失败后的状态、资源归属，以及保留期限和删除条件是否已确定。

**完成条件：** 高风险不变量有明确行为与测试方式，依赖的待决项已提出；无需为每个函数或组件编写风险表，也不穷举与本票无关的故障组合。

## 2. 优先实现风险边界

先实现高风险状态转换并用定向自动化测试覆盖，再接入其余功能。未知副作用结果保持未决，安全确认后才推进状态或释放资源。实现可按内部步骤推进，验收按完整功能收口。

使用异常注入、依赖替身、可控时钟和状态转换测试覆盖正常与核心失败分支。修复缺陷时补充能复现目标行为的回归测试；测试替身不证明真实数据库、网络或进程语义，确需这些证据时选择最小边界验证。

**完成条件：** 关键状态及失败分支已有测试保障，可继续接线；此时不要求整库 quick、构建或独立审查。新增证据只针对尚未覆盖或已变化的行为。

## 3. 完整功能收口

核对入口、配置接线、授权、恢复和清理等票内逻辑已连通，按根规则集中验证与审查。发现问题先区分功能缺口、测试不足和范围外改进，再修复或记录；不从缺少真实故障演练推导功能未完成。

**完成条件：** 达到根规则的 L1，实际结果与剩余项记录在现有票据；不重复生成切片验收报告。提交粒度服务于可理解和可回退，不决定验证或审查次数。
