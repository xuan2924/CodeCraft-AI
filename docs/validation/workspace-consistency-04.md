# 任务 04：文件一致性与恢复验证

## 结论与范围

用户确认的候选方案在受控文本夹具下成立：Go 私有根目录、不可变全量文件树、同目录原子发布包含版本/回执的提交目录、每工作区串行锁。选定方案已写入 [工作区设计](../design/workspace-execution.md#文件一致性与恢复契约任务-04)。

这是决定票的可执行证据，不是正式 Go 服务上线或第一阶段闭环交付。探针位于 `backend/prototypes/workspace-consistency/`，不依赖任务 03 的题目格式，不包含 gRPC、Java 数据库或浏览器。

## 实际环境

- Windows 主机，Go `go1.26.5 windows/amd64`；`GOOS=linux GOARCH=amd64 CGO_ENABLED=0` 交叉编译。
- Docker Engine `29.4.0`，Docker Desktop Linux；内核 `6.18.33.2-microsoft-standard-WSL2 x86_64`。
- 运行镜像 `maven:3.9.15-eclipse-temurin-21`，本次本地 image ID `sha256:9654767eabba379936a98e17dcacdb3355ff160631e40236d650d6e74bd4cd3b`；仅借用已有 Linux 运行环境，没有下载新的 Go 镜像或依赖。
- 夹具存于容器 `/tmp`，文件系统 `overlayfs`，不是 Windows bind mount，也不是目标部署持久卷。
- 测试程序只读挂载；运行 `--network none --rm`，没有凭证或 Docker socket 挂载。此设置不代替业务沙箱安全验收。

## 测试方法与实际结果

初始公开接口先写测试，编译因缺少实现失败；实现 Apply/Read/Query 后单测通过。下一片加入 Copy/Freeze 测试，编译因接口缺失失败，实现后通过。随后对已实现行为添加故障/并发/安全回归测试，通过公开接口检查结果；直接修改存储仅用于模拟损坏、链接和宿主路径攻击，不用内部布局推导期望结果。

| 验证 | 实际结果 |
|---|---|
| 两文件整批保存、重开 Store 查询回执、同键重放 | 修订仅从 0 到 1，文件与回执一致；重放不推进 |
| 相同内容保存、旧基线保存另一文件、同键异载荷、重命名 | 无变化不推进；旧基线/键复用拒绝；新增+删除整批推进一次 |
| 第一文件写入后返回注入 I/O 错误 | 正式树仍是两个旧文件，没有成功回执，无部分应用 |
| 子进程实际 Kill：第一文件写入后、发布前 | 内核释放锁；新进程观察旧版本；stage 不可见，无回执 |
| 子进程实际 Kill：rename 后、父目录 Sync 后 | 新进程观察完整新树、新修订和同一回执；重复请求不推进 |
| 成功持久化后模拟响应丢失 | 返回错误但 Query 查到版本 2；不会将错误等同回滚 |
| 冻结发布后 Kill | 重开可查询冻结回执，新写入被拒绝 |
| 8 个并发相同请求，两个同基线不同请求竞争 | 同键仅一个效果；不同键一成功一基线冲突 |
| 复制与写入协调 | copy hook 持锁时写入等待并响应 deadline；随后保存成功，副本仍是完整旧版本；旧预期版本复制拒绝 |
| 在途写入与冻结协调 | 冻结等锁超时；写入完成后冻结记录新修订，后续新写入拒绝 |
| 发布前 Context 取消 | 旧版本仍有效，不发布 |
| 非法/越界/保护路径、文件目录冲突 | 整批拒绝，不改变其他文件 |
| 内部/外部/目录 symlink、硬链接、FIFO | Read/Apply/Copy 失败关闭；外部夹具未修改；FIFO 不阻塞 |
| 并发目录交换为外部 symlink，200 次读取 | 运行样本未泄露外部标记；不推导任意宿主攻击下的文件树完整性 |
| 最新已提交 manifest 损坏 | Read/Query 报错，不悄悄回退旧版本 |

## 没有证明的保证 / 后续门槛

1. **不是 exactly-once**：回执去重依赖工作区实例唯一、同一权威存储及回执保留。NotFound 不是旧 RPC 已停止，Java 必须排空/隔离旧调用后再决定下一步。
2. **持久性边界**：只 Kill 进程，没有断电、内核崩溃、磁盘缓存故障、真实 ENOSPC、权限故障或存储损坏恢复。文件/目录 Sync 顺序已实现，但目标部署文件系统须复验；初建根目录的父目录持久化也应纳入正式创建事务。
3. **授权/跨语言**：任务 05 选择排空或栅栏协议，验证接管、撤销、到期与文件提交的全链路排序。文件锁不能独自解决 Java→Go 的迟到请求。
4. **路径与平台**：Linux fd-relative 遍历已验证；Windows/junction、NFS/共享盘、实际服务策略加载、跨演练身份绑定尚未验证。服务私有根目录和可信父目录是前提，不保护同权限宿主攻击者任意篡改元数据。
5. **容量/保留**：全量快照与累计回执只用于小夹具。配额、请求/文件上限、历史基线读取、未决回执保留、墓碑、引用保护、stage 清扫和磁盘准入仍须实现；不能部署此探针对外服务。
6. **性能与完整性**：未运行 Go `-race`（交叉编译未配置 Linux C 工具链），并发功能测试不替代竞态检测。无内容校验和、损坏修复或备份恢复测试。
7. **集成**：未运行正式 Go gRPC 边界、Java 数据库对账、浏览器端到端或目标部署持久卷测试；任务 04 的通过不解除这些功能验收门槛。
