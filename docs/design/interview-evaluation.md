# 面试、题目与评测设计

状态：本文件主要记录第三阶段已确认的产品目标，不表示面试官、挑战、回顾或 AI 报告已实现。当前第二阶段工程练习已验收，见 [阶段记录](../../.scratch/copilot-loop/issues/22-stage-acceptance.md)；最终面试 FSM、评价维度和报告存储契约仍待设计。面试官和评测官是 Java 内部职责，不是用户可管理的 Copilot。

## 题目与发布

- 平台维护固定版本 Java/Maven 题目包：基础需求、初始工程、受控测试目标、可编辑范围、演练时长、评价标准及至多一轮可选挑战。
- 首期通过仓库文件及验证命令/脚本发布，不建设可视化出题后台。发布固定题目版本与镜像标识。最小 manifest、包摘要、离线镜像、受控测试与结果分类见 [题目包契约](problem-package.md)；首题为购物车金额计算 1.0.0，45 分钟、无挑战。
- 初始工程须能在禁网容器中编译、运行预定测试，初始结果符合题目设计，不要求初始代码全部通过。
- 参考解必须通过基础及配置的挑战测试；验证离线依赖、权限、资源限制和元数据齐全。未通过发布验证的题目不进入可选列表。
- 验收规则和源码公开，权威副本不可修改；挑战测试进入后公开。用户可编辑练习测试，但删改断言/构建配置不能绕过平台受控验收。

## 演练阶段与计时

```text
准备工作区/执行环境与模型检查
→ 澄清（可浏览，不开放保存、AI 修改或测试）
→ 用户点击“开始实现”
→ 实施（连续计时）
→ 当前版本基础验收通过后，可主动进入预设挑战
→ 用户结束或到期收尾
→ 冻结、最终验收、可跳过回顾与报告
```

- Java 确定性逻辑拥有状态迁移权限；LLM 只表达当前阶段内容。测试事件验证任务、版本、阶段并幂等处理，不从日志或模型判断阶段通过。
- 澄清允许直接开始，不要求提问次数；实施后仍可询问需求。首期无澄清闲置自动过期。
- 从“开始实现”起按题目时长计时，挑战共用时限，后端截止时间权威。仅服务端确认的显式暂停停表；断线、等待审批、故障、压缩、更换 Key 均不停表。
- 环境准备与模型检查在开始计时前完成；检查契约见 [模型接入](model-access.md)。
- 故障与等待保留可识别记录，不据此推断能力；平台故障不归责用户代码。最终验收及报告不占作答时间。

## 第三阶段生命周期协议（05 实施契约）

本节是 05 的实现目标，不表示所有接口已交付；实施结果以该票验收记录为准。复用现有工作区、任务快照及持久栅栏，不另建不受生命周期约束的聊天服务。

| 工作区状态 | 产品阶段与权限 |
|---|---|
| `PREPARING` / `PREPARATION_FAILED` | 准备、重试或放弃；尚未计时 |
| `READY` | 澄清；个人模型准备检查未通过时先完成设置，不开放模型问答或开始；只读题面/代码，不保存、不测试 |
| `ACTIVE` | 实施；`stage=BASE/CHALLENGE` 决定已公开需求和受控测试目标 |
| `PAUSING` | 暂停请求已提交，禁止新作答和收费请求；仍按原截止时间计时，等待在途收敛 |
| `PAUSED` | 栅栏已闭合且任务已收敛；持久化正的剩余时长，截止时间为空；占用唯一活动名额 |
| `RESUMING` | 显式恢复已受理，重开栅栏待确认；尚不开放作答，不自动派发旧队列 |
| `CLOSING → FINAL_TESTING → ENDED` | 停止、核对、冻结及有限最终验收；结束后进入待提交/跳过的回顾，再生成报告（06） |

- 合法迁移为准备成功到 `READY`、`READY → ACTIVE`、`ACTIVE → PAUSING → PAUSED → RESUMING → ACTIVE`，以及可结束阶段到 `CLOSING`。澄清允许零消息直接开始。暂停与恢复不改变 `stage`，不增加题目时长。`PAUSING` 到期直接收尾，不能随后确认暂停；`PAUSED/RESUMING` 无到期任务。主动结束可打断暂停或恢复，结束栅栏排序在先前控制转换之后，不能短暂恢复作答。
- `POST /api/exercises/{id}/pause`、`/resume` 复用会话、来源/CSRF、`X-Operation-Credential` 和 `Idempotency-Key`。受理返回 202 操作回执，通过既有操作查询和演练快照观察结果，不把 HTTP 成功当作已暂停。相同操作键只观察原操作，不能让旧暂停键再次暂停已恢复的演练。`GET /api/exercises/{id}` 不发起暂停/恢复或收费任务（到期观察仍沿用既有确定性收尾），提供状态、阶段、服务端时间、截止或暂停剩余时长及转换操作标识；刷新只恢复快照，不隐式恢复。
- 暂停请求在用户授权锁和工作区控制锁下检查 `now < deadlineAt`，同事务关闭 Java 准入并持久化暂停意图。复用 Go `CloseGate` 的递增 epoch 与写入回执核对，不回滚已提交修改；停止执行并完成同步结果核对，取消未决审批、终止当前模型轮次/子任务/BTW、保留未派发 follow-up 为 `PAUSED`。未知副作用保持未决，不能提前停表。未发布的命令候选与本地草稿不冒充已保存版本。
- 收敛确认事务重新读取时间与状态：只有栅栏关闭、写入无未决项且所有参与者安静时才持久化 `deadlineAt - now` 并进入 `PAUSED`；若 `now >= deadlineAt` 则到期收尾。不按请求到达时间返还收敛耗时。时间精度不得向上取整增加作答时长。
- 恢复复用持久 `CloseGate/OpenGate` 转换；仅开放回执确认后，按确认时刻加持久剩余时长写入新截止并进入 `ACTIVE`。重启只继续同一转换，不重复增加时长。旧 epoch、旧审批与旧派发授权永不复用；保留队列通过既有显式收费确认恢复接口重新授权。
- 接管/释放与暂停转换串行；暂停期间可接管以取得恢复权，但控制权转移不得打开作答栅栏。身份撤销仍优先关闭准入；新会话不能凭旧页面状态绕过控制权。保存、批准、模型派发、工具提交、Bash、测试、steer、follow-up、子任务、BTW 全部使用同一生命周期和截止检查，读历史不续期、不恢复。
- 面试官消息采用独立持久任务与只读快照/SSE，复用既有 cursor/reset/撤销/背压契约；断开不重发收费调用。派发前及结果提交时复核会话、生命周期、绑定版本和截止，暂停后迟到结果不能触发阶段迁移；未知调用不自动重发。面试官没有文件修改或任意命令工具，费用与 Copilot 分账。
- 挑战进入为独立幂等命令：在控制锁下核对 `ACTIVE`、未到期、当前 revision 的基础验收有效通过以及题目预设挑战。持久化进入事实后才公开挑战题面/测试；无挑战只返回无入口，不返回隐藏内容。不得由旧测试事件、模型文字或客户端状态触发进入，不修改源码或安装依赖。

### 面试官问答持久任务

- `POST /api/exercises/{id}/interviewer/tasks`：`{text}`，4 KiB UTF-8，要求会话/CSRF、当前操作凭证及幂等键。仅 `READY/ACTIVE` 可受理；READY 复核个人模型准备检查，但使用演练绑定的 INTERVIEWER 平台模型，平台承担费用。零提问仍可直接开始。每场最多 200 条，最多一条在途；不加入 Copilot 对话、不授予任何工具或阶段迁移权限。
- GET 同路径按 `before` UUID 倒序每页 20 条读取只读历史；GET `/{task}` 读取快照；`/{task}/events` 使用现有有界 SSE 传输、持续身份校验、快照游标与 reset 语义。刷新、重连和重复 POST 不调用模型，不自动重放未知调用。
- 受理保留提问、阶段、平台配置身份；派发时固定当前公开题面（不读取 manifest 的隐藏挑战）、必要的绑定平台指令/Skill 和调用价格快照，不混入私人 Skill、Copilot 对话或凭证。每场容量统一预留 128 KiB/请求，输出上限 16 KiB，历史及用量行随演练计量和删除。
- `QUEUED → RUNNING → SUCCEEDED/FAILED`。队列期限 300 秒，单次调用上限 120 秒且不超过会话和作答截止；先持久化 RUNNING 再调用，无重派发路径。重启后超时 RUNNING 标为 `INTERVIEWER_RESULT_UNKNOWN`；未知不自动重发。派发和提交均在 owner/control 锁下复核原会话、凭证、阶段和生命周期。阶段切换、接管、暂停或结束使迟到文本不公开为有效回答，已知用量仍单独保存。
- 暂停意图同事务取消 QUEUED 问题，RUNNING 等待有界调用收敛或到期标未知；未知不产生代码副作用，不回滚已知费用。暂停确认的领域静默检查包括面试官任务。历史只读不要求操作凭证。

## 可选挑战

基础任务完成条件是当前已保存版本的规定验收全部通过。通过后继续保存使旧结果不能证明新版本通过。

配置了挑战的题目展示“进入挑战”和“结束并回顾”；无挑战则不展示入口。进入请求由后端校验并幂等处理，不凭按钮可点击作为授权。

挑战只追加预设需求和启用对应测试，不偷偷修改用户代码或临时下载依赖。模型不能自行扩展任务。进入后不能退回未参与；用户仍可结束。基础阶段曾通过的事实保留，但最终版本若破坏基础功能须标明回归。

05 实施决定：挑战使用包内 `challenge/` 独立、固定版本的受控发布包，其参考解必须通过包括基础回归在内的完整验收；两包 `initial/` 必须逐字节相同，且挑战包不得继续嵌套挑战。维护者分别离线验证两张不可变镜像，发布产物绑定两者摘要与验证回执。基础阶段 Bash/测试只使用基础镜像，不能从 `/opt/acceptance` 读取隐藏测试；进入挑战不修改工作区树、不重新安装依赖。挑战镜像只供挑战受控验收，开发 Bash 仍用基础镜像。公开题库只投影基础题面与 `hasChallenge`，挑战需求/测试仅由本人演练的阶段感知接口在已进入后返回。该决定是实现约束，发布/执行链路尚须完成后才可标记验收。

### 挑战阶段接口与证据

- `GET /api/exercises/{id}/challenge` 返回本人演练的 `available/entered/eligible/reason`；只有 `entered=true` 才附固定挑战需求和验收源码，未进入不下发隐藏正文。GET 不发布挑战、不执行测试。`POST` 同路径使用会话/CSRF、操作凭证、幂等键。
- 进入事务按 owner → workspace control 锁序串行，要求 ACTIVE 且未到期、当前已保存修订具有同实例 `base/PASSED` 结构化验收证据、全部领域任务已静默（运行中的 Copilot/面试官须先收敛，避免继续使用旧阶段上下文）。进入事实保存当时修订和基础测试 ID，基础证据加入保留引用，随演练计量/删除。源码、开始时间与截止时间不变；重复命令只观察原进入事实。
- 受控测试请求支持 `base/challenge` 白名单；只有已进入挑战的演练可请求 challenge，不能用客户端目标绕过进入检查。已进入后仍可显式运行 base 检查基础回归；最终验收固定使用 challenge（其测试包含基础回归），未进入则只用 base。结果身份关联真实使用的独立镜像/包摘要，不把基础镜像身份写到挑战结果上。
- 最终验收复用查询必须同时匹配冻结修订、工作区实例及当前已进入阶段目标；旧 base 通过不能替代 challenge 的最终结果。已进入事实不可回退，暂停/恢复不改变阶段。

## 结束与冻结

- 关闭页面不结束演练；测试未通过也允许主动结束，记录未完成及失败证据。
- 主动结束先处理未保存草稿（保存/丢弃/返回），提示运行任务及待审批修改；确认后停止任务、终止未处理审批，等执行收敛后冻结代码和证据。
- 到期禁止新的保存、批准、任务启动和 steer 等作答操作，停止并核对在途结果后冻结。未保存草稿保留供复制，不自动写入最终代码；提前提醒保存。
- 停止不回滚已经应用的修改。结束后只读，重新练习从题目初始工程创建新演练，不解冻旧记录。
- 冻结版本已有有效平台验收结果则复用，否则自动执行一次已进入阶段的验收；不偷偷启用未参与挑战。测试失败可正常报告，环境故障单独说明。
- 提供关键决策、AI 审查和剩余风险的简短回顾，允许跳过；自述是补充证据，不能代替代码/测试事实。

## 工程底座的失败与收尾（任务 05）

第一阶段最初没有模型检查；第二阶段已接入真实模型准备检查、Copilot 与 Skill，但仍不含面试官、挑战或 AI 报告。当前底座状态、操作权、到期及有限最终验收遵循 [任务 05 协议](task-event-recovery.md)，已有正式实现与验收，不替代上述第三阶段完整产品流程。

- 用户确认：准备失败可重试，也可放弃并释放活动名额；旧实例永久封存，残留资源后台清理，失败可见。
- 用户确认：最终验收持续环境故障时有限重试，耗尽后结束并显示“最终验收结果不可用”，保留冻结代码、释放活动名额，不记为代码失败或通过。
- 技术预算初值为最多 3 次尝试、总计 10 分钟，持久化并跨重启保持；未知执行先核对，不并行启动下一次。资源清理/执行隔离与活动演练名额分开，不能因为结束就忽略仍可能运行的容器。
- 最终冻结尚不可确认时保持收尾待核对，不虚构冻结版本；该基础设施故障与冻结后的验收不可用分开展示。

## 角色与上下文

| 职责 | 允许的工作与证据 |
|---|---|
| Copilot | 已发布需求、当前代码、相关对话和工具结果；不提前看到未发布挑战 |
| Interviewer | 解释需求、回答问题、发布已确认进入的挑战、引导回顾；读取必要阶段/进度/交互证据，不另起改代码工具循环 |
| Evaluator | 冻结代码、测试、变更、相关对话与回顾；不只依赖 Copilot 自述 |

Java 按职责提供上下文，不共享全部历史或私有 Skill 原文。平台模型及 Skill 按演练固定，用户无配置权；管理员后续修改仅影响新演练。平台承担两者费用，见 [架构](architecture.md) 与 [Skill 配置](skills.md)。

## 评价与报告

评价 AI 协作完成工程任务的表现，不推断用户独立编程能力，不按 AI 使用量自动扣分。

- 工程结果围绕最终冻结版本的正确性、质量与验证；早期失败可作为修正过程证据，不按失败次数机械扣分。最终版本未验证不能借用旧版本通过结果。
- 协作过程关注澄清、决策、审查和修正行为；最终维度及题目判级标准仍待定。
- 按已批准的 00 规则采用百分制：正确性与功能完整性 35、代码质量与工程规范 25、测试与验证 20、问题分析与 AI 协作 20。不增加排名。“未参与挑战”是参与状态，不扣基础分；已参与挑战仍采用同一组权重。
- 每个维度必须给具体反馈：依据明确时判级并引用证据；无法支撑等级时说明观察范围、给出下一步练习，不强行判级、不设置“证据不足”等级或标签。
- 未记录到行为不等于用户没有能力。跳过回顾不自动扣分；用户自述与可验证事实区分。
- 本应采集的数据缺失按报告数据异常处理、重试或提示，不归责用户。

先展示确定性验收结果、参与阶段和变更，再异步补充 AI 评价。模型失败不隐藏已有结果，也不重新执行已有测试。

AI 报告发布前校验结构、等级、证据引用实际存在、各维度反馈齐全及明确事实一致性（例如失败不能写成通过）。有限次重生成后仍失败则提示并允许重试，旧报告重试沿用原配置。程序校验不保证所有主观评价正确。

### 06 回顾与报告实施契约

本节是实现约束，不代表该票已经交付。

- 确定性结果沿最终验收即时可读；仅 ENDED 且冻结修订已确认时接受 `POST /api/exercises/{id}/report/review`，请求为 `{skip,text}`，回顾最多 4 KiB UTF-8，跳过时 text 必须为空。采用会话/CSRF/owner 及幂等键，不要求作答操作凭证。提交或跳过均为不可变决定，不能事后追加回顾或隐式改分；自述单独标记，不能单独支撑正确性得分。
- `GET /api/exercises/{id}/report` 返回确定性冻结/测试事实、回顾状态和报告状态；无报告记录表示待回顾，不因读取创建记录或调用模型。报告快照具有不可变报告 ID、冻结修订、绑定 EVALUATOR 版本及单调 generation。用户显式重试只能针对同一冻结版本和平台配置，不能覆盖后来的 generation。
- 证据来源限定本人演练的冻结文件、最终验收、保留变更/对话以及回顾，不读取个人 Skill 原文。证据 ID 按类型和不可变来源生成；模型只可引用本次保存的证据目录。代码/对话正文供平台评价，不默认进入 PDF；公开报告只给有界证据摘要和本人可授权读取的原来源链接。来源超出有界读取时明确截断，缺失不能伪造零值或通过。
- 评价在持久任务中异步执行，QUEUED → PREPARING（仅只读取证）→ RUNNING（已持久派发）→ SUCCEEDED/FAILED/UNKNOWN。取证和模型请求在数据库事务外进行，派发与结果提交在 owner 锁下复核身份、删除、冻结修订、绑定版本和 generation。已派发的未知调用不重新发送，截止后标 UNKNOWN，用户显式重试才开始新 generation。确定无有效报告的结构/证据校验失败最多自动重生成两次（共三次），保留已知用量与原因；未知结果不走自动重生成。
- 发布必须恰有四个已知维度，分数为范围内整数或 null，非空反馈、真实证据引用。非空分数必须有非自述证据；正确性数值还必须引用当前冻结最终验收。总分仅在四项均有依据且最终验收可用时为四项之和；平台验收 UNAVAILABLE/PENDING 时不得发布总分。结构化 `verification` 必须等于确定性事实；此校验不能保证所有自由文本主观判断正确。
- 报告、回顾、证据摘要、原始有界评价及尝试/用量随演练计量与删除；普通调用前预留总预算，删除先撤销读写并等待在途调用有界收敛，未知调用不重发。报告 PDF 按本人请求从同一 generation 快照现生成，不留永久缓存或公开 URL，发送前再次核对归属/删除与版本；只含评分、结论和关键证据摘要，未完成明确标记，不补假分数。

## 反馈

- 用户可针对面试官消息或报告评价提交描述；预览并授权附带消息、报告片段或代码证据。
- 默认不附 Copilot 对话、Skill、凭证或完整代码。管理员仅查看提交包与相关配置版本，不能由反馈跳转浏览整场私有演练。
- 用户可查看自己的反馈及管理员回复；状态为待处理/已处理，不扩展为客服聊天或完整工单系统。
- 反馈可促使管理员验证、发布新配置，不能悄悄改当前演练或承诺必然修改。
