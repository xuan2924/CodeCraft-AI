# Copilot 工具循环：首期有效设计

状态：读取、修改提案、整批 ASK/AUTO 审批、受控测试与 steer 已接入 Java、持久化及 Web 页面；自动/手动上下文压缩及原证据读取已接入。P2-11/12 已通过真实 DeepSeek 非思考 + Linux Java/Go + Docker + 浏览器的读取→Diff→审批→测试失败续答，以及 AUTO 无手动批准应用与切回 ASK；受控测试另已验证稳定版本结果及父任务联动停止。steer 使用可控 SDK 流、真实 PostgreSQL 和组件竞态验证。DeepSeek Chat ON 真实浏览器链路及三协议声明组合已完成验证；用户取消 OpenAI、GLM、Kimi 三家目标后，矩阵按 [已验证范围](../research/model-provider-matrix.md) 收口。Skill、用量与保留删除亦已验收，阶段证据见 P2-22；不将可控模型测试、服务实例重建或一次性 PoC 视为真实供应商或进程强杀验证。

## 选择与范围

首期采用 **LangChain4j 模型 API + Java 应用自管 Copilot Loop**。不使用 AI Services 自动工具循环作为 Copilot 主执行器，暂不引入 `langchain4j-agentic` 工作流运行时。

这里只决定 Copilot 的编排实现，不变更 Java 主后端 + Go 沙箱 + Vue 的架构，不要求 Interviewer、Evaluator 各实现一套工具循环，也不建设通用 Agent 框架。选择原因和替代方案见 [ADR-0001](../adr/0001-copilot-application-owned-loop.md)。

## 职责边界

| 所有者 | 职责 |
|---|---|
| LangChain4j 模型 API | 模型请求与响应适配、消息及工具调用结构、流式接口；使用 SDK，不自行重写模型通信协议 |
| Java Copilot Loop | 模型调用轮次、工具批次与执行位置、工具请求/结果配对、审批暂停与继续、上下文组装、预算及停止条件、运行状态恢复 |
| Java 业务层 | 演练所属用户、审批模式、Patch 基线与状态、权限校验、幂等和审计；不把授权交给模型 |
| Go 执行服务 | 在受控演练工作区执行文件工具和测试，落实路径、命令及资源限制，执行停止和资源清理 |

Loop 通过受控工具适配器调用业务层/Go，不另建一套绕过原有权限和审批的工具入口。凭证与服务信任边界见 [架构设计](architecture.md)。

## 执行模型

```text
准备模型上下文 → 调用模型
  ├─ 最终回答 → 结束
  └─ 工具调用批次
       → 校验并执行允许的工具
       → 需要审批时保留批次、执行位置和已完成结果，暂停
       → 用户决定后重新校验权限、Patch 状态和基线版本
       → 记录应用 / 拒绝 / 冲突等确定结果
       → 补齐对应工具结果，继续模型循环
```

首期工具批次按模型返回顺序逐项执行，不并行调度。每项开始前检查停止、steer、演练状态与有效授权；审批等待时后续项不执行，已完成结果和调用 ID 保留。这个限制不禁止用户在 AI 运行时继续编辑，也不限制为固定单轮。

现代工具广告为 `read/grep/find/edit/write/run_tests/bash/load_skill/read_source/read_evidence/delegate_task/web_search/web_read`，名称、schema、通道权限与容量声明统一由不可变 `CopilotToolCatalog` 提供；历史 `view_file/grep_code/glob_files/propose_changes` 仍可执行。`edit(files)` 支持 EDIT/CREATE/DELETE，EDIT 按原文件唯一且互不重叠的 `oldText/newText` 精确替换；统一 LF 比较并保留原文件换行风格。`write(path,content)` 创建或整体替换。二者均生成标准不可变提案，不绕过审批。历史 `propose_changes(expected_revision, changes)` 仍支持完整 CREATE/UPDATE/DELETE 批次，最多 32 个文件、192 KiB 参数；重命名使用同批 CREATE+DELETE。复用底座路径/文本校验、FILE_BATCH 准入、Go 原子提交和回执，不解析或模糊应用展示 Diff。固定基线原文及目标文本一并保留、计量；登记前最多预留 64 MiB，登记后按实际记录结算，批准另行检查写入容量。当前默认逐次审批；等待审批/写入时释放 worker，已确认工具不重做。相同基线、相同内容的已拒提案不会再登记；有限无进展保护仍覆盖模型反复提交。

这是控制流目标，不是固定三个工具或只支持一轮的实现。审批行为见 [审批设计](approval.md)，文件与测试的安全边界见 [工作区与执行](workspace-execution.md)，通信和重连见 [接口与事件](api-events.md)；各专题标明的待决项须先确认，不能从控制流示意图推导最终协议。

需要保存模型使用的消息与工具结果，也需要独立的运行状态、审批状态和执行证据。聊天记忆不代替任务恢复记录。恢复不应重新生成已有工具批次或盲目重放结果不确定的外部副作用。

不能直接将原型的 Properties 文件、固定游标或单文件回执作为正式持久化与恢复方案；具体待验证项见下文。

## 任务与停止

一次 Copilot 任务是一次用户请求及其完整模型/工具循环，包含审批暂停与继续。拒绝提案后调整仍属于当前任务；最终回复、停止或异常终止后再次发起才是新任务。同场演练最多一个 Copilot 任务，不隐式排队第二个任务，但支持 steer。

“停止任务”阻止后续执行，保留已生效修改；“拒绝修改”只拒绝当前提案；“撤销修改”通过代码历史恢复已应用代码，并创建新的受授权修订，不删除原记录。停止过程显示“正在停止”，核对在途结果后才显示“已停止”，完整审批语义见审批设计。

不设置正常任务的固定总轮次、总 Token 或总时长硬截止。整体受演练截止时间和用户停止约束；单次请求/工具保留超时、并发与输出限制，重复失败无进展时停止并说明。模型窗口与单次输出上限仍须遵守。

## Copilot 发起的测试

- 测试归属于发起它的 Copilot 任务，持久化父子关联；测试工具等待确定结果后回填模型，期间不执行下一项工具。测试使用已保存版本的稳定副本，用户仍可编辑。
- 停止 Copilot 时同时停止其发起且仍在运行的测试，执行状态收敛后父任务才显示已停止；不停止用户独立发起的手动测试。浏览器断线仍不等于停止。
- 手动与 AI 测试共用第一阶段的单演练执行名额；占用时返回明确的结构化忙结果，不排队、不抢占、不高频自动重试，不将其他版本的结果冒充本次测试结果。
- 测试通过、失败、超时、环境错误和中断按底座结构化结果回填，不能从模型说“通过”或日志文本推断成功；未知执行先对账，不盲目重启测试。

## Copilot 发起的开发命令

- `bash(command, directory, expected_revision?)` 复用开发命令服务，不走受控测试入口。固定原命令、目录、基线及登记 ASK/AUTO 模式；审批是命令级授权，不表示提前接受未知 Diff。具体权限见[审批设计](approval.md#开发命令审批)。
- V42 `copilot_command` 保存提案、原工具 ID、模式版本、决定审计和唯一子命令绑定；登记保留原工具 512 KiB 额度，执行另用既有 192 MiB 预留。决定、子命令登记与 `WAITING_COMMAND` 同事务，等待释放 worker。父任务仍占单演练 Copilot 名额，压缩和 steer 不越过未决执行。
- 恢复只查询原绑定，等待进程已静默、同步已有确定结论、容器及副本收尾成功后回填。完整回执在事务外校验/投影，提交时重验原版本与载荷；未知结果不续模型、不释放父任务。父任务停止只取消自己的子命令，不认领或停止独立手动命令。
- 返回 `COMMAND_RESULT` 或 `COMMAND_SYNC_FAILED`，保留普通退出码、停止/超时原因、同步状态/修订和执行引用。普通命令没有权威通过证据。模型日志使用与测试相同的 16 KiB / 64 段 UTF-8 安全尾部；模型节选截断与底座输出丢弃/缺失独立表示。
- 父工具回填前通过既有演练数据贡献接口保护命令原证据，之后恢复普通命令有界历史保留。绑定/审计/模型回执随演练保留及删除，纳入同一容量；新明确容量不足时可复用 #03 的有界安全清理，不清理未决、冲突或父工具仍引用的记录。

## steer

- 运行中接收用户调整方向的指令；记录“已接收”，在安全点纳入下一次模型调用后标记“已生效”。不能修改已发出的模型请求或回滚已应用代码。
- 当前请求/已开始工具收敛后、下一项工具开始前检查指令。保留已完成结果，使旧待审批提案失效，不继续旧批次剩余操作。
- 为未执行的工具补齐明确的未执行结果，保持调用 ID 配对，再携带新指令重新规划。
- 连续 steer 按接收顺序保留，在下一个安全点一并处理，不静默覆盖；已生效后的新指令在后续安全点处理。
- 若任务已结束，提示未生效，不自动创建新任务。steer 与批准、停止、到期的竞争按服务端确定顺序处理。
- 实现状态为 `RECEIVED`（已接收）、`APPLIED`（已纳入持久模型请求上下文，不保证供应商收到或成功回复）、`NOT_APPLIED`（结束前未派发，保留原因）。接收审计包含原任务、用户、授权版本、原文、接收序号和幂等键；不刷新 Skill 快照或重授权原父会话。
- 单条有效 UTF-8 原文至多 4 KiB、不含 NUL，最多 32 条待处理；每条预留 64 KiB 覆盖审计与正式消息，纳入既有计量、保留及删除。超限拒绝，不覆盖；列表按数字序号倒序每页 20 条，模型上下文仍按接收顺序追加。
- 所有者锁排序 steer 与原批次批准/执行登记。先接受 steer 的待审批提案变为 `INVALIDATED/STEER_SUPERSEDED`；已开始的读操作、已批准的原 FILE_BATCH 和已绑定测试先收敛，未知结果不释放槽位、不重做。旧剩余调用逐 ID 回填 `NOT_EXECUTED/STEER_SUPERSEDED` 后重新规划，既有拒绝记录与已完成结果保留。

## 工具与失败处理

工具输出、仓库内容和 Skill 是非可信输入，不授予权限。文件读取使用带行号切片；搜索、日志及文件结果都有条数/字节上限，截断明确提示。

| 情况 | 行为 |
|---|---|
| 临时网络、限流、供应商临时错误 | 有限重试并遵循退避；副作用操作先确认幂等性或查询结果 |
| 参数错误、路径/权限错误 | 返回明确结果供模型修正，不原样盲重试 |
| 基线冲突 | 旧提案失效，重新读取和生成 |
| 写入结果未知 | 先对账，禁止盲重放 |
| 测试未通过 | 正常测试结果，不当作工具故障重试 |
| 重复相同失败且无进展 | 停止循环并说明，不无限调用 |

## 内嵌子任务委派

- `delegate_task(goal, context?)` 创建真实 CHILD 会话/任务，复用同一用户的持久 Loop、模型选择、用量和工具执行。目标最多 4 KiB，显式选择的支持上下文最多 8 KiB；另附父任务最近已保存用户目标最多 4 KiB、来源 ID/截断标记，不复制全部聊天、工具协议或 hidden thinking。子任务独立固定创建时可用的 Skill 目录/指导，后续预算和摘要仍走原通道。
- 一层、每场一个活动 CHILD、每父任务最多 8 次委派且一次在途；MAIN 原活动名额保留。父任务及原工具进入持久 `WAITING_CHILD`，清除 worker 租约并释放线程，不与其子任务同时推进写入。原工具 ID、父/子任务 ID、子会话及目标一事务建立；没有平台 Agent、独立 SDK 或工作区自动合并。
- MAIN 广告与执行 `delegate_task`；CHILD 可读取、检索、提案、测试、Bash、证据/Skill/联网工具，但 schema 和运行时均禁止再次委派；BTW 仍只读且不能委派。普通 start/follow-up 不接受 CHILD 会话。子任务使用正常 ASK/AUTO 版本、审批、工作区修订与执行栅栏，人工及其他会话写入仍可能使其旧基线失效，不自动覆盖或伪造合并。
- 子任务确定成功/失败/停止后，原委派工具恰好保存一个结构化结果：真实子任务/会话、终态/原因、最新已保存助手文本最多 16 KiB、来源和截断信息、交接时观察修订。它不是全部子历史，不表示已撤销历史修改，也不表示父任务完成。父任务随后继续自己的 Loop；父会话及包含原交接消息的 Fork 可用 `read_evidence` 分页读取已交接子任务证据，不能据此读取任意旁支。
- 父任务停止传播到子任务；子任务命令未知、写入/测试未收敛时，父任务保持 STOPPING，保留原工具等待和清理保护。只停止子任务则把停止结果交父任务。等待子任务时的父 steer 仅在子任务交接后的安全点纳入，不立即改变正在执行的子目标。子任务 PAUSED 不冒充终态，用户可处理问题或停止子任务交回；失效原授权不会自动改绑新授权。
- 恢复仅核对持久关联和真实终态，不重建子任务、不重复已完成工具或未知付费请求；到期/授权失效停止父子。初始主任务费用确认涵盖后续模型选择的有限委派；子调用仍归同一用户/演练，可能收费。关联、结果和子历史纳入原容量与整场删除；代码历史保留真实子任务 ID，导航指向所属主会话。

## BTW 只读旁支

- 同一主会话具有独立 BTW 会话映射，历史不列入普通 New/Fork 会话列表；同场最多一个活动 MAIN 和一个活动 BTW，复用现有全局有界 worker 与模型驱动。任务通道持久保存，旁支不替换/停止主任务。每次问题需当前操作权及费用确认，原意图键重放优先于读取新主线上下文。
- 初始上下文为提交时主线最近用户消息/已保存助手文本各最多 4 KiB、来源 ID 和投影截断标记；不复制工具协议、工具输出或 hidden thinking。旁支只续接自身消息、摘要、Skill/项目指导；主线没有自动注入旁支历史。
- 旁支仅允许 `read/find/grep/read_evidence/read_source/load_skill/web_search/web_read`（兼容旧读取别名）；共享策略同时裁剪模型工具 schema 和约束实际执行，禁止提案、写入、测试、Bash、委派。普通 start/follow-up 不能以 BTW 会话绕过通道约束。
- 活动任务唯一性按演练+通道；摘要等待、模型派发和独立摘要调度按所属会话核对，旁支摘要不阻塞主线。主线原忙/审批/写入规则不改变；侧边问题受现有生命周期、操作权、存储及全局并发门禁。
- 停止接口仍按原任务 ID，只停止该旁支。到期/授权撤销/服务恢复覆盖所有通道；未知已发模型请求保留中断/费用不确定状态，不重发。旁支消息、摘要、用量和映射纳入原用户/演练计量与整场删除，不转入平台 Agent 账户。
- 显式带回仅发送用户预览整理的有限结论：主线可接收时走原 steer，回执区分接收与生效；空闲时追加到新请求草稿、清除费用勾选，仍需用户确认发送。主线暂停/停止收敛时保留旁支结论而不越过状态；从不自动复制完整旁支。

## 文件、代码与日志引用

- 普通新任务可带最多 4 个引用，每个固定节选最多 2 KiB UTF-8。`FILE/CODE` 来源为已保存路径，`TEST_LOG/COMMAND_LOG` 为原执行任务 ID；来源类型/身份、版本、字节位置、限额及服务端指纹随请求提交，不接受客户端自造引用正文。引用不赋予审批权限、不自动执行命令或读取整个项目。
- 服务端先重放已受理的原意图回执，再在事务外读取/核对来源；最终任务准入在原所有者锁下再次核对保存版本及保留日志，原任务 UserMessage 保存有界不可变节选与元数据。请求指纹包括引用选择；旧键不同引用冲突。编辑器发送前保存若改变版本，明确拒绝旧引用，不用新代码悄悄替换。
- `read_source(kind,source,version?,offset?,limit?)` 只读当前尚保留来源，默认 2 KiB，UTF-8 字节对齐；续读必须沿引用/上一页 `version`，版本变化或缺失是明确失败。`nextOffset/retainedBytes` 表示展示窗口；`sourceIncomplete/droppedBytes` 表示底层已丢弃/不完整，不能由翻页恢复。文件版本含工作区身份与修订；日志版本含修订及保留日志/丢失状态指纹。
- 来源目录复用原测试/命令历史，命令按原 cursor 翻页，只返回元数据；选择历史任务不重放执行。文件/日志节选随原消息进入现有容量计量、上下文投影、`read_evidence` 和整场删除；不额外永久保留完整来源。来源过期后旧任务中的已保留节选仍可读，超出节选的部分不保证可用。

## 后续独立任务队列

- Follow-up 与 steer 分开：仅当前会话存在活动任务时显式加入，原文最多 4 KiB、每会话最多 32 个未派发项，需确认后续费用。队列不修改当前模型请求，不复制任务/工具或继承当前勾选 Skill。派发沿正常新任务准入取得当时有效模型与权限，并读取已保存代码。
- PostgreSQL 保留单调接收顺序、原任务锚点、已派发前缀、会话、原授权会话哈希/控制凭证摘要及意图键，不存原 Cookie/操作凭证。队首等待所有演练活动任务及上下文操作收敛，成功后原子创建独立任务并记录其 ID；重入/重连不能创建第二个任务。PAUSED/待审批/待写入/待测试/待命令都不是完成。
- 原任务或前一队列任务失败/停止/中断则暂停队首，后项不能越过。授权或容量失效也暂停。显式“重新授权并继续队列”只接受暂停队首，重新确认费用并记录当前授权、恢复世代和固定幂等回执；不允许在任务仍运行时预先豁免未来失败。迟到旧世代失败不能覆盖新授权。取消与派发在原所有者锁下排序；已派发项只能走原任务停止，不伪装撤回。
- 演练结束/到期取消未派发项；关闭浏览器不取消已授权队列。原有有界 Coordinator 调度，无新框架、无内存自动发送。容量计量在事务外，创建/取消/恢复/派发在原所有者事务内；保留字节、恢复回执及最终清理接入整场保留删除。
- 读接口返回最近 100 项和全部未派发项（最多 132），按接收序排列。任务 latest 使用单调准入序，避免同时间戳 UUID 排序将已创建的后续任务隐藏。历史迁移保持既有 created_at/id 顺序。

## 联网资料工具

- `web_search(query)` 和 `web_read(url)` 复用普通持久化工具循环、原任务归属、停止/到期检查及 512 KiB 工具预留。由 Tavily 官方 Search/Extract HTTP API 提供搜索/正文，不在宿主实现任意 URL 抓取或 HTML 解析，不引入插件系统。
- 配置和专用 Key 见 README；缺配置返回明确不可用。Search 固定 basic、最多 5 来源且不请求生成答案，回执为 `SEARCH_SNIPPETS`；Extract 固定单 HTTP(S) URL、basic/text，检查 HTTP 200 中的 per-URL 失败，正文回执为 `FETCHED_BODY`。链接、内容和失败均真实来自服务响应，不以请求已发出冒充成功。
- 两个有界请求许可，禁止自动重试。总超时取配置和演练剩余时间较小值，覆盖完整响应体；中断取消原 HTTP future，未确认结果可能消耗 credits。服务重启沿既有工具批次中断配对，不重发工具。
- 传输最多 1 MiB；搜索每条正文最多 4 KiB、读取正文最多 32 KiB，`retainedTruncated` 表示超过保留界限的部分不可取回。原工具消息保留有界内容；模型上下文可投影截断并给出原消息 ID，继续用 `read_evidence` UTF-8 分页，不重新检索。页面展示分页和底层截断分开。
- 专用资料服务账户 credits 与用户模型 Token 分开，提供值则记录原任务回执，缺失标未知；不复制用户 Key、不伪造货币金额，不转记平台 Agent 模型费用。来源是不可信证据，不构成指令或审批授权。来源及回执沿既有整场保留/计量/删除。

## Fork 对话

- Fork 选择父会话内一条实际消息为包含式边界，完整继承原生协议前缀；在事务外用 SDK 消息类型校验调用/结果 ID、工具名称和顺序完整配对。未完成批次明确拒绝，选择其最后回执或之后回答；不创建活动任务、审批、模型请求或执行。
- `copilot_fork_message` 物化不可变原消息身份，统一成员视图供页面、模型上下文和跨模型兼容转换读取；分支后续消息仅属于自身任务。再次 Fork 物化成员，不递归查询祖先。原消息不改写，供应商思考字段仍保留；模型证据读取只扩展到确已继承的消息，不开放父会话边界之后或兄弟私有内容。
- 每次 Fork 最多 2,000 消息及 16 MiB 原协议，超限拒绝而非部分继承。成员元数据预留 512 字节/条加会话创建额度，沿整场计量和删除，先删除成员再删除原消息；目前不提供单会话删除。原摘要不复制为分支摘要，原始消息按既有上下文规划进入新会话，不重新设计压缩。
- New 和 Fork 共用每演练 100 会话限额及原操作凭证/容量准入。幂等键绑定创建类型、来源及边界，同键不同意图拒绝；原回执可核对但不能重新执行。会话创建不取得并行主任务资格，也不改变任何文件或测试版本。

## 项目指令

- 每次主模型请求准备时，从正式已发布工作区读取根 `AGENTS.md`，以及本任务最近最多 32 次真实成功的 `read/view_file` 调用目标的祖先目录 `AGENTS.md`。工具生命周期与 `outcome_code` 分离，失败回执不会加载子目录规则；历史未分类回执不推断为成功。不扫描宿主、不注入无关子树、不从其他会话或旁支推导路径；New 从根规则开始。目录规则在读取文件后的下一模型请求生效，不修改在途请求或既有批次。
- 按目录深度根到叶排序；子目录规则仅在其子树覆盖祖先同类指导，不覆盖平台规则或审批授权。使用独立的非可信项目指导消息，位于 Skill 与聊天之前；用户原请求和工具证据不改写。指导纳入实际请求窗口估算和保留内容预算，不另建摘要/压缩机制。
- 单文件正文最多 8 KiB，总正文 32 KiB，来源最多 32 个。缺失、超限、读取失败分别标记且不装入部分正文；来源数量超过限制明确标记。文件与准备前后正式快照不一致则取消本次准备、重新从安全点读取，不混合修订；派发事务再检查已观察修订。
- 每个 `copilot_turn.project_instructions` 保存实际派发的来源、修订、状态和加载正文，沿 turn 行计量及整场删除，保留不受后续指令更新影响。页面展示最近一次已派发请求的快照，不把当前文件冒充历史。读接口只授权查询、不派发模型。
- 项目指令由正常题目包发布或既有可编辑区域内文件维护，不新增任意路径写权限；受保护根规则仍不可经 AI Patch 改写。

## 上下文压缩

压缩是应用 Harness 首期必备能力，不依赖供应商自动处理。

- 每次调用前以 SDK 消息 UTF-8 序列化字节、工具 schema 和 512 协议余量保守估算输入 Token，另预留所选模型输出；有效窗口取模型声明窗口与执行上下文限额的较小值。默认占用达到 80% 时尝试压缩，估算不冒充供应商实测。界面实际用量展示见 [模型接入](model-access.md)。
- 采用近期原文、历史摘要与按需读取证据。保留任务目标、用户决策、关键修改、审批状态、工具调用/结果配对和证据引用。
- 已完成历史批次可整体摘要；未完成调用不能拆散。原始对话和执行证据持久化保留，压缩不删除原始记录或修改业务状态。
- 支持自动压缩和“立即压缩”；在当前请求结束、工具批次结果配对完整的安全点执行。
- 先控制可重新读取的冗长输出，再按需用用户当前模型摘要，摘要调用计入用户费用。缓存优化不能牺牲正确性。
- 默认保留最近 4 个完整单元、当前任务原始目标及最新已生效方向原文。可重读工具结果先投影为至多 8 KiB，接近上限时降到 1 KiB；原文不变。来源每页默认最多 512 条，并以至少两个合法最大工具批次的原文字节界限读取；只压缩完整前缀，成功后可逐页继续，不能静默遗漏尾部。
- 不足 4 KiB 的可替代前缀不调用摘要模型。正文上限为 8 KiB 与被替代输入字节一半的较小值；最终 SDK 编码后的摘要输入至少节省 25%，避免微小收益反复收费。固定模板 `prompts/copilot/summary.txt` 要求 goal/decisions/changes/state/evidence 五字段；引用只接受当前来源或原摘要 ID，不允许工具请求。非思考摘要默认预留最多 2048 输出 Token；思考模式保持原模型输出/思考预算关系。
- 仅完整但结构、证据或压缩收益不合格的响应允许修复一次。网络未知、重启或租约过期不自动重发；同一上下文版本/失败来源抑制自动重复。原内容仍安全则显示失败并继续，否则暂停；手动压缩成功或已无需压缩时，仅唤醒原授权仍有效且因上下文暂停的原任务，不新建聊天、不复活已终止任务。
- 以演练级 `copilot_context` 版本头及 `copilot_compaction` / `copilot_compaction_call` 保存来源范围、摘要链、模型配置、派发标记、响应及实际 usage。准备/编解码在事务外；短事务重验并派发，发布采用版本 CAS。授权结束、停止、到期或失去租约均不能发布；新 steer 不改在途摘要，随后按正常协议纳入。
- 活动任务在模型前安全点借用原 worker；无活动任务或上下文暂停时，手动压缩使用同一个有界池的独立租约，与新目标准入互斥。取消等待请求立即生效；独立 worker 可中断，借用聊天 worker 的在途压缩登记取消后等待请求收敛，避免迟到中断误伤下一次聊天。立即停止整个任务仍使用原停止入口。已派发请求可能收费。
- `read_evidence(id, offset?, limit?)` 仅读取同演练保留消息或已发布摘要，校验 USER、原会话、活动任务及 worker 租约；不授予文件/网络/审批权限。按 UTF-8 字节分页，默认 2048、允许 128–4096 文本字节，编码输出最多 8 KiB，沿 `nextOffset` 读取；隐藏供应商 opaque thinking/signature，保留的原协议记录不变。
- 跨模型历史只转换到最后一个不兼容批次的完整结果边界（包括未开始工具的合成回执）。当前精确模型产生的后续原生工具配对及 thinking 继续原样传递，不把整个新对话持续降级成历史文本。正常调用记录输入估算、上下文版本/范围和转换截止序号，便于核对。

## 配置与恢复

模型协议、连接测试、Key 更新及费用见 [模型接入](model-access.md)。个人中心保存多个模型连接，演练内由用户显式选择、切换模型，不通过覆写同一连接换模型，也不推导个人设置编辑自动联动。Key 保存无需真实检查；每次请求使用完整配置，在途请求不变，不自动重发失败请求，历史按实际请求记录非秘密配置身份而非套用当前模型。演练中切换不额外测试、不要求已有有效检查，后续正常请求直接使用所选模型，失败明确报错且不回退；开始计时前检查保持。切换在当前请求及其工具批次收敛、结果配对完整后，于下一次模型请求生效；不使待审批提案失效，不替代停止/steer/到期规则，不要求等整个任务结束。等待时展示“将在下次请求使用”，当前任务自然结束也不为切换额外发请求。切换持久化排序、跨协议历史及窗口变化已按 ADR 0008 与 P2-07/08/15/19/20 落地验证；不能以换模型为由重执行已完成工具或丢弃原始证据。

删除当前所选个人连接/模型不等于停止 Copilot：当前请求及工具批次按原规则收敛后暂停新的模型/摘要调用，提示用户重新选择，不用缓存的已删除配置继续派发、不自动替选或重发。删除本身不使待审批失效或停止在途测试；停止、steer、到期规则保持。演练、手动编辑/测试及倒计时继续，删除非当前项不影响当前演练。删除与派发/恢复的排序已经 P2-07/08 及后续恢复回归验证，见 [模型接入](model-access.md#删除个人连接或模型p2-03-已确认)。

模型配置的生效边界与 Skill 不同：每个任务启动时加载用户启用的 Skill 快照，显式/自动按需读取；在途任务及 steer 不刷新 Skill 快照，见 [Skill 配置](skills.md)。

浏览器断线不停止任务，`auto` 可继续写入，待审批暂停。服务重启后恢复已确认状态和待审批记录；中断模型请求不自动重发收费，由用户重试。已派发但无法确认的模型请求以 `MODEL_RESULT_UNKNOWN` 贯通任务视图，保留独立的不完整预览并提示可能计费。用户可对已终止任务显式发起新请求、重新确认费用；一般暂停任务先停止再发起；因上下文不足暂停的原任务可在手动压缩成功后按仍有效的原授权继续。GET/SSE 不代替收费或继续意图。未知写入先核对，不能重生成已完成批次；测试恢复见 [接口与事件](api-events.md)。

## 流式预览与低延迟唤醒

- `copilot_snapshot` 与 REST 仍为唯一持久权威快照。流式 Token 通过进程内有界 `TransientTaskStreamHub` 发布最新全文预览，数据库预览检查点最多每 2 秒一次，正常完成或异常退出边界另行落盘；不保存逐 Token 事件历史。
- 新 SSE `copilot_preview` 不带 `id`，载荷为 `taskId`、`turnId`、UUID 字符串 `previewEpoch`、从 `"1"` 递增的十进制字符串 `previewSequence`、`text`、`thinking`、`truncated`、`thinkingTruncated`。两段正文为有界全文替换，不是 delta；临时序号不替代持久游标。仅在当前 RUNNING turn 与授权快照匹配时发送；终态、重连或切换任务以持久快照覆盖。
- 通知只携带任务身份，不缓存用户会话授权。每次发送仍走原数据库授权、归属、删除及当前状态检查；空闲最多 5 秒重新检查并按原心跳周期发送。慢连接没有无界预览队列，新的分片合并为最新预览。
- Copilot、面试官、评测官及自动批准的提交后信号仅入有界唤醒队列，不在提交线程查询数据库或调用模型。持久扫描、停止、到期和租约检查继续作为恢复兜底；丢失信号不改变任务语义。60 秒清理及密钥轮换使用独立调度池，不阻塞高频发现。

## AI 数据保留与容量

- 对话、模型协议消息、工具结果、Diff、审批记录和任务 Skill 快照随演练自结束起保留 30 天；提前或到期删除时一并清理，不另设每类数据的保留天数。演练存续期间不因压缩删除原始记录，未决写入、审批与恢复证据先安全收敛再清理。
- 这些记录计入 [工作区与执行](workspace-execution.md#保留与删除) 已有的 512 MiB 单场预算，不额外发放 AI 额度。调用模型/摘要/工具前为输出、执行回执和必要状态预留空间，不能在收费请求或副作用已发生后才发现记录无处保存。
- 接近上限先清理允许回收的无引用数据，仍不足则拒绝新增占用并明确提示；始终保护停止、对账、结束和删除所需空间。存储额度不是正常任务总 Token 或总轮次硬截止。
- 个人模型连接及 Skill 原件独立于演练，删除演练不删除个人设置；Key 不复制进对话、协议消息、工具记录或快照。任务快照的引用计量与回收见 [Skill](skills.md)。
- 模型及摘要调用逐次预留 2 MiB，普通读取工具预留 512 KiB，压缩请求及 steer 各预留 64 KiB；提案证据登记沿用最多 64 MiB，批准另走 FILE_BATCH 准入。摘要正文、原响应、usage、引用与行元数据全部计量，不以摘要发布释放原证据额度。既有 256 MiB 收尾保护保留；计量不可用或容量不足时在派发前拒绝。
- 对话展示复用原协议消息，工具/审批通过身份引用原证据；不逐轮复制完整输入历史，不保留全量逐 Token SSE 回放。相同保留内容若物理复用，按各演练的去重引用计入内容及引用元数据；最后引用解除且个人原件不再需要时才回收。Skill 快照的实际接线由 P2-17/18 验收。
- 不重新引入固定全局业务数据预算、磁盘水位或备份建设。

## 实现与验证边界

`read` 单次返回最多 200 行 / 64 KiB，超出请求范围正常分页并提示下一 `start_line`；`grep` 默认附带两行上下文，支持前缀、匹配数限额及受限正则子集，拒绝可能产生无界回溯的构造。截断明确标记。批次按顺序执行。

每个 MAIN/CHILD 任务独立持久保存 `planning_revision`。`edit/write/run_tests/bash` 省略 `expected_revision` 时使用服务器规划基线，显式传入则必须一致；外部保存或恢复推进版本返回结构化冲突，不偷换到最新版本。成功读文件后的下一次模型准备刷新基线，本任务确认的写入/命令同步推进基线。`ToolOutcome` 显式区分等待与完成，`outcome_code` 独立记录 OK、INVALID_ARGUMENTS、CONFLICT、DENIED、APPROVAL_REJECTED 或 LEGACY_UNCLASSIFIED，不用执行完成伪装业务成功。

`run_tests(target, expected_revision?)` 接受当前阶段已发布的受控目标（基础或挑战）；可选修订只能是十进制字符串，参数最多 4 KiB，拒绝未知/重复字段、类型强转、尾随 JSON 和任意命令。测试准入、所属父工具绑定及 `WAITING_TEST` 同事务落盘；等待释放 worker，后续工具必须等待终态且 quiescent 的结果。共享原测试准入、稳定副本、执行槽位与容量，不另建队列；忙仅返回 `TEST_SLOT_BUSY`。同一父任务、已生效用户目标、修订和目标的确定结果显式标记 `reused`，不再执行。

工具回执保留原测试身份、修订、终态和证据引用，仅投影最多 16 KiB/64 段日志尾部；`logTruncated`/`omittedLogBytes` 与底座 `logsIncomplete`/`droppedBytes` 分开表达。完整证据取回后在事务外解码、投影、编码，提交时复核原测试版本。父工具结果提交前通过领域保留贡献接口保护原记录，之后恢复普通测试保留窗口。父任务停止/到期/授权失效只登记其绑定子测试的取消，确认执行收敛后才结束父任务；原测试协调器恢复只查询原 ID，不重放 Start。

压缩确定性验证覆盖窗口/来源分页、派发与发布栅栏、有限修复、旧授权、取消、容量、保留删除及模型切换后的原生配对。真实 DeepSeek 非思考已验证一次摘要后继续读取工具并答复；历史与文件读取使用夹具，不作为真实 Go 或浏览器端到端证据。多协议及思考字段的分层证据已由 P2-19/20 收口，支持范围见矩阵，不以该单项或受控 SDK 测试替代真实供应商验证。

## 证据与实现门槛

三轮一次性 PoC 提供以下证据：

1. AI Services 与自管 Loop 都能实现进程内审批、拒绝、版本冲突与重复批准保护。
2. agentic 配置应用存储后，可在工作流审批点跨 JVM 恢复。
3. 应用自管和 agentic 包裹应用执行器，都能恢复固定工具批次，保留已完成读取结果及工具调用 ID，并在处理剩余工具后向假模型回填配对结果。

第三轮中 agentic 仍依赖应用维护工具批次、消息和游标；没有验证 AI Services 自动循环的透明跨进程恢复。以上均不证明生产环境 exactly-once、性能优势或更低开发成本。

一次性原型已从当前树移除，源码和实验记录可用 `git show c185c65:backend/prototypes/agent-loop-poc/README.md`（及同目录 RECOVERY/BATCH-RECOVERY）追溯。日常开发只需理解 [ADR 0001](../adr/0001-copilot-application-owned-loop.md) 的取舍，不必重跑旧实验。

正式实现的动态多轮、审批/停止/steer、压缩、恢复、执行联动及保留删除已有第二阶段证据；后续变更只对受影响边界补验证，不将 PoC 当时未覆盖的项目反复列为当前待办。真实供应商兼容声明以模型矩阵为准。
