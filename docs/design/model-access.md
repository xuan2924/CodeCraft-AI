# 模型连接、上下文用量与计费

状态：产品边界已确认；SDK 协议覆盖、供应商能力及计费配置仍需真实验证。协议支持是首期目标，不是现有能力声明。

## 连接与凭证

- 提供 DeepSeek、GLM、Kimi、OpenAI 预设；支持用户自定义 Base URL、API Key、模型 ID。
- 显式选择 OpenAI Chat Completions、OpenAI Responses 或 Anthropic Messages 协议，不静默试探切换协议。供应商与协议不是一对一关系。
- 用户连接供 Copilot 及摘要使用；平台连接供面试官、评测官使用，配置权和费用归属见 [架构](architecture.md#配置权隐私与费用)。
- Java 调用供应商。凭证加密存储，解密密钥由部署环境安全注入；不回显完整 Key，不进入日志、模型上下文或 Go 沙箱。个人模型连接独立于演练保留，删除演练不删除该连接；Key 不复制进对话、协议消息、工具结果或 Skill 快照。
- 用户在个人中心保存多个个人模型连接，例如 Kimi、DeepSeek、OpenAI 各自的地址、协议和 Key；演练中的 Copilot 提供模型选择入口，从个人配置中显式选择、切换使用的模型，不要求通过覆写同一连接来换供应商。
- 个人配置管理与演练中的模型选择是不同操作。Key 可直接保存替换，不以真实检查成功为前提；不由此推导个人设置一经编辑就自动改变当前演练配置，编辑在用连接后需显式应用更新版本，见 ADR 0008。
- 已发出的请求保持原配置，显式切换只作用于后续请求，不自动重发失败请求，不重置代码、对话、审批或倒计时。新配置不可用时明确报错，不自动恢复旧 Key 或切回其他连接；手动编辑/测试及结束演练不受阻。切换在当前请求及其工具批次收敛后、下一次模型请求时生效，历史兼容路径仍须核实。
- 平台模型/规则按演练固定；允许更换失效凭证，但不因此改变规则或模型版本，见 [Skill 配置](skills.md)。

### 多连接管理与演练内模型切换（P2-03 已澄清）

用户澄清需求为“个人中心配置多个 Key/模型，演练中的 Coding Agent 支持从中切换模型”。此前将方案 B 解读为“修改个人配置，当前演练自动跟随”有偏差，该解读撤回，以本节为准；见 [ADR 0005](../adr/0005-live-model-connection-updates.md)。

- **一条连接可配置多个模型，已确认。** 连接保存一份 Base URL、协议和 Key；其下添加多个模型 ID，各模型分别配置上下文窗口及适用的思考模式等参数。多个模型共用连接凭证，不要求重复填写 Key；不同地址、协议或 Key 使用不同连接。
- 演练选择的是具体的“连接 + 模型配置”，而非只选供应商或 Key。同连接内换模型、跨连接换模型都通过演练选择器完成，不覆写原配置；同名模型通过所属连接区分。
- 每次模型/摘要请求使用一份完整配置，不混用不同连接的地址、协议或 Key。切换生效点见下文；请求与切换的持久化排序由 P2-02 实现验证；当前所选配置被实际编辑后，按 ADR 0008 在批次收敛后暂停并提示显式使用更新版本，不静默恢复为整场固定模型或个人设置自动联动。
- 每次调用记录实际使用的非秘密配置身份；历史请求、usage 和费用不随当前模型选择或个人配置修改重标。历史不持久保留旧 Key，在途请求为完成当前调用所需的凭证不构成历史备份。
- 保存成功不等于检查通过。地址、协议、模型、思考模式或 Key 改变后，不继承旧版本检查结果；迟到的旧检查不能覆盖新版本状态。开始计时前仍检查所选配置，两项均有效才准入。
- **演练中切换模型不额外发起连接测试，也不要求已有有效检查结果，已确认。** 用户从已保存配置中选择后，后续正常业务请求直接使用所选模型；调用失败明确报错，由用户修正或切换，不自动回退或重发。仍校验归属、配置格式及支持能力，不能把免测试等同于绕过权限或承诺协议兼容。用户主动触发的检查继续受原限额约束。
- 跨模型/协议切换涉及工具调用 ID、推理字段、窗口及压缩上下文兼容，由 P2-01/02/04 核实；不能静默丢弃必需字段或重执行已完成工具。不兼容配置域在完整批次边界转为带来源的只读文本历史，显式提示，原始协议/证据保留；不伪造签名或重做工具，见 ADR 0008。
- 删除连接/模型的行为已确认，见下文；删除不是停止 Copilot 或结束演练。编辑正在使用的连接/模型不自动改变演练选择；当前批次收敛后暂停新的模型/摘要请求，待用户显式选择更新版本，演练结束后可编辑/删除个人配置，历史记录不保留旧 Key。

### 模型切换生效时机（P2-02/03 已确认）

- 用户可在运行中选择新模型；不取消或改写已发出的请求。当前模型请求及其工具批次处理完、调用与结果配对完整后，下一次模型请求使用所选模型，不要求等整个 Copilot 任务结束。
- 模型切换本身不使待审批提案失效、不自动批准或拒绝，也不跳过后续工具；用户仍按原审批规则处理。停止、steer、基线变化、结束/到期等既有控制规则不受影响，不能因等待切换而继续执行已被禁止的工具。
- 等待期间显示“将在下次请求使用”，区分当前请求使用的模型与用户所选模型。若当前任务自然结束，切换不额外触发模型请求、不自动另起任务；保留模型选择供后续请求使用。
- 本次确认产品生效边界，不代替 P2-01 的协议兼容证据及 P2-02 的切换、派发、审批、停止和恢复排序验证。

### 删除个人连接或模型（P2-03 已确认）

- 允许删除个人连接或其下的模型配置。删除未选中的项不影响当前演练；删除单个模型不删除共用连接或其他模型，删除连接则其下模型不再可选。历史记录保留实际请求的非秘密配置身份，不随个人配置删除而清空。
- 删除当前所选项时，不取消已发出的模型请求；当前请求及其工具批次按原规则收敛，之后不再使用已删除配置发起新的模型/摘要请求，暂停模型调用并提示重新选择。不能继续靠缓存凭证派发，也不自动替选其他模型。
- 删除本身不使待审批提案失效，不自动停止当前工具或所属测试；停止、steer、基线变化和到期等原规则仍可使批次提前收敛。不能为等批次完成而绕过既有授权或截止时间。
- 不因此结束演练，手动编辑、测试及倒计时继续。界面说明“所选配置已删除，请重新选择”，不将暂停模型调用显示为任务已停止或演练已结束。选择新模型仍遵循显式切换规则，不自动重发已失败或中断的收费请求。
- 删除与派发、待切换选择、恢复的持久化排序，以及不保留历史 Key 的回收实现仍须验证；业务删除受理不能被迟到配置写入复活。

## 第二阶段交付与验证边界

- [第二阶段规格](../../.scratch/copilot-loop/spec.md)已确认以真实 DeepSeek 非思考模式打通首条读取—审批修改—测试—回复链路，再验收思考模式；两种模式都属于本阶段交付，不以非思考通过代替思考兼容性。
- 三种协议、四家预设和自定义连接是本阶段结束目标；按官方核验及真实验证声明支持矩阵，不承诺每个供应商支持全部协议。协议、流式工具参数、推理字段、消息回填和 usage 必须结合正式 SDK 核实，发现缺口先请求确认，不静默降级。
- 真实模型验收显式触发并提示费用，自动回归使用可控替身；替身成功不能声明供应商兼容。首条联调可显式读取环境变量中的 DeepSeek Key，但不能将测试配置变成产品的隐式凭证回退，不能展示或提交秘密。
- 阶段性入口仍需真实完成模型检查，不冒充完整面试；面试官、评测及平台 Agent 配置留到第三阶段。

## 实现组织

- 模型客户端由统一入口按已授权的连接配置解析，业务模块不自行创建供应商客户端；缺失配置明确失败，不静默回退到其他模型或平台凭证。
- 结构化输出的解析、校验与有限重试集中封装；重试服从 [Copilot Loop](copilot-loop.md#工具与失败处理) 的预算及恢复语义，业务代码不复制重试循环，也不叠加 SDK 隐式重试。
- Prompt 模板在实现时集中到 `resources/prompts/`，按业务归属组织，动态输入显式传入；模板引擎及文件格式结合 SDK 核实后确认，不预建空目录或将示例类名视为现有接口。
- 供应商适配属于共享技术实现，业务编排留在所属模块；仅提取实际复用的能力，不为示例中的 Registry、Invoker 或异步模板预建通用框架。

## 自定义地址安全

用户在 P2-03 明确选择 **仅校验 HTTPS（方案 A）**，替代此前“仅公网 HTTPS”的设计：校验 Base URL 为合法 HTTPS URL，不做内网 IP、DNS 解析结果或实际连接目标检查，不建设 DNS 重绑定防护。HTTPS 内网地址和解析到内网的域名不因目标属于内网而被拒绝；不新增 HTTP 本地例外，不关闭正常 TLS 证书校验。

按用户填写的 Base URL 及所选协议发送请求；不自动修正地址、探测或切换服务。地址、Key 或兼容性错误明确返回，由用户修改配置。HTTPS 不构成内网隔离，仍存在服务器被引导访问内部 HTTP 服务的 SSRF 风险；本次有意缩减防护范围，不宣称已消除此风险。取舍见 [ADR 0004](../adr/0004-model-url-https-only.md)。

P2-03 根据已授权技术决策明确不自动跟随任何重定向：配置 JDK Redirect.NEVER，3xx 明确失败，由用户修正地址，不向下一目标转发凭证。合法 HTTPS URI 还需有效 host，拒绝 userinfo/fragment；不借此新增 IP/DNS 目标限制。界面提示：自定义地址运营方会接收凭证和请求内容；“模型名与官方相同”不证明实际模型或价格相同。

## 凭证与修订实施契约

- 使用 JDK AES-256-GCM，随机 96-bit nonce、128-bit tag，AAD 绑定格式/用户/连接/密钥 ID；密钥环与当前 ID 由部署环境安全注入，不存明文或旧 Key 历史。携密对象不打印值，响应只展示已配置状态，错误/日志不输出 SDK 原始异常、响应正文或请求头。
- 新旧部署密钥可短期并存，受信维护入口分批重新加密，完成后移除旧密钥；不开放管理员读取用户凭证的入口。缺失配置/解密失败明确不可用，不回退环境中的联调 Key。
- 实际调用参数或 Key 编辑使检查失效；展示名称变化不使检查失效。演练不自动跟随编辑，原请求/批次收敛后提示显式使用更新版本；不混用新 Key 与旧地址/协议。重要取舍见 [ADR 0008](../adr/0008-model-revisions-and-history-boundaries.md)。
- 配置与检查采用版本及用户事务锁排序；网络调用不占数据库事务，迟到结果不能认证新配置或复活已删除配置。列表分页有界，不擅加未确认的个人连接数量上限。

## 配置测试

执行前提示少量真实请求可能收费；测试记录与演练用量分开。

1. **基础连接**：验证指定地址、鉴权和模型的一次基本请求；区分网络、鉴权、模型不存在等错误，不一律报 Key 无效。
2. **工具调用闭环**：发送无副作用测试工具定义，校验调用名称、ID、参数，执行测试工具并回填结果，再检查模型能使用回执继续响应。不能只检查 HTTP 200 或一个 `tool_calls` 字段。

两项分别展示并独立记录结果。通过只证明该配置完成过基本闭环，不证明流式参数、多工具、推理消息或所有 Agent 行为兼容。演练开始计时前须准备好工作区/执行环境，且两项检查均通过。

### 检查复用与准备失败（P2-03 已确认）

- 同一配置的成功检查自各自完成起 **30 分钟内可复用**；开始计时时复核两项结果均有效，避免设置页刚检查成功又重复收费。检查结果按“连接版本 + 具体模型配置”区分，同 Key 下模型 A 通过不代表模型 B 通过。连接地址、协议或 Key 改变，使该连接下模型的旧检查失效；单个模型 ID 或思考模式改变，仅使对应模型的旧检查失效，不沿用旧版本的成功结果。
- 检查失败不自动反复调用。用户可显式重试或放弃准备；放弃按既有准备取消/清理协议释放活动演练名额，未知在途结果仍须对账，不因释放名额丢弃恢复记录。
- 已开始的演练不因检查记录过期而暂停，不定时发送收费探测请求；实际请求失败按任务错误与恢复契约处理。
- Key 保存即替换，不以检查成功为前提；这一后续确认覆盖原“候选 Key 检查通过才切换、失败保留旧配置”的规则。检查结果只属于被检查的配置版本，失败不回滚已保存的新 Key，也不恢复旧版本的成功状态。

### 检查费用与频率限制（P2-03 已确认）

以下为可配置初值，仅约束连接检查，不作为正常 Copilot 任务的总请求数或总时长限制：

- 一组完整检查最多 **3 次模型请求**：基础检查 1 次、工具闭环 2 次。仍有效的成功结果可复用时减少实际请求，不为凑齐次数重复检查。
- **不自动重试**。模型未调用测试工具、参数不合法或回填后未完成闭环，明确记录检查失败，不追加请求直到成功；SDK 隐式重试也不得突破本规则，其关闭能力由 P2-01 核实。
- 每次模型请求最长 **120 秒**，包括流式响应；达到上限停止本次检查并尝试取消请求，不以取消成功推断供应商未计费。取消及超时能力仍须结合 SDK 验证。
- 每用户同时最多 **1 组**检查，**5 分钟内最多启动 3 组**，失败也计数。基础检查、工具检查、演练准备和用户显式触发的 Key 检查均使用统一的用户级准入，不能通过不同连接或入口绕过。数据库并发与重启一致性随实现验证。
- 调用前提示可能收费。非思考基础检查上限 128 Token、工具两次各 256；思考检查每次最多 2048。解码内容每组至多 64 KiB，传输每次至多 8 MiB；达到上限仍未完成就失败，不追加请求。请求次数与超时不等于固定金额上限，缺失 usage 不按零费用处理。

## 上下文占用与缓存

- 界面展示最近一次请求的输入上下文用量 / 上下文窗口；供应商返回可用用量后才更新，不展示调用前估算为实测值。
- 输入包含系统指令、工具定义、对话和工具结果；不同供应商统计口径需适配。缓存命中输入仍占窗口，不把累计 Token 当当前上下文。
- 未返回可用数据时显示未知。已验证模型窗口从配置读取；未知模型由用户填写并标记来源，提示填大可能请求超限。
- 压缩后尚无新返回时显示“已压缩，等待下次请求更新占用”，不把旧值当压缩后数值。
- 自动压缩内部可估算输入并预留输出空间；具体压缩行为见 [Copilot Loop](copilot-loop.md#上下文压缩)。
- 为复用缓存尽量保持系统规则、工具和固定题目内容的稳定顺序，变化内容按需追加。缓存优化服从正确性，不能以缓存命中为由保留大量无关信息。
- 缓存能力与收费由供应商决定，不承诺统一命中率，也不追求“写入越多越好”。

## 用量与费用

- 使用供应商实际返回的普通输入、缓存相关输入/写入及输出等字段；区分已包含在总输入中的子项，不能重复计费。
- 按供应商、模型、价格生效时间、时区及适用条件匹配官方价格配置。分时计费仅在官方规则确实适用时启用，不把历史价格或用户举例写成当前事实。
- 用户侧累计 Copilot 和摘要用量/估算费用；平台面试官与评测费用独立记录，不计入用户费用。连接测试单列。
- 自定义地址无法确定实际模型和价格时，不估算费用；可展示供应商返回的 Token 数。不能仅凭声明模型名套用官方单价。
- 失败请求可能已计费而未返回 usage，标明统计可能不完整，不按零费用处理。金额是估算，实际扣费以供应商账单为准。

## 待决与实现验证

- 核实 LangChain4j 对三种协议的版本支持、流式工具参数、推理字段、消息回填和 usage 暴露；不足时提出适配方案，不自行宣称 API 已存在或变更选型。
- 四家供应商和自定义兼容服务的能力矩阵、模型目录、窗口、定价源更新/审计方式，以及基础测试通过后的能力失败提示。
