# 演练审批设计

状态：本文行为已确认；存储、状态枚举与并发实现仍待验证。审批是授权策略，不改变文件、命令、网络或资源权限。

## 模式与提案

- 演练支持 `auto` 与 `ask for approve`，未指定时默认后者。模式仅由用户选择，变化保留审计记录。
- 读取、搜索和受控测试无需逐次审批，但仍受权限和资源限制。
- AI 修改登记为带工作区基线的提案；`auto` 校验通过后应用，审批模式接受后才应用。两者均保留 Diff、结果与审计。
- 一个多文件提案整批接受或拒绝，不提供逐行/逐文件部分批准。原子性及版本见 [工作区与执行](workspace-execution.md)。
- 每次批准检查身份、演练归属、页面操作权、提案状态和基线，防止重复应用；页面操作权见 [接口与事件](api-events.md)。

## 模式切换

以服务端登记提案为生效分界：提案按登记时模式处理；模型已开始生成但尚未登记的提案，使用登记时最新模式。

已登记的待审批提案不会因切到 `auto` 自动获批。切换和登记必须有确定顺序；前端收到切换成功后才展示生效状态。

## 操作语义

| 操作 | 含义 |
|---|---|
| 停止任务 | 停止 Copilot 后续执行，保留已生效结果 |
| 拒绝修改 | 当前提案不应用，回填拒绝结果；Copilot 可以继续调整 |
| 撤销修改 | 恢复已应用代码；首期不提供此能力 |

拒绝可附理由，不使整轮任务自动失败；模型不能原样反复提交被拒方案。停止显示“正在停止”，待执行结果收敛后显示“已停止”与已应用修改，不将未知写入伪报为未应用。Loop 与 steer 见 [Copilot Loop](copilot-loop.md)。

## 失效与竞争

- 基线不匹配即使提案失效，不自动合并；重新读取、生成新提案，旧批准不授权新内容。
- 不设独立审批倒计时。工作区变化、所属任务停止、steer 使旧计划失效、演练结束或清理会终止旧审批的可处理性。
- 批准、停止、steer 及到期收尾按服务端确定顺序处理：停止/失效先生效则禁止写入；修改先应用成功则保留，不自动回滚。
- 已在执行的写入须对账后给出终态，不能仅凭按钮点击时间认定结果。
- 待审批任务可在重启后恢复，处理前重新校验权限、基线与状态，不自动批准。

## 验收要求

覆盖默认模式、登记与切换竞争、旧提案保留、拒绝后继续、重复批准、越权、版本变化、多文件失败、停止/steer/到期与批准竞争及重启恢复。使用可控模型替身，验证无额外写入、无静默覆盖、旧授权不迁移到新提案。
