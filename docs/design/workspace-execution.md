# 工作区、Patch 与沙箱执行

状态：存储、版本、一次性测试和部署边界已确认；任务 04 已选定不可变版本目录与原子提交记录方案，并完成 Linux 受控夹具的进程崩溃验证。正式服务、跨语言授权协调、断电恢复及配额尚未验证。

## 工作区与文件权限

- Go 在持久化磁盘目录保存每场演练的真实工程文件。目录不依赖测试容器生命周期；Go 若容器化，必须挂载持久化目录/卷。磁盘持久化不是备份。
- 用户及 Copilot 文件工具仅能操作当前演练中题目允许的路径。题目声明可编辑区域及 `pom.xml` 是否可改；任何配置修改都不授权联网下载依赖。
- 权威验收测试及受控执行配置放在可编辑工作区之外；测试公开不等于可修改。题目发布见 [面试与评测](interview-evaluation.md)。
- 题目包及工作区全面禁止符号链接（包括内部链接和 Windows junction）、硬链接及特殊文件；校验规范化路径、逐级真实路径和演练归属，禁止穿越、越界、跨演练访问，不能只做字符串前缀检查。政策已确认；任务 04 已验证 Linux 描述符相对遍历拒绝链接及目录交换样本，正式服务路径集成、Windows junction 与部署宿主验证仍待完成。
- 支持文本文件创建、修改、删除；重命名作为新增与删除的原子批次处理。首期无任意文件上传。
- Skill 由独立受控配置入口管理，不因此扩大文件工具权限，见 [Skill 配置](skills.md)。

## 工作区版本与写入

整个工作区使用一个修订版本，不按 AI 调用次数计数。

- 成功改变正式文件内容或结构时递增；用户保存和 AI 应用均计入。一批多文件原子写入只递增一次。
- 本地输入/草稿备份、相同内容保存、读取、测试、审批拒绝、模式切换或失败写入不递增；测试产物不回写正式代码。
- 用户保存与 Patch 应用均检查基线。任何文件变化都使旧基线过期，即使文件不同也不自动合并。
- 多文件提案整批应用或不应用；不能部分成功。冲突使旧提案失效，重新生成不继承旧批准，见 [审批](approval.md)。
- 版本与写入回执必须可恢复；不得使用进程内计数冒充持久化版本。采用下述不可变文件树与原子提交记录，版本和回执由 Go 一同持久化；Java 查询对账。
- 本地草稿与冲突展示见 [Web IDE](web-ide.md)；单页面操作权见 [接口与事件](api-events.md)。

## 文件一致性与恢复契约（任务 04）

用户已确认采用“不可变版本目录 + 原子发布提交记录”，以独立 Go 探针验证，不提前建立正式服务或页面租约。证据与未验证项见 [任务 04 验证记录](../validation/workspace-consistency-04.md)；探针不是有效规格的替代品。

### 所有权与公开边界

Go 是正式文件、当前修订、冻结状态和写入回执的持久化所有者；Java 是身份、演练、授权及业务操作记录的所有者。Java 的版本字段只是已确认观察值，不自行递增，也不让 Go 访问业务数据库。修订、请求 ID、回执均绑定不可复用的工作区实例；不能删除后复用实例标识并重置版本接受旧请求。

| 操作 | 契约 |
|---|---|
| 读版本/文件 | 返回同一已提交修订的内容、修订号及冻结状态，不直接暴露正在准备的目录；历史基线内容的保留/查询由证据保留策略另行落实 |
| 整批变更 | 接受工作区实例、请求 ID、基线、变更集合和任务 05 提供的可信授权协调信息；先核对已提交回执，再检查冻结、授权及整个工作区基线；路径/文本检查全部通过才能发布 |
| 结果查询 | 按工作区实例和请求 ID 返回已提交回执；没有回执表示查询线性化时没有已提交结果，不表示旧 RPC 永远不会提交；损坏/不可访问必须报不可确认，不能冒充未找到 |
| 稳定副本 | 输入预期当前修订；不匹配拒绝。复制与写入/冻结共用工作区协调区，返回独立副本及确定修订；复制成功后原工作区可继续保存，测试不能写回源目录 |
| 冻结 | 与写入串行化，等待已进入提交协调区的操作收敛，持久化只读状态及最终修订/回执；本身不推进内容修订。新请求拒绝，历史成功请求仅返回原回执，不重新执行 |

上述是语义边界，不是已生成的 RPC 定义。具体消息、状态码、持久化 gateEpoch 与超时语义见 [任务 05 协议](task-event-recovery.md)。

请求指纹绑定操作种类、基线、完整变更内容；键在同一工作区所有变更种类间唯一。同键同载荷返回原回执，即使当前版本已推进；同键不同载荷拒绝。回执至少包含请求标识、结果修订、是否改变内容、冻结结果；正式协议需明确业务操作关联。无变化保存也要持久化回执，重放不能重新解释成新保存。失败校验不发布提交；查询无回执不是可重放许可证。所有回执访问仍须 Java 校验当前身份与归属，不能为幂等绕过授权。

### 存储与唯一提交点

首个实现采用保守全量复制，不在已发布树上原地更新，不用硬链接共享可变文件。所有读写经 Go 管理的私有根目录；测试容器只得到独立执行副本。正式实现必须限制文件数、字节数、历史与回执容量；探针的小夹具不构成容量方案。

```text
取得工作区串行协调权
  → 读取最新已发布记录（修订、冻结、累计回执）
  → 去重与基线/权限/路径检查
  → 在同一文件系统 stage 目录准备完整新树
  → 刷新文件、树目录、manifest（修订 + 回执 + 冻结状态）及 stage 目录
  → 原子重命名 stage 为下一个 commit 目录   ← 唯一可见提交点
  → 刷新工作区父目录
  → 返回成功
```

探针以单调提交序号命名 `commit-*`，读取最大序号，无单独的 HEAD 指针。提交序号是存储细节，不是工作区内容修订；无变化保存及冻结产生提交记录但不增加修订。一批多文件只推进一次修订。根目录中的 `stage-*` 永不作为正式版本读取，崩溃遗留目录只能在确认没有活跃操作后清扫。已发布目录损坏必须失败关闭并告警，不能自动退回旧版本伪装成功。

Go 通过每工作区操作串行化协调读、写、复制、冻结；探针使用本地 `flock`，每次调用独立描述符，进程终止由内核释放。锁等待与发布前响应 Context 取消；系统调用本身不保证立即中断，发布后的取消不回滚。此锁不是分布式租约，不支持多宿主共享存储或 NFS。

### 崩溃及 Java–Go 对账

| 观察到的故障 | Go 的恢复/查询 | Java 的处理 |
|---|---|---|
| 准备多文件中途失败或发布前进程终止 | 旧树、旧修订仍正式可见；stage 被忽略；没有成功回执 | 明确提交前拒绝可记录失败；传输不确定则先查询 |
| 原子发布后进程终止、响应丢失 | 文件、修订、回执来自同一个发布目录；可查询原结果 | 按原请求 ID 对账，更新自身业务记录，不换键补写 |
| Java 在收到 Go 成功后、更新数据库前终止 | Go 回执保留 | Java 恢复未决操作，查询并收敛业务状态 |
| 查询无回执 | 只证明此时未提交；旧请求可能还在网络或队列中 | 保持未决，先通过任务 05 的协调协议排空/隔离旧调用；不能自动重发或宣布最终失败 |
| 发布后目录刷新错误、查询损坏/不可用 | 结果未知；不得假定已回滚 | 停留在待核对/人工处置状态，不盲重放 |

Java 在派发前应持久化操作 ID、工作区实例、载荷指纹/可恢复请求及未决状态；具体表结构由正式实现决定。查询必须到同一工作区权威存储，不读可能滞后的副本。未决写入影响接管、结束、删除时，须先完成排序和对账。回执不能在未决操作仍可能到达时删除；保留期限、墓碑和垃圾回收尚待设计，不能默认永远保留或静默过期。

已验证的是本机 Linux 容器文件系统上的进程终止，不是断电、磁盘损坏、NFS 或所有部署文件系统的持久性证明。不宣称 exactly-once：能保证的范围是受控单机协调与回执保留期间，同键已提交请求不会再产生文件效果。

### 交给任务 05 的操作权协调要求

操作权是页面对演练执行写操作的资格，不是登录身份。Java 负责判断；Go 的文件提交必须处于同一个可排序的授权有效区间内，不能仅依赖 RPC 发出前的一次检查。

- 若旧页面写入先完成提交，接管后生效，保留这次写入结果。
- 若接管先完成，旧操作不能再提交；接管响应成功必须意味着这一保证已生效。
- 超时未知不能视为写入已经终止；Java 不能仅释放本地锁后宣布接管成功，让迟到的 Go 写入绕过失效检查。
- 任务 05 已选择 [持久化 CloseGate/OpenGate 协议](task-event-recovery.md#页面操作权与可恢复栅栏)：Java 先落盘转换意图，Go 与原子发布共用协调区持久化新代次，核对后才激活新控制权。正式服务尚未接入；任务 04 探针的文件锁本身不解决跨服务授权问题。
- 到期/主动结束先关闭新写入准入，再收敛在途写入，最后冻结最终修订。冻结不自动保存浏览器草稿、不代表停止测试；停止与最终验收属于生命周期协议。

## 测试生命周期

```text
选定服务端工作区版本
→ 在一致性保护下复制稳定测试副本
→ 挂载到本次专用受限容器
→ 执行平台允许的目标
→ 保存结果与限额内日志
→ 销毁容器、临时副本和构建产物
```

- 首期不复用容器，不在编辑/等待审批时维持测试容器。每场演练同时最多一个测试任务，重复启动不隐式排队。
- 复制必须与保存/Patch 协调，不能混合两个版本；复制后的测试允许原工作区继续编辑保存。
- 测试结果始终归属于启动版本。旧版本通过不能解锁当前版本挑战入口。
- 命令和参数由服务端受控模板生成，不接受模型/浏览器的任意命令字符串，不提供任意 shell 工具。
- 使用固定版本题目镜像预装离线依赖；缺失依赖报环境错误，不临时开放网络。首个题目包、受控目标和维护者发布验证见 [题目包契约](problem-package.md)；正式发布记录与部署宿主复验仍待实现。
- 结果区分通过、测试失败（如编译或断言失败）、执行超时、已停止、环境错误。日志保留受限但最终状态可查询。
- 只有题目明确的资源与性能条件才能作为性能验收依据；平台保护性超时不直接等同于算法性能不合格。
- 停止/超时必须终止相关执行并清理，RPC 取消不等于进程退出。正常结束、异常和服务重启均有资源回收路径；清理失败可观测并可重试。
- 浏览器断线不触发任务停止或删除工作区，恢复行为见接口设计。

## 部署与隔离

本阶段允许 Java、数据库与 Go/Docker 同机，仅限可信受邀用户；不向匿名或不可信用户开放。不以独立机器/VM 为首期前提，扩大范围前重新评审隔离与滥用防护。

Docker 共享宿主内核，接受同机资源耗尽和逃逸可能影响平台/数据的剩余风险，不宣称完整恶意代码隔离。

- 容器非 root、禁网、drop capabilities、no-new-privileges、seccomp；禁止 privileged、Docker socket、宿主敏感目录和凭证挂载。
- 根文件系统只读，必要执行副本及临时目录独立可写且限额。候选人代码不在 Java/Go 服务宿主进程中执行。
- CPU、内存、PID、磁盘、日志、单任务超时与全局并发设可配置上限。按题目实测，不采用草案统一的 512MB/30 秒硬编码值。首题实测与建议值见 [题目包契约](problem-package.md#首题资源建议与边界)，不推广为其他题目的默认值。

## 保留与删除

- 结束后保留最终代码、报告所需证据、对话、修改/审批记录与限额内日志；清理执行临时资源。
- 历史版本按证据需求保留，不承诺无限完整快照；报告引用的证据不能先被静默删除。
- 用户可主动删除已结束演练：确认后先禁止访问，再后台清理；过程中显示“正在删除”，失败可重试。
- 未结束演练先停止并结束，避免清理与写入竞争。
- 澄清阶段首期不自动闲置过期；保留工作区容量限制与磁盘监控。具体保留期限、配额和备份目标仍待定。
