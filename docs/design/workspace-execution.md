# 工作区、Patch 与沙箱执行

本文定义当前存储、版本、执行和部署边界。第一阶段工作区、跨语言授权、稳定版本测试、日志/停止/恢复、结束冻结与保留删除已交付；第二阶段 AI 数据亦接入同一容量与删除流程。历史验证见 [#10–#12](../validation/workspace-write-browser-10-12.md)、[#13](../validation/stable-test-run-13.md)，最终范围与证据见 [P2-22](../../.scratch/copilot-loop/issues/22-stage-acceptance.md)。

## 工作区与文件权限

- Go 在持久化磁盘目录保存每场演练的真实工程文件。目录不依赖测试容器生命周期；Go 若容器化，必须挂载持久化目录/卷。磁盘持久化不是备份。
- 用户及 Copilot 文件工具仅能操作当前演练中题目允许的路径。题目声明可编辑区域及 `pom.xml` 是否可改；任何配置修改都不授权联网下载依赖。
- 权威验收测试及受控执行配置放在可编辑工作区之外；测试公开不等于可修改。题目发布见 [面试与评测](interview-evaluation.md)。
- 题目包及工作区全面禁止符号链接（包括内部链接和 Windows junction）、硬链接及特殊文件；校验规范化路径、逐级真实路径和演练归属，禁止穿越、越界、跨演练访问，不能只做字符串前缀检查。Linux 描述符相对遍历与正式服务路径集成已有验证；当前 Go 运行于 Linux，Windows junction 和其他部署宿主不在本机阶段验证范围内，不因未验证而放松禁止链接政策。
- 支持文本文件创建、修改、删除；重命名作为新增与删除的原子批次处理。首期无任意文件上传。
- Skill 由独立受控配置入口管理，不因此扩大文件工具权限，见 [Skill 配置](skills.md)。

## 工作区版本与写入

整个工作区使用一个修订版本，不按 AI 调用次数计数。

- 成功改变正式文件内容或结构时递增；用户保存和 AI 应用均计入。一批多文件原子写入只递增一次。
- 本地输入/草稿备份、相同内容保存、读取、测试、审批拒绝、模式切换或失败写入不递增；测试产物不回写正式代码。
- 用户保存与 Patch 应用均检查基线。任何文件变化都使旧基线过期，即使文件不同也不自动合并。
- 多文件提案整批应用或不应用；不能部分成功。冲突使旧提案失效，重新生成不继承旧批准，见 [审批](approval.md)。
- 版本与写入回执必须可恢复；不得使用进程内计数冒充持久化版本。采用下述不可变文件树与原子提交记录，版本和回执由 Go 一同持久化；Java 查询对账。
- 本地草稿与冲突展示见 [Web IDE](web-ide.md)；单页面操作权见 [接口与事件](api-events.md)。

## 文件一致性与恢复契约（任务 04）

采用已确认的“不可变版本目录 + 原子发布提交记录”；任务 04 的独立 Go 探针是早期方案证据，正式 Java/Go 服务已在后续工作区交付中接入。早期记录见 [任务 04](../validation/workspace-consistency-04.md)，正式证据见 [工作区验收](../validation/workspace-write-browser-10-12.md)；不因原型曾未建设服务而重复选型或引入页面租约。

### 所有权与公开边界

Go 是正式文件、当前修订、冻结状态和写入回执的持久化所有者；Java 是身份、演练、授权及业务操作记录的所有者。Java 的版本字段只是已确认观察值，不自行递增，也不让 Go 访问业务数据库。修订、请求 ID、回执均绑定不可复用的工作区实例；不能删除后复用实例标识并重置版本接受旧请求。

| 操作 | 契约 |
|---|---|
| 读版本/文件 | 返回同一已提交修订的内容、修订号及冻结状态，不直接暴露正在准备的目录；历史基线内容的保留/查询由证据保留策略另行落实 |
| 整批变更 | 接受工作区实例、请求 ID、基线、变更集合和任务 05 提供的可信授权协调信息；先核对已提交回执，再检查冻结、授权及整个工作区基线；路径/文本检查全部通过才能发布 |
| 结果查询 | 按工作区实例和请求 ID 返回已提交回执；没有回执表示查询线性化时没有已提交结果，不表示旧 RPC 永远不会提交；损坏/不可访问必须报不可确认，不能冒充未找到 |
| 稳定副本 | 输入预期当前修订；不匹配拒绝。复制与写入/冻结共用工作区协调区，返回独立副本及确定修订；复制成功后原工作区可继续保存，测试不能写回源目录 |
| 冻结 | 与写入串行化，等待已进入提交协调区的操作收敛，持久化只读状态及最终修订/回执；本身不推进内容修订。新请求拒绝，历史成功请求仅返回原回执，不重新执行 |

上述是语义边界，不是已生成的 RPC 定义。具体消息、状态码、持久化 gateEpoch 与超时语义见 [任务 05 协议](task-event-recovery.md)。

请求指纹绑定操作种类、基线、完整变更内容；键在同一工作区所有变更种类间唯一。同键同载荷返回原回执，即使当前版本已推进；同键不同载荷拒绝。回执至少包含请求标识、结果修订、是否改变内容、冻结结果；正式协议需明确业务操作关联。无变化保存也要持久化回执，重放不能重新解释成新保存。失败校验不发布提交；查询无回执不是可重放许可证。所有回执访问仍须 Java 校验当前身份与归属，不能为幂等绕过授权。

### 存储与唯一提交点

首个实现采用保守全量复制，不在已发布树上原地更新，不用硬链接共享可变文件。所有读写经 Go 管理的私有根目录；测试容器只得到独立执行副本。正式实现必须限制文件数、字节数、历史与回执容量；探针的小夹具不构成容量方案。

```text
取得工作区串行协调权
  → 读取最新已发布记录（修订、冻结、累计回执）
  → 去重与基线/权限/路径检查
  → 在同一文件系统 stage 目录准备完整新树
  → 刷新文件、树目录、manifest（修订 + 回执 + 冻结状态）及 stage 目录
  → 原子重命名 stage 为下一个 commit 目录   ← 唯一可见提交点
  → 刷新工作区父目录
  → 返回成功
```

探针以单调提交序号命名 `commit-*`，读取最大序号，无单独的 HEAD 指针。提交序号是存储细节，不是工作区内容修订；无变化保存及冻结产生提交记录但不增加修订。一批多文件只推进一次修订。根目录中的 `stage-*` 永不作为正式版本读取，崩溃遗留目录只能在确认没有活跃操作后清扫。已发布目录损坏必须失败关闭并告警，不能自动退回旧版本伪装成功。

Go 通过每工作区操作串行化协调读、写、复制、冻结；探针使用本地 `flock`，每次调用独立描述符，进程终止由内核释放。锁等待与发布前响应 Context 取消；系统调用本身不保证立即中断，发布后的取消不回滚。此锁不是分布式租约，不支持多宿主共享存储或 NFS。

### 崩溃及 Java–Go 对账

| 观察到的故障 | Go 的恢复/查询 | Java 的处理 |
|---|---|---|
| 准备多文件中途失败或发布前进程终止 | 旧树、旧修订仍正式可见；stage 被忽略；没有成功回执 | 明确提交前拒绝可记录失败；传输不确定则先查询 |
| 原子发布后进程终止、响应丢失 | 文件、修订、回执来自同一个发布目录；可查询原结果 | 按原请求 ID 对账，更新自身业务记录，不换键补写 |
| Java 在收到 Go 成功后、更新数据库前终止 | Go 回执保留 | Java 恢复未决操作，查询并收敛业务状态 |
| 查询无回执 | 只证明此时未提交；旧请求可能还在网络或队列中 | 保持未决，先通过任务 05 的协调协议排空/隔离旧调用；不能自动重发或宣布最终失败 |
| 发布后目录刷新错误、查询损坏/不可用 | 结果未知；不得假定已回滚 | 停留在待核对/人工处置状态，不盲重放 |

Java 在派发前应持久化操作 ID、工作区实例、载荷指纹/可恢复请求及未决状态；具体表结构由正式实现决定。查询必须到同一工作区权威存储，不读可能滞后的副本。未决写入影响接管、结束、删除时，须先完成排序和对账。回执不能在未决操作仍可能到达时删除；保留与墓碑回收遵循下文及 [任务 05 协议](task-event-recovery.md#rest-与幂等边界)，实际引用追踪与垃圾回收已在第一阶段 #16 和第二阶段 #21 验证，不能默认永远保留或静默过期。

已验证的是本机 Linux 容器文件系统上的进程终止，不是断电、磁盘损坏、NFS 或所有部署文件系统的持久性证明。不宣称 exactly-once：能保证的范围是受控单机协调与回执保留期间，同键已提交请求不会再产生文件效果。

### 交给任务 05 的操作权协调要求

操作权是页面对演练执行写操作的资格，不是登录身份。Java 负责判断；Go 的文件提交必须处于同一个可排序的授权有效区间内，不能仅依赖 RPC 发出前的一次检查。

- 若旧页面写入先完成提交，接管后生效，保留这次写入结果。
- 若接管先完成，旧操作不能再提交；接管响应成功必须意味着这一保证已生效。
- 超时未知不能视为写入已经终止；Java 不能仅释放本地锁后宣布接管成功，让迟到的 Go 写入绕过失效检查。
- 任务 05 已选择 [持久化 CloseGate/OpenGate 协议](task-event-recovery.md#页面操作权与可恢复栅栏)：Java 先落盘转换意图，Go 与原子发布共用协调区持久化新代次，核对后才激活新控制权。正式接入证据见 [#10–#12](../validation/workspace-write-browser-10-12.md)；任务 04 探针的文件锁本身不解决跨服务授权问题。
- 到期/主动结束先关闭新写入准入，再收敛在途写入，最后冻结最终修订。冻结不自动保存浏览器草稿、不代表停止测试；停止与最终验收属于生命周期协议。

## 测试生命周期

```text
选定服务端工作区版本
→ 在一致性保护下复制稳定测试副本
→ 挂载到本次专用受限容器
→ 执行平台允许的目标
→ 保存结果与限额内日志
→ 销毁容器、临时副本和构建产物
```

- 首期不复用容器，不在编辑/等待审批时维持测试容器。每场演练同时最多一个测试任务，重复启动不隐式排队。
- 复制必须与保存/Patch 协调，不能混合两个版本；复制后的测试允许原工作区继续编辑保存。
- 测试结果始终归属于启动版本。旧版本通过不能解锁当前版本挑战入口。
- 受控测试的命令和参数由服务端模板生成，不接受模型/浏览器的任意命令字符串；开发 Bash 是下述独立 `COMMAND` 用途，不得替代权威测试。
- 使用固定版本题目镜像预装离线依赖；缺失依赖报环境错误，不临时开放网络。首个题目包、受控目标和维护者发布验证见 [题目包契约](problem-package.md)；本机发布产物与 Java 发布记录已实现；跨宿主部署需另行复验，不把本机回执当跨宿主发布证明。
- 结果区分通过、测试失败（如编译或断言失败）、执行超时、已停止、环境错误。日志保留受限但最终状态可查询。
- 只有题目明确的资源与性能条件才能作为性能验收依据；平台保护性超时不直接等同于算法性能不合格。
- 停止/超时必须终止相关执行并清理，RPC 取消不等于进程退出。正常结束、异常和服务重启均有资源回收路径；清理失败可观测并可重试。
- 浏览器断线不触发任务停止或删除工作区，恢复行为见接口设计。

## 联网开发 Bash（手动 / Copilot）

- Copilot 经命令级 ASK/AUTO 决定后复用相同准入与执行器；决定与父子绑定原子提交，未回填父工具结果的命令受原证据保护。手动入口仍显式执行，不受 AI 审批模式影响。
- 普通命令使用独立 `workspace_command` 业务记录与 `COMMAND` 执行用途，复用执行登记、停止墓碑、资源名额、日志和容量计量。与权威测试共用执行名额，但不产生测试通过/失败证据；`EXITED` 加实际退出码表示普通 Bash 结果，非零不等于平台故障。
- Java 先持久化幂等请求及唯一执行身份，再由后台 worker 派发。已标记派发的请求只查询/恢复观察；登记缺失时先取得精确执行身份的取消墓碑，不重放 Bash。身份撤销、作答结束、原截止时间到期或 gate 换代触发安全停止；未知停止继续保留原身份。
- 用户命令只在题目固定镜像的 Docker 容器内运行：非 root、只读根文件系统、资源限制不变，普通命令使用 bridge 网络。权威测试继续禁网、固定验收内容及正式修订，不复用命令日志判分。
- `/project` 仅挂载该执行的独立可写副本，不暴露已发布不可变树。`/cache` 是有界 tmpfs，Maven/npm/Go 下载缓存使用该目录；`/project/target` 与 `/project/node_modules` 是副本内可删除的临时构建目录，不单独挂载，避免 `mvn clean` 删除挂载点失败。连续安装/构建应在同一 Bash 请求内完成，不承诺跨命令缓存。
- 整个可写副本含构建目录采用 128 MiB / 20,000 目录项的周期巡检限额，超限停止；这是正常使用下的有界资源保护，不是恶意写入的硬磁盘配额。正式源码仍为 200 文件 / 10 MiB，命令最多 4096 UTF-8 字节，工作目录最多 1024 字节且必须是已存在的规范项目相对目录。CPU、内存、进程数、tmpfs 和运行时限沿题目版本资源策略；首题策略为 1 CPU、768 MiB、128 PIDs、30 秒。
- 单次持久化增长预留 192 MiB，包含原始基线、副本、潜在正式修订及日志等。退出/停止/超时后先确认所有进程静默，再比较候选源码并通过原 gate、截止时间与预期修订的原子批次同步。无变化不增修订；较新保存或 Patch 导致 `CONFLICT`，授权终止或无效文件导致 `REJECTED`，未知发布保持 `PENDING`，均不得伪称已同步。
- 命令退出、进程静默、同步结果和清理是独立事实。构建目录在静默并核对同步结果后清理，失败沿执行回执重试；`copyCleanup=SUCCEEDED` 对命令表示副本收尾已完成，不表示候选源码已删除。候选原始/最终内容可读取 Diff；受管理文本规则不允许呈现的输出明确报告不可用。
- 普通淘汰最多保留最近 20 条已完成且 `SYNCED` / `UNCHANGED` 的输出；新增命令被容量明确拒绝时，可先精简本场最多 4 条最旧的安全已完成记录，再重新计量并用原请求键受理一次，不以 20 条作为最低保留承诺。未知执行和 `CONFLICT` / `REJECTED` 候选不普通淘汰。先提交清理意图，再幂等清理 Go 证据；旧请求键收到已精简回执，不能重执行。历史支持分页；用户操作的源码恢复/回滚在增强票 #05 提供。整场删除仍遵循原静默、清理与保留流程。

## 部署与隔离

本阶段允许 Java、数据库与 Go/Docker 同机，仅限可信受邀用户；不向匿名或不可信用户开放。不以独立机器/VM 为首期前提，扩大范围前重新评审隔离与滥用防护。

Docker 共享宿主内核，接受同机资源耗尽和逃逸可能影响平台/数据的剩余风险，不宣称完整恶意代码隔离。

- 容器非 root、禁网、drop capabilities、no-new-privileges、seccomp；禁止 privileged、Docker socket、宿主敏感目录和凭证挂载。
- 根文件系统只读，必要执行副本及临时目录独立可写且限额。候选人代码不在 Java/Go 服务宿主进程中执行。
- CPU、内存、PID、磁盘、日志、单任务超时与全局并发设可配置上限。按题目实测，不采用草案统一的 512MB/30 秒硬编码值。首题实测与建议值见 [题目包契约](problem-package.md#首题资源建议与边界)，不推广为其他题目的默认值。

## 保留与删除

以下政策已由第一阶段 #16 与第二阶段 #21 实现并验收，具体证据见 [保留删除票](../../.scratch/copilot-loop/issues/21-ai-retention.md)。数量、容量与时间参数集中配置；对话、协议消息、工具结果、Diff、审批和任务 Skill 快照随演练保留/删除，纳入同一 512 MiB 预算及调用前预留，见 [Loop](copilot-loop.md#ai-数据保留与容量)。配额不保证宿主剩余磁盘，也不表示已完成任意部署的容量/断电测试；后续报告需要扩展证据引用时须遵循同一保留边界，不能静默先删。

### 保留期限与用户数量

- 已结束演练自结束起默认保留 30 天，界面展示到期日期；允许用户提前删除，到期整场进入同一删除流程。调整配置不得追溯缩短已有保留承诺。
- 仅删除已结束演练；未结束演练须先停止并结束，不因闲置自动过期。澄清阶段不设闲置自动过期的既有边界不变。
- 每用户最多保留 20 场已结束且未删除的演练，另保留最多一场未结束演练的约束。达到历史数量上限后拒绝创建新演练，提示用户先删除旧记录，不自动挑选未到期记录删除。
- 删除受理并撤销访问后释放用户历史数量名额；尚未清理的资源仍按原归属计入实际占用，不能通过删除或新建掩盖残留资源。

### 工作区与单场容量

| 范围 | 可配置初值 | 统计边界 |
|---|---|---|
| 工作区文件数 | 200 个 | 平台管理的工作区文本文件 |
| 单文件 | 1 MiB | 工作区文本文件内容 |
| 工作区总内容 | 10 MiB | 当前工作区文本内容合计，不包含镜像、预装依赖及测试构建产物 |
| 单场实际存储预算 | 512 MiB | 当前与历史代码副本、stage/临时目录、测试副本与证据、日志及归属该演练的持久化记录；不是预分配空间 |

- HTTP 大文件批次使用独立 Jackson 读取约束和 64 MiB 实际流字节边界，覆盖合法文本 JSON 转义开销；一个非阻塞大请求许可限制同步处理峰值，未知长度同样计数。身份等其他 JSON 输入保持 16 KiB/4 KiB 文档/字符串边界；后端持久化工作区日志与大请求不误用身份小 mapper。
- 题目发布检查初始工作区是否符合上述内容限制。新增或修改超限时整批拒绝并说明原因，不截断文件、不部分保存、不损坏原代码。
- 历史副本、测试构建产物和临时资源不计入当前代码内容上限，但其实际占用不能从单场预算中漏算。共享镜像及预装依赖不重复归属到每场演练。
- Java 以持久化事务预留统一准入，Go 返回有序、持久化世代的实际长度快照；数据库统计可归属业务行的长度，包含 TOAST 值，不伪装逐场分摊共享 WAL/索引/文件系统页。工作区和执行归属集合只增不减，迟到子集不能忘记旧资源；计量不可用/身份丢失不按零占用处理，旧快照不能降低已知占用。
- 接近单场上限时先回收无引用数据，再重新计量；仍不足则拒绝新增占用。默认收尾保留 256 MiB，不预写磁盘：普通消费不得使用，最终验收最多三个尝试各预留 56 MiB，仍保留至少 72 MiB 用于计量暂存及有界救援元数据；只有计量前已确认收敛的操作，才由后置快照释放在途预留。实际占用、在途预留和收尾保留分别展示，不能把固定预留冒充实际数据。
- 恢复停止/结束是当前归属用户的显式安全操作，不需要重新取得页面凭证或普通消费额度：每个测试复用唯一取消意图，每场复用唯一收尾意图，不授予写入/新测试权限，不允许取消系统最终验收。恢复结束不发送新的保存，保留本地草稿，服务器先关闭并核对在途写入，再冻结已提交版本。见 [ADR 0007](../adr/0007-owner-recovery-stop-and-end.md)。受信任 `StopSystemTask` 按完整测试身份执行减权限取消，允许工作区仍处于 OPEN，不以关闭整个工作区为前提，也不授予页面操作权；Java 校验归属并禁止用户恢复停止取消最终验收，Copilot 仅能取消持久绑定的普通测试。Go 保留内部鉴权、工作区存在及执行身份匹配校验和取消墓碑，阻止原执行 ID 的迟到 Start。
- 本机第一阶段不新增固定全局业务数据预算或磁盘水位准入策略，不采用本轮讨论过的 20 GiB、5 GiB/10% 阈值。每场限制、已有执行资源约束仍生效；磁盘不足必须明确报错、保护已提交数据，不能伪报保存或清理成功。未确认退出的执行仍占用隔离执行名额，不因本项豁免而放行。

### 历史版本与测试证据

- 不提供浏览或恢复任意历史保存的能力。保留当前代码、结束后的最终代码，以及仍被保留测试结果、在途操作、冲突比较或恢复流程引用的版本；无引用旧版本可后台回收。
- 普通测试保留最近 20 次已完成的完整记录，包括结构化结果、限额日志及对应代码版本。运行中、结果未知或仍被恢复流程引用的记录不参加淘汰。
- 最终验收各次尝试及必要证据独立保留至演练删除，不挤占普通测试的 20 次窗口。最终验收的尝试次数仍受任务 05 的有限预算约束。
- 普通测试旧记录整体淘汰后，对应代码版本仅在没有其他引用时才可回收。界面提示较早记录已清理，不声称展示全部测试历史；保留的结果不能引用已静默删除的必要证据。
- 每次测试日志按题目 `runtime.logBytes` 有界保留；首题为 stdout/stderr 合计 1 MiB，采用尾部保留，持续排空输出并展示截断和丢弃字节数。事件窗口与长期测试记录是不同保留层次。
- 第二阶段演练内 AI 原始记录随演练保留至删除，不因上下文压缩移除；这是原始证据保留，不是完整逐 Token 事件回放。个人模型连接和 Skill 原件独立保留，Key 不复制进演练消息、工具结果或 Skill 快照；删除个人原件不破坏保留中的任务快照。

### 删除、失败与最小记录

- 手动删除须确认；手动及到期删除都先撤销文件、任务、日志访问与事件订阅，再后台清理该演练的代码、测试记录、日志及无须保留的业务载荷。清理失败不恢复访问。
- 清理失败按 1 分钟、5 分钟、30 分钟，之后每小时重试；用户可手动触发，但同一演练不得并行重复清理。持续失败超过 24 小时提示需要人工处理，后台仍可继续重试；展示失败原因和重试状态，不因超过重试时限而伪报完成。
- 未知写入、残留执行、迟到派发先隔离、对账并确认栅栏/取消记录有效，再回收恢复所需证据。失败与等待清理资源继续计入占用；业务结束、执行静默、物理清理完成是不同事实。
- 删除完成后的本人最小进度记录保留 7 天，仅含演练标识、删除时间和状态；之后不再提供进度查询。未完成的删除不因经过 7 天而隐藏。
- 内部防重放记录只保留必要标识、指纹与处理结果，不含代码、日志正文或凭证；只有确认旧请求不可再生效时才可回收，不能按统一 7 天强删。既有完整业务回执至少保留完成后 7 天、未决操作不按时间清除的规则继续生效；回执不等于完整原始请求载荷。
- 浏览器在确认已受理删除且访问已撤销后清除对应草稿与编辑器状态；其他设备下次联网确认删除后处理，自动到期同样适用。不因网络错误、登录过期或单个含义不明的 404 清空草稿，不承诺远程擦除离线设备。页面行为见 [Web IDE](web-ide.md#演练保留与删除)。

### 备份边界

第一阶段不做备份与恢复功能，不提供备份脚本或恢复验收，接受本机数据损坏后可能无法恢复的风险。持久化、正常重启恢复、未知写入对账与防重放仍须实现；它们不是灾难备份，不能以“不做备份”为由省略。

## 待决与实现验证

正式多文件发布、gRPC/Java 对账、授权栅栏、回执/墓碑、复制/冻结及重启清扫已交付，行为遵循 [任务 05 协议](task-event-recovery.md)。第一阶段 #16 和第二阶段 #21 已验证历史引用、跨存储计量、收尾预留、回收、删除重试与磁盘不足失败安全。具体证据区分确定性 L1、真实文件/数据库与按需故障验证，不重新要求整套故障矩阵。Windows junction、断电与其他目标部署容量仍未因此获得保证；扩大平台或部署范围时须另行核验，不能因文档收口放宽安全约束。

## 验收要求

以下列出需覆盖的行为，不是逐票重跑真实故障矩阵的要求。默认使用快速确定性的 L1，时间策略使用可控时钟；额外真实验证按明确安排或具体问题最小执行并复用已有证据，不自动形成 QA 欠账。

覆盖路径/链接越界、跨演练访问、保护文件、命令模板、禁网、资源限制；验证整批写入、无变化保存、并发冲突、崩溃对账、稳定测试副本及旧结果标识；验证停止杀进程、重启清扫、删除与在途写入竞争。任务 16 另须验证 30 天到期与既有承诺、20 场准入、文件/单场容量边界、磁盘不足和收尾预留、20 次普通测试窗口与最终验收引用、删除重试/人工处理提示、最小进度过期及安全墓碑回收。Docker 测试明确环境，未运行不算通过；不要求第一阶段备份恢复验收。
