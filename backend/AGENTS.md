# 后端通用编码规范

## 边界与数据

- 按职责组织模块，保持依赖单向；通过所属模块的公开接口访问其能力，避免循环依赖和跨模块直接修改内部数据。
- 请求/响应类型与持久化 Entity 分离；边界完成输入校验和类型转换，内部 DTO 按实际职责定义，不机械复制相同模型。
- 配置集中加载并校验；有依赖的服务通过构造函数装配，业务代码不散落读取环境变量。
- SQL 参数化，动态列名和排序使用白名单；集合场景批量读取/写入，避免循环查询导致 N+1。
- 数据库结构通过版本化迁移修改；协议源文件是生成代码的唯一来源，不手改生成文件。Protobuf 删除字段后保留编号和名称，避免复用。
- 外部调用透传超时与取消；队列和流使用有界缓冲，定义背压、拒绝或截断策略，不静默丢弃关键结果。
- 重试前明确幂等边界；副作用结果不确定时先核实，不能以重试代替一致性处理。

## Java

- 避免含糊缩写和无语义魔法值。采用 4 空格缩进、显式 import，工程格式化配置建立后由工具检查。
- Spring 组件采用构造器注入；保持业务逻辑与 HTTP、持久化等适配职责分离。
- 对象值比较使用 `equals` 或空值安全比较；重写 `equals` 时同时维护 `hashCode`，作为 Map key 的对象在存储期间保持相等性相关字段稳定。
- 异常保留原因链；在负责处理的边界统一映射错误并记录上下文和堆栈，不逐层重复记录。使用 SLF4J 参数化日志，不向调用方返回内部堆栈。
- 资源使用 try-with-resources 或明确的 finally 清理；finally 不返回结果或掩盖原异常。
- 事务放在 Service 的 public 方法上，通过 Spring 代理调用；注意同类自调用失效。按异常类型明确回滚规则并测试，事务内避免长耗时外部调用。
- 共享可变状态明确同步策略；执行器、任务队列及外部资源并发均有上限，定义拒绝与关闭行为。采用虚拟线程也不省略资源限流。
- 捕获 `InterruptedException` 后向上传递或恢复中断标记并退出当前操作；自行设置的 ThreadLocal 在作用域结束时清理。

## Go

- 使用 gofmt；包名简短且表达职责，导出 API 有用途和契约注释。接口按使用方实际需要定义，避免为每个结构体预建接口。
- 需要超时或取消的调用以 `ctx context.Context` 为首参并沿调用链透传；避免用 `context.Background()` 切断请求取消，也不以 Context 代替业务参数。
- 显式处理 error；需保留原因时用 `fmt.Errorf("...: %w", err)` 包装，边界用 `errors.Is/As` 匹配。普通失败返回 error；recover 只放在明确的故障隔离边界，记录失败并清理。
- Goroutine 有明确所有者、退出和等待路径；发送与接收均考虑取消，channel 由拥有关闭权的一方关闭。
- 资源成功获取后及时安排 defer 清理；循环内的大量资源按单次操作作用域释放。检查影响结果的写入、刷新和关闭错误。
- 共享 map 与其他可变数据使用同步保护；含锁的值使用后不复制。依赖服务通过构造函数装配，普通数据结构可直接初始化。
